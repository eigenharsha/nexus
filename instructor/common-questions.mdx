These recur in every cohort. Have the answer ready before it's asked.

| Week | The stall | What unblocks it |
| --- | --- | --- |
| 1 | "Why are we writing C? I came here for AI." | Show the Week 26 quantization lesson. The float-bits sketch from Week 1 *is* that lesson. Say it in week 1, not week 26. |
| 1 | Segfault with no idea where | Don't explain — run it under ASan in front of them. The tool teaches faster than you can. |
| 2 | Git conflicts cause genuine panic | Draw the DAG. Every time. The panic is from not having a mental picture. |
| 3 | `@classmethod` vs `@staticmethod` never sticks | Only the `from_csv` factory example works. Skip the abstract explanation entirely. |
| 4 | Async is "just faster threads" | Run the CPU-bound benchmark and let async lose. The measurement corrects it, argument doesn't. |
| 8 | Isolation levels feel theoretical | Two terminals on a projector. Watch the anomaly happen. Nothing else lands. |
| 11 | **The maths wall — the biggest drop-off in the course** | Do not let anyone skip. Split the room, slow down, and connect every concept forward to the week it pays off. |
| 13 | "Why implement a hash table when `dict` exists?" | Show the Week 27 HNSW lesson. Same reason. Structures you've built are structures you can reason about. |
| 17 | Wants to jump straight to deep learning | Show them the Grinsztajn 2022 benchmark. XGBoost still wins on tabular data, which is most of their future job. |
| 19 | Believes their 99% accuracy | Plant a leak in their own notebook, live, and let them find it. It only teaches once, and it teaches permanently. |
| 21 | Backprop by hand feels pointless | It's the only reason Week 25 is readable. Say so, then make them do it anyway. |
| 24 | Kubernetes overwhelm | Reduce to three objects: Deployment, Service, Probe. Everything else can wait. |
| 25 | Attention is "too abstract" | Four-word sentence, attention matrix drawn by hand, before any code. Always works. |
| 26 | "Just fine-tune it" for a knowledge problem | The decision table. Fine-tuning teaches behaviour; RAG supplies facts. Repeat weekly until it sticks. |
| 27 | RAG demo works, then fails on real documents | Their parsing is broken, not their embeddings. Ninety percent of the time. Check the parse first. |
| 30 | Wants five agents where one would do | Make them run the head-to-head benchmark. Single agent usually wins, and the data is more persuasive than you are. |
| 31 | "Evals slow us down" | Show a prompt change that silently broke three cases. One demo ends the argument. |
