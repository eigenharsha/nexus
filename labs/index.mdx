Every week has one lab, written as a ticket rather than as homework — *"Payments is seeing
duplicate charges under load. Fix it."* — with three tracks so the same problem serves a
beginner and a senior engineer.

<CardGroup cols={3}>
  <Card title="basic" icon="seedling">
    About 60% written for you. TODOs marked, answers provided. Start here if the topic is new.
  </Card>
  <Card title="standard" icon="hammer">
    A spec and a test suite. You write the implementation. Start here if you ship code for a living.
  </Card>
  <Card title="hard" icon="mountain">
    Adds a performance, scale or robustness constraint that the `standard` solution fails.
  </Card>
</CardGroup>

## Layout

```
labs/p1/week-01/
├── README.md          # the ticket
├── basic/             # scaffolded
├── standard/          # spec + tests
├── hard/              # + the constraint
├── solution/          # reference (also on a hidden page)
├── tests/
└── Makefile           # make verify
```

## The rules

<Steps>
  <Step title="Attempt before you read">Twenty minutes stuck, then the common-mistakes table, then Layer 1 again. Solutions last.</Step>
  <Step title="make verify is the grader">Green on a correct solution, red on the starter. No instructor required.</Step>
  <Step title="Ship it is not optional">Committed, deployed, containerized, or measured. A lab never ends at "it printed the right thing".</Step>
  <Step title="One repo per week, publicly">With a README you would link from a resume. That's the actual output of this course.</Step>
</Steps>
