# Nexus — Reference & Paper Library

**Canonical location:** `site/reference/papers.mdx` — that file is the published library and the
one to edit. This page holds the *rules* for what goes in it.

## What qualifies

| Bucket | Rule |
|---|---|
| **Primary docs** | Official documentation, specs, RFCs, or the library's own source. Version-pinned. |
| **Papers** | The paper the idea actually comes from — not the blog post about the paper. |
| **Go deeper** | Exactly one: the single best book chapter, lecture or long-form post. Never a list of five. |

## The three hard rules

1. **Every entry carries a one-sentence "read this for…".** "Read the attention paper" is useless.
   "Read section 3.2.1 for why the √d_k scaling exists" is a usable instruction.
2. **Nothing is cited that the author has not read.** This is checkable: the reason line will be
   generic if you haven't.
3. **Point at the section or figure.** Most papers have one figure that carries the idea. Name it.
   That figure is usually also the module's diagram.

## Marking

- **★** = worth reading end to end. Keep these rare — roughly one per two weeks.
- Everything else: abstract, the named figure, the named section. That's the assignment.

## Per-module requirement

Every module page's **Sources & further reading** section must have at least one primary doc and,
where the topic has one, the originating paper. A topic with a paper and no citation is a reject
under `PLAN/00-content-spec.md` §5.

## Reading method (taught in Week 11, used from then on)

1. Three passes: abstract + figures + conclusion → method → maths with a pen.
2. Find the one figure. Redraw it by hand. That's the module sketch.
3. Reproduce the smallest claim — one number or one plot.
4. Write the one-sentence takeaway. If you can't, you haven't read it.
