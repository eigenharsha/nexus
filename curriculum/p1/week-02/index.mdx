## Outcome

<Note>By Sunday you live in the terminal: you can answer a question about a 1 GB log in under 30 seconds, you have automated a real recurring chore so it is safe to run 100 times, and you use Git the way a team does — branches, conflicts, bisect, and recovery from your own mistakes.</Note>

Five things you cannot do today and will be able to do by Sunday night:

1. Answer "top 20 endpoints by p95 latency" from a 1 GB log two different ways, and explain why one is **4.9× faster** than the other.
2. Write a script that is provably idempotent, provably mutually exclusive, and survives 200 random `SIGKILL`s without corrupting anything.
3. Compute a Git blob's SHA-1 by hand and get the same 40 characters `git hash-object` does.
4. Find a bug hidden in 200 commits in **8 automated test runs**.
5. Query a Postgres on a private subnet from your laptop with **zero ports exposed to the internet**.

## Why this week, and why now

Week 1 taught you what a program is. This week is about the environment every program actually lives in. It is also the week with the highest hourly return of the whole 32: the terminal, Git and SSH are the three tools you will use every single day for the rest of your career, and most engineers learn only enough of each to get by. Two weeks of deliberate practice here compounds for years.

There is one more reason. Everything after Week 5 — Docker, Kubernetes, GPU boxes, training runs on remote machines — assumes you are comfortable in a shell on a machine you cannot see. That comfort is built here.

## Set up before Monday

```bash
# macOS: get GNU tools so your local behaviour matches Linux CI
brew install coreutils findutils gnu-sed grep gawk jq shellcheck tmux git

# Debian/Ubuntu
sudo apt install -y jq shellcheck tmux git build-essential

git --version          # 2.39+
jq --version           # jq-1.7+
shellcheck --version   # 0.10.0+
ssh -V                 # OpenSSH 9.6+ (9.6 fixed the Terrapin downgrade)
```

Generate the test log the labs use (it is 1 GB; make sure you have the space):

```bash
# the generator is in labs/p1/week-02/fixtures/genlog.c
cc -O2 fixtures/genlog.c -o genlog && ./genlog 1000000000 > access.log
wc -l access.log        # ~8,954,064 lines
```

<Warning>
**`grep -P`, `readlink -f`, `date -d` and GNU `sed -i` do not exist on macOS.** Module 2 has
the full BSD-versus-GNU table. Installing GNU coreutils and putting `$(brew --prefix)/opt/coreutils/libexec/gnubin`
on your `PATH` is the fastest way to stop discovering these one at a time in CI.
</Warning>

## What "done" looks like

- A public repo whose **commit history was generated by the lab itself** — a monitor that samples, reports, commits and pushes, idempotently, over SSH.
- Timings for both log-pipeline shapes on your machine, with the ratio and one paragraph on why.
- A `~/.ssh/config` with at least one `ProxyJump` and `ControlMaster` enabled, and a key you generated this week.
- `shellcheck` clean on every script in the repo.
- One diagram redrawn from memory and committed.
