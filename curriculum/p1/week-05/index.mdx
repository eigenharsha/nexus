## Outcome

<Note>
By Sunday you can trace one URL from keypress to pixels with measured numbers at every step, and
you have deployed a responsive, accessible page that consumes a real API and stays fast with
50,000 rows in it.
</Note>

This is the week the course turns outward. Weeks 1–4 were about one machine: memory, the shell,
Python, concurrency. From here on, everything you build is something another machine talks to. You
need the contract — HTTP — before you can design an API in Week 6 or store its data in Weeks 7–8.

The through-line: **every layer here is a place where latency hides.** A connection you did not
reuse costs 96 ms. A blocking script costs 135 ms. A layout read inside a loop costs 100× per row.
You will measure all three yourself this week rather than take them on faith.

## Where this week's numbers come from

<Note>
**Measured.** Every figure in this week was run on this course's own hardware — an Apple Silicon
laptop (11 cores, 18 GB, macOS), Chrome-headless-shell 134, Node 24.19 and `curl` 8.x — and each
one carries the command that produced it. Nothing here is modelled. The full reproduction log,
with the exact invocations and the raw timings, is committed at `evidence/phase-1-w05-08-measurements.md`.

Network timings depend on your distance to the origin; the *ratios* (keep-alive versus fresh
connections, virtualized versus full render, `Promise.all` versus sequential `await`) are the
claims, and those you should reproduce. See [About the numbers](/start/about-the-numbers) for what "measured" commits us to.
</Note>

## What you should be able to say out loud by Sunday

1. "45% of that request finished before a byte of my data was sent, and here is the breakdown."
2. "This is a `PATCH`, not a `PUT`, because the client does not own the whole representation."
3. "Grid, not Flexbox — the container decides the structure and the columns must line up across rows."
4. "Those three calls are independent, so `Promise.all`; sequential `await` would have been 2.6× slower."
5. "That is a preflight failure. The fix is on the server; nothing I do in the browser can authorise it."

## Prerequisites check

Before Monday you should be able to: run a shell script and read its output (`P1-W02-M3`); explain
what `await` does in Python (`P1-W04-M4`); and open a terminal, run `curl` and `node --version`
without looking anything up. If `node -v` prints nothing, install Node 20 LTS or newer first — the
JavaScript modules assume it.

## What this week feeds

Week 6 makes you the server this front end is talking to: the same status codes, the same CORS
headers, the same idempotency problem, from the other side. Weeks 7–8 are what happens behind that
server when the data has to be correct. Keep the repo you build this week — the Week 6 lab wires
its API into this exact front end.
