## Outcome

<Note>
By Sunday you will have written — from scratch, with tests — a dynamic array, a doubly linked
list, an LRU cache, a hash table with two different collision strategies, and a min-heap; you
will have benchmarked all of them against CPython's built-ins; and you will be able to explain,
with numbers from your own machine, the three places where Big-O told you the wrong thing.
</Note>

## Why this week is not "the interview prep week"

You will pass technical screens more easily after this week. That is a side effect, not the point.

The point is that every system you build in the back half of this course is one of these five
structures wearing a costume:

| What you build later | What it actually is | Week |
| --- | --- | --- |
| Semantic cache in front of an LLM | hash map + doubly linked list (LRU) | 28 |
| HNSW's candidate queue during graph descent | bounded min-heap | 27 |
| A database index page walk | a B-Tree, which is a BST that gave up on being a BST | 8, 14 |
| Token vocabulary lookup in a tokenizer | open-addressed hash table | 25 |
| Agent step graph validation | topological sort with cycle detection | 30 |
| Streaming top-K over a token log | bounded heap + reservoir sampling | 32 |

If you learn these structures as trivia you will re-learn them badly in week 27 under time
pressure. If you learn them now as *machinery*, week 27 is a naming exercise.

## The measurement environment

Every number in this week's pages was measured on one machine and you should reproduce them on
yours. Numbers that do not reproduce are the most interesting thing in the week — chase them.

| | |
| --- | --- |
| Machine | Apple M3 Pro, 18 GB unified memory, macOS 15 |
| Python | CPython 3.12.9 (Homebrew), no JIT, no `-O` |
| Timing | `time.perf_counter`, best-of-5, `gc.collect()` before each rep |
| Memory | `tracemalloc` peak for Python-heap figures; `ru_maxrss` for whole-process figures |

<Warning>
Best-of-N, not mean. A mean folds in every unrelated thing your laptop did during the run —
Spotlight indexing, a browser tab, thermal throttling. The minimum is the closest you get to
"the work itself", and it is the number that reproduces.
</Warning>

## Exit checks

You are done with week 13 when you can do all five of these without notes:

1. Derive the amortized O(1) cost of appending to a doubling dynamic array, using the accounting method.
2. Explain why a linked list traversal can be slower than an array traversal of the same length even though both are O(n) — and quote your own measured ratio.
3. Implement an LRU cache with O(1) `get` and `put` in under 15 minutes.
4. State the load factor at which your open-addressed table becomes slower than your chained table, from your own sweep.
5. Find the top 100 of a 10-million-element stream using under 1 MB of working memory, and say why the bounded heap is O(n log k) and not O(n log n).
