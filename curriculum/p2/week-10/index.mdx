## Outcome

<Note>
By Sunday you will have built a multi-room chat server on raw sockets that survives a thousand
concurrent clients, documented its wire protocol, and diagnosed a network problem with a packet
capture rather than a guess.
</Note>

Week 9 ended at the machine's edge — a CPU that can compute and remember. This week is what happens
when two of them need to talk, and it is the week where "it works on my machine" stops being a joke
and becomes a diagnosable class of failure.

## What makes this week different

Almost everything you have used so far — HTTP clients, database drivers, message queues — is a thin
layer over this module's material. This week you write the layer.

Three threads run through all five modules:

1. **Round trips dominate.** A measured HTTPS request took 88.8 ms, of which 87 ms was three round
   trips and about 2 ms was work. Every performance decision in networking is "can I remove a round
   trip", not "can I make the code faster".
2. **TCP gives you a byte stream, not messages.** You will measure 1,000 sends becoming 413 reads,
   with one read returning 40 messages. Every framing bug in every network program is a
   misunderstanding of this one fact.
3. **Concurrency model is a memory decision.** Thread-per-connection measured 1,002 OS threads and
   35.7 KiB/connection; an event loop measured 2 threads and 0.9–6.0 KiB. That is the whole C10K
   argument, in two numbers.

## Prerequisites

- Week 4 (`asyncio`, the event loop) and Week 5 (HTTP as a client).
- Python 3.12 or 3.13. For the serialisation benchmark: `msgpack` 1.2.x, `protobuf` 7.x,
  `grpcio-tools` (which bundles `protoc`).
- `tcpdump` and Wireshark for the packet captures. On macOS, `tcpdump` needs `sudo`.
- `openssl` 3.x for the TLS module.
- Optional but strongly recommended: a Linux machine or container, because `tc netem` (loss and delay
  emulation) has no clean macOS equivalent.

## A warning about this week's measurements

Every number above was measured on one machine, on one network, once, and several were taken while
the machine was under heavy concurrent load. **Reproduce them.** Where your numbers differ, that is
a finding worth writing down — particularly for the socket benchmark in Module 3, where the ordering
of the three concurrency models is stable but the magnitudes are not.

Getting a different answer and being able to explain why is the actual skill this week teaches.
