### The words, defined

- **Population** — everything you would like to know about. All users, all requests, all emails.
- **Sample** — the part you actually measured.
- **Parameter** — a true number about the population, e.g. the true conversion rate. Usually unknown.
- **Statistic** — a number computed from the sample, e.g. the observed conversion rate.
- **Estimator** — the recipe for computing a statistic. **Estimate** — the number it produced this time.
- **Bias** — does the estimator get the right answer on average?
- **Variance** — how much does the estimate bounce around between samples?
- **Standard error** — the standard deviation of the estimator. For a mean, `σ/sqrt(n)`.
- **Confidence interval** — a range computed so that, if you repeated the whole procedure many times,
  95% of the intervals produced would contain the true parameter.

### Estimating a mean, and watching the interval shrink

```python
import numpy as np
from scipy import stats
rng = np.random.default_rng(0)

pop = rng.normal(100, 15, 1_000_000)         # the "population": true mean 100
for n in (10, 30, 100, 1000, 10000):
    s = rng.choice(pop, n, replace=False)
    se = s.std(ddof=1) / np.sqrt(n)          # standard error
    hw = stats.t.ppf(0.975, n - 1) * se      # half-width of a 95% interval
    print(f"n={n:>6}  mean={s.mean():7.3f}  95% CI half-width={hw:7.3f}  "
          f"contains 100: {abs(s.mean() - 100) < hw}")
```

Measured:

```
n=    10  mean= 98.313  95% CI half-width= 12.005  contains 100: True
n=    30  mean= 98.764  95% CI half-width=  4.246  contains 100: True
n=   100  mean= 99.432  95% CI half-width=  2.977  contains 100: True
n=  1000  mean= 99.459  95% CI half-width=  0.996  contains 100: True
n= 10000  mean= 99.867  95% CI half-width=  0.297  contains 100: True
```

The interval shrinks like `1/sqrt(n)`, which has a consequence worth internalising:

**To halve your uncertainty, you need four times the data.** From n=100 to n=10,000 — a hundredfold
increase — the half-width fell from 2.977 to 0.297, exactly a factor of ten. Diminishing returns are
built into the mathematics.

### What a confidence interval actually means

The correct statement: **"if I repeated this entire procedure many times, 95% of the intervals I
construct would contain the true value."**

The tempting and wrong statement: "there is a 95% probability the true value is in *this* interval."
The true value is a fixed number; it is either in this interval or it is not. The 95% describes the
*procedure*, not this particular interval.

In practice, people use the loose interpretation and it rarely causes harm. What *does* cause harm is
the next one.

### The trap: comparing two overlapping intervals

Suppose model A has a 95% CI of `[0.890, 0.953]` and model B has `[0.925, 0.974]`. They overlap.
Does that mean the models are not significantly different?

**No.** That inference is invalid, and it is the single most common statistical error in machine
learning practice.

The reason is that you are asking about the **difference**, and the difference has its own uncertainty
which is *smaller* than either interval suggests — especially when the two models were evaluated on
the **same test set**, because then their errors are correlated and much of the noise cancels.

The correct procedure is to compute a confidence interval **on the difference itself**. Layer 2 does
exactly this on real models, and the answer flips.

### Hypothesis testing

The formal machinery for "is this difference real":

1. **Null hypothesis (H₀)** — the boring explanation. "There is no difference."
2. **Alternative (H₁)** — what you suspect. "There is a difference."
3. Compute a **test statistic** measuring how far your data is from what H₀ predicts.
4. Compute the **p-value**: the probability of seeing data at least this extreme **if H₀ were true**.
5. If `p < α` (conventionally 0.05), reject H₀.

```python
from scipy import stats
import numpy as np
rng = np.random.default_rng(1)
a = rng.normal(100, 15, 200)
b = rng.normal(103, 15, 200)                  # a genuine 3-unit difference
t, p = stats.ttest_ind(a, b)
print(f"means: {a.mean():.2f} vs {b.mean():.2f}   t={t:.3f}  p={p:.5f}")
```

```
means: 98.90 vs 101.64   t=-2.008  p=0.04534
```

A real 3-unit difference, `n = 200` per group, and `p = 0.045` — only just under the threshold. That
is worth noticing: a genuine effect of this size is detected only marginally at this sample size, which
is exactly what the power analysis in Layer 2 quantifies.

### What a p-value is NOT

Memorise this list. It is asked in interviews and misunderstood in meetings.

A p-value is **not**:

- ❌ The probability that the null hypothesis is true.
- ❌ The probability that your result was "due to chance".
- ❌ The probability that the result will replicate.
- ❌ A measure of how big or important the effect is.
- ❌ Evidence *for* the null when it is large. `p = 0.4` means "not enough evidence", not "no effect".

A p-value **is**: the probability of observing data at least this extreme, **assuming the null
hypothesis is true**. It is `P(data | H₀)`, and from Module 1 you know that is not `P(H₀ | data)`.

**The practical replacement:** report the **effect size with a confidence interval**, and let the
p-value be a footnote. "Model B is +2.87 F1 points better, 95% CI [+0.74, +5.38]" tells you the
direction, the magnitude and the uncertainty. "p = 0.012" tells you almost nothing.

### The bootstrap: a confidence interval for anything

Here is the idea, and it is startlingly simple.

You have one sample of size `n`. You want to know how much your statistic would wobble across
different samples — but you only have one sample. So: **treat your sample as if it were the
population, and draw new samples from it, with replacement.**

```python
import numpy as np

def bootstrap_ci(data, statistic, B=10_000, alpha=0.05, seed=0):
    rng = np.random.default_rng(seed)
    data = np.asarray(data)
    n = len(data)
    boots = np.array([statistic(data[rng.integers(0, n, n)]) for _ in range(B)])
    lo = np.percentile(boots, 100 * alpha / 2)
    hi = np.percentile(boots, 100 * (1 - alpha / 2))
    return statistic(data), lo, hi

rng = np.random.default_rng(0)
sample = rng.lognormal(0, 1, 500)            # a nasty skewed sample
print("mean  ", bootstrap_ci(sample, np.mean))
print("median", bootstrap_ci(sample, np.median))
print("p99   ", bootstrap_ci(sample, lambda x: np.percentile(x, 99)))
```

**With replacement** is the essential detail: each resample contains some observations twice and omits
others, which is exactly what simulates the variability of drawing a new sample.

Why this is the tool to learn: there is a formula for the standard error of a mean. There is no simple
formula for the standard error of an **F1 score**, a **median**, a **p99**, or the **AUC of a
classifier**. The bootstrap handles all of them with the same ten lines.

<Accordion title="Answer">

The p99's relative interval is much wider.

The mean uses every data point, so resampling changes it only slightly. The p99 is determined by
roughly the top 1% of the data — about 200 points out of 20,000 — and a resample can easily include or
exclude several of the most extreme ones. **A percentile deep in the tail is estimated from very few
observations, so it is intrinsically noisy.**

The practical consequence is the one worth carrying: **p99 and especially p99.9 need far more data
than the mean to estimate reliably.** A p99.9 computed from 1,000 requests rests on about one
observation, and reporting it to three significant figures is false precision. If your monitoring
reports p99.9 from a one-minute window with a few hundred requests, that number is mostly noise —
which is why sketch-based metrics report error bounds and why long windows matter for deep percentiles.

</Accordion>

### Choosing the right test

| Question | Test | Assumptions | When it breaks |
|---|---|---|---|
| Two group means differ? | Welch's t-test (`ttest_ind(..., equal_var=False)`) | Roughly normal *sample means* (CLT) | Very heavy tails at small `n` |
| Two group means, same subjects? | Paired t-test | Differences roughly normal | — |
| Two distributions differ at all? | Mann-Whitney U | Independent samples | Sensitive to shape, not only location |
| Two proportions differ? | Two-proportion z-test, or chi-square | `np` and `n(1−p)` above ~5 | Very rare events; use Fisher's exact |
| Categorical association? | Chi-square test of independence | Expected counts above ~5 per cell | Sparse tables; use Fisher's exact |
| Any statistic, no formula? | **Bootstrap** | Sample is representative; `n` not tiny | Extreme quantiles; very small `n` |

**Always use Welch's t-test, never Student's.** `scipy.stats.ttest_ind` defaults to `equal_var=True`,
which assumes both groups have the same variance — an assumption you almost never have reason to make,
and which costs you nothing to drop. Set `equal_var=False` every time.

**One-tailed versus two-tailed.** A one-tailed test has more power but only detects an effect in the
direction you predicted. Choose it **before** seeing the data or not at all; switching to one-tailed
after seeing which way the result went halves your p-value illegitimately and is a recognised form of
p-hacking.

### Effect size, which is what actually matters

A p-value tells you whether an effect is *detectable*. It says nothing about whether it *matters*.
With `n = 10,000,000` almost every difference is significant.

**Cohen's d** for two means:

```python
import numpy as np
def cohens_d(a, b):
    a, b = np.asarray(a), np.asarray(b)
    na, nb = len(a), len(b)
    pooled = np.sqrt(((na - 1) * a.var(ddof=1) + (nb - 1) * b.var(ddof=1)) / (na + nb - 2))
    return (b.mean() - a.mean()) / pooled
```

Conventional (and rough) interpretation: 0.2 small, 0.5 medium, 0.8 large. But the honest version is
that the meaningful threshold is **domain-specific**: a 0.5% conversion lift is enormous for an
e-commerce site and negligible for a research benchmark.

**Report this, always: effect size, confidence interval, sample size, and the p-value last.**

### The main event: is model B better than model A?

Two real naive Bayes classifiers from Module 1, differing only in the smoothing parameter, evaluated
on the same 1,115-message test set.

```python
import numpy as np
rng = np.random.default_rng(0)

def f1_of(y, pred):
    tp = ((y == 1) & (pred == 1)).sum()
    fp = ((y == 0) & (pred == 1)).sum()
    fn = ((y == 1) & (pred == 0)).sum()
    p = tp / (tp + fp) if tp + fp else 0.0
    r = tp / (tp + fn) if tp + fn else 0.0
    return 2 * p * r / (p + r) if p + r else 0.0

# predA, predB: predictions of the two models on the SAME test set; yt: true labels
B = 10_000
idx = rng.integers(0, len(yt), size=(B, len(yt)))       # ONE index set, used for BOTH models
bA = np.array([f1_of(yt[i], predA[i]) for i in idx])
bB = np.array([f1_of(yt[i], predB[i]) for i in idx])
diff = bB - bA                                           # the PAIRED difference

print(f"A F1 = {f1_of(yt, predA):.4f}  95% CI [{np.percentile(bA,2.5):.4f}, {np.percentile(bA,97.5):.4f}]")
print(f"B F1 = {f1_of(yt, predB):.4f}  95% CI [{np.percentile(bB,2.5):.4f}, {np.percentile(bB,97.5):.4f}]")
print(f"paired difference 95% CI [{np.percentile(diff,2.5):+.4f}, {np.percentile(diff,97.5):+.4f}]")
print(f"P(B > A) across resamples = {(diff > 0).mean():.4f}")
```

Measured output:

```
model A (alpha=1.0)  F1 = 0.9231
model B (alpha=0.1)  F1 = 0.9518
observed difference  = +0.0287
A 95% bootstrap CI: [0.8898, 0.9527]
B 95% bootstrap CI: [0.9251, 0.9742]
PAIRED difference 95% CI: [+0.0074, +0.0538]
P(B > A) over bootstrap resamples = 0.9966
CIs overlap: True
```

**Look at what just happened.**

- A's interval is `[0.890, 0.953]`. B's is `[0.925, 0.974]`. **They overlap substantially.** The
  naive reading is "no significant difference".
- The **paired difference** interval is `[+0.0074, +0.0538]` — **entirely above zero.** B is better,
  with 99.66% of resamples agreeing.

Both statements are computed from the same data. The second one is correct and the first is a
misapplication.

**Why the difference is so much tighter:** the two models are evaluated on the *same messages*. When a
bootstrap resample happens to include several hard messages, **both** models do worse on it, so the
difference is unaffected. The shared noise cancels. That is what "paired" means, and it is why the
same index array `idx` must be used for both models.

**This is the single most useful ten lines in Week 12.** It works for F1, AUC, accuracy, BLEU, an LLM
judge's win rate, or any metric you can compute — and it is exactly what you will use in Week 31 to
decide whether a prompt change actually helped.

### Power analysis: how much data do you need?

**Power** is the probability of detecting a real effect. Conventionally you want 0.80 — meaning you
will miss a real effect 20% of the time. Four quantities are linked, and fixing any three determines
the fourth:

- `α` (false-positive rate, usually 0.05)
- Power (usually 0.80)
- Effect size
- Sample size

```python
from scipy import stats
import numpy as np

def n_for_two_means(effect_d, alpha=0.05, power=0.80):
    za = stats.norm.ppf(1 - alpha / 2)
    zb = stats.norm.ppf(power)
    return int(np.ceil(2 * ((za + zb) / effect_d) ** 2))

for d in (0.1, 0.2, 0.5, 0.8):
    print(f"Cohen's d = {d}: {n_for_two_means(d):>7,} per group")
```

```
Cohen's d = 0.1:  1,570 per group
Cohen's d = 0.2:    393 per group
Cohen's d = 0.5:     63 per group
Cohen's d = 0.8:     25 per group
```

Note the shape: **sample size scales as `1/d²`.** Halving the effect you want to detect quadruples the
data required. Do this calculation *before* running the experiment; doing it afterwards to explain a
null result is called a post-hoc power analysis and it is uninformative.

### Trade-offs

| Decision | Choose this when… | Choose the other when… | The number |
|---|---|---|---|
| **Bootstrap** | Any statistic without a clean formula (F1, AUC, median, p99) | You need speed and the statistic is a mean | 10,000 resamples of a 1,115-row test set runs in seconds |
| **Paired comparison** | Both models evaluated on the same data | Genuinely independent samples | Paired CI `[+0.0074, +0.0538]` versus overlapping individual CIs — the paired one is decisive |
| **Welch's t-test** | Always, for two means | Never — assuming equal variance buys nothing | `equal_var=False`; scipy's default is `True`, which is the wrong default |
| **Report effect size + CI** | Always | Never report a bare p-value | "+2.87 F1 points, CI [+0.74, +5.38]" versus "p = 0.012" |
| **Percentile bootstrap** vs **BCa** | Quick work; roughly symmetric statistic | Skewed statistic, or you need accurate coverage | BCa corrects for bias and skew; it is what `scipy.stats.bootstrap(method='BCa')` does |

### What breaks in the real world

A team ran an experiment comparing a new retrieval model against the incumbent on 400 queries. The new
model's mean nDCG@10 was 0.612 against 0.598. The 95% CIs were `[0.577, 0.647]` and `[0.564, 0.632]` —
overlapping — so the readout said "no significant improvement" and the work was shelved.

Six months later someone recomputed it as a **paired** comparison on the same 400 queries. The mean
per-query difference was +0.014 with a 95% CI of `[+0.004, +0.024]`, and a paired t-test gave
`p = 0.006`. The improvement had been real and detectable all along.

**Query difficulty was the dominant source of variance**, and it was shared: hard queries scored low
for both models. The unpaired analysis let that shared variance swamp a real 2.3% relative improvement.
Pairing removed it.

Two rules came out of it, and they are worth adopting verbatim. **If both systems were evaluated on the
same items, the analysis must be paired** — this is not an optimisation, it is a correctness
requirement. And **never conclude "no difference" from overlapping intervals**; compute the interval on
the difference.

### Design checkpoint

<Accordion title="You have 500 eval prompts. A prompt change moves your LLM judge's win rate from 62% to 66%. Is it real? What do you report?">

**First, do the paired analysis.** If both prompt versions were run on the same 500 prompts — and they
should have been — you have 500 paired outcomes. Count them properly:

The relevant statistic is not the two rates but the **discordant pairs**: prompts where old won and new
lost, versus old lost and new won. That is **McNemar's test**, which is the correct test for paired
binary outcomes, and it is far more powerful than comparing two proportions.

```python
from scipy import stats
# b = old wins, new loses;  c = old loses, new wins
b, c = 31, 51
result = stats.binomtest(c, b + c, 0.5)      # exact McNemar
print(f"discordant: {b} vs {c}, p = {result.pvalue:.4f}")
# discordant: 31 vs 51, p = 0.0352
```

**Second, put an interval on the difference.** A paired bootstrap over the 500 prompts gives a CI on
the win-rate difference. With `n = 500` and a 4-point difference, expect a half-width in the region of
3–4 points — so the interval will be close to zero and the honest answer may well be "promising but
not conclusive".

**Third, and this is the part people skip: check what the eval can detect at all.** From Module 1's
arithmetic, `n = 500` with `α = 0.05` and 80% power detects roughly a 6-percentage-point difference in
a proportion near 60%. **A 4-point difference is below your eval's resolution.** That is a fact about
the eval, not about the change, and it should have been known before running it.

**What to report:**

> "Win rate 62% → 66%, paired difference +4.0 points, 95% CI [−0.4, +8.4], McNemar p = 0.04.
> Our 500-prompt eval has ~80% power to detect a 6-point difference, so this is at the edge of what we
> can resolve. Recommend: expand to 1,200 prompts before deciding, or ship behind a flag and measure
> the online metric."

**What not to report:** "win rate improved 4 points" with no interval, which is what usually happens.

The senior move is naming the eval's resolution up front. An eval that cannot detect the size of
change you typically make is not an eval, it is a ritual — and knowing its minimum detectable effect
tells you whether to invest in more prompts or in a more sensitive metric (a graded score rather than
a binary win, which typically cuts the required `n` substantially).

### Bootstrap variants and when the simple one fails

| Method | What it does | Use when |
|---|---|---|
| **Percentile** | Take the 2.5th and 97.5th percentiles of the bootstrap distribution | Roughly symmetric statistic; quick work |
| **Basic (pivotal)** | Reflects the bootstrap distribution around the observed value | Bias is suspected |
| **BCa** | Bias-corrected and accelerated; adjusts for both bias and skewness | The statistic is skewed; you need accurate coverage. `scipy.stats.bootstrap(method='BCa')` |
| **Studentised** | Bootstraps a t-like pivot | Highest accuracy; needs a variance estimate per resample |
| **Block bootstrap** | Resamples contiguous blocks | **Time-series or autocorrelated data** — the ordinary bootstrap is invalid |

The last row is the one that bites in production. **The ordinary bootstrap assumes exchangeable
observations.** Latency measurements taken in sequence are autocorrelated (a GC pause makes several
consecutive requests slow), so resampling individual observations destroys that structure and produces
intervals that are far too narrow. Use a block bootstrap with a block length longer than the
autocorrelation.

**How many resamples?** For a confidence interval, `B = 2,000` is usually adequate and `B = 10,000` is
comfortable. The Monte Carlo standard error of a bootstrap percentile falls as `1/sqrt(B)`, so going
from 2,000 to 10,000 reduces it by 2.24×. For a p-value near a decision threshold you want more,
because you are resolving a tail.

**Where the bootstrap genuinely fails:** extreme quantiles (the max, or a p99.99 from few points),
very small samples (`n < 20`), and any statistic that is a non-smooth function of the data.

### Multiple comparisons

If you run `m` independent tests at `α = 0.05`, the probability of at least one false positive is
`1 − 0.95^m`:

| Tests `m` | P(at least one false positive) |
|---|---|
| 1 | 5% |
| 5 | 23% |
| 10 | 40% |
| 20 | 64% |
| 100 | **99.4%** |

Measured on pure noise (200 samples, `k` independent standard normal variables, all pairwise
correlations tested):

| Variables `k` | Pairs | With `p < 0.05` | Rate | Surviving Bonferroni |
|---|---|---|---|---|
| 5 | 10 | 0 | 0.00% | 0 |
| 20 | 190 | 6 | 3.16% | 0 |
| 100 | 4,950 | **257** | 5.19% | **0** |

**257 "significant" correlations among 100 variables that are all independent noise.** The observed
rate tracks the nominal 5% exactly, which is the point: `α` is doing precisely what it promises, and
the promise is not what people assume.

Corrections:

- **Bonferroni** — test at `α/m`. Simple, controls the family-wise error rate, very conservative. In
  the table above it correctly rejected all 257.
- **Holm-Bonferroni** — a stepwise version; uniformly more powerful than Bonferroni, same guarantee.
  There is no reason to use plain Bonferroni instead.
- **Benjamini-Hochberg** — controls the *false discovery rate* (the expected fraction of your
  rejections that are false) rather than the family-wise error rate. Much more powerful when you have
  many tests and can tolerate some false discoveries. The default in genomics and the right choice for
  screening.

**In practice this means: designate one primary metric before the experiment.** Everything else is
exploratory and must be labelled as such. A dashboard with 40 metrics, checked for significance, will
show about two "significant" movements per experiment purely by chance.

### P-hacking and the garden of forking paths

The ways a nominal 5% false-positive rate becomes much larger, all of which are common and mostly
unintentional:

| Practice | Effect on the false-positive rate |
|---|---|
| Peeking at the result and stopping when significant | Measured in Module 4: **5% → 25%** with 20 looks |
| Trying several metrics, reporting the best | `1 − 0.95^m` |
| Trying several segments, reporting the best | Same, and segments are usually many |
| Excluding outliers after seeing the result | Unquantifiable, and it is a decision made from the data |
| Switching from two-tailed to one-tailed after the fact | Halves the p-value illegitimately |
| Adding covariates until it is significant | Unquantifiable |

Gelman and Loken's "garden of forking paths" is the important subtlety: **you do not have to
consciously p-hack for this to happen.** If you would have made different reasonable analysis choices
had the data come out differently, the effective number of comparisons is far greater than one, even
though you only ran one analysis.

The defence is **pre-registration**: write down the primary metric, the analysis, the exclusion rules
and the decision threshold *before* looking at the data. Internally this can be a paragraph in the
experiment ticket. It costs ten minutes and it is the only thing that actually works.

### Confidence intervals for proportions: use the right one

The textbook (Wald) interval for a proportion is `p̂ ± z·sqrt(p̂(1−p̂)/n)`, and it is **badly broken**
for small `n` or extreme `p̂`. With `p̂ = 0` it produces a zero-width interval, which is obviously
wrong, and its actual coverage can fall far below the nominal 95% even at moderate `n`.

Use instead:

- **Wilson score interval** — good coverage across the whole range, closed form, the sensible default.
- **Agresti-Coull** — add 2 successes and 2 failures, then use Wald. Nearly as good, trivial to
  implement.
- **Clopper-Pearson** — exact, guaranteed at-least-nominal coverage, conservative.

```python
from scipy import stats
import numpy as np

def wilson(k, n, conf=0.95):
    z = stats.norm.ppf(1 - (1 - conf) / 2)
    p = k / n
    denom = 1 + z**2 / n
    centre = (p + z**2 / (2*n)) / denom
    half = z * np.sqrt(p*(1-p)/n + z**2/(4*n**2)) / denom
    return centre - half, centre + half

print(wilson(0, 100))     # (3.47e-18, 0.03699) -- sensible; Wald would give (0.0, 0.0)
print(wilson(3, 100))     # (0.01025, 0.08452)
```

This matters directly for conversion rates, error rates and eval pass rates — all of which are
proportions, and many of which are small.

### Production failure modes

| Failure | Signature | Detection |
|---|---|---|
| **Overlapping CIs read as "no difference"** | A real improvement shelved | Always interval the *difference*; pair when the same items were used |
| **Unpaired analysis of paired data** | Underpowered; real effects missed | The war story: unpaired CIs overlapped, paired gave `p = 0.006` |
| **Bootstrap on autocorrelated data** | Intervals far too narrow; coverage well below nominal | Block bootstrap with a block longer than the autocorrelation |
| **Wald interval on a small proportion** | Zero-width or out-of-range intervals | Wilson or Clopper-Pearson |
| **Many metrics, no correction** | Two "significant" results per experiment, always | Designate a primary metric; Holm or Benjamini-Hochberg for the rest |
| **`equal_var=True` by default** | Slightly wrong p-values when variances differ | Always `equal_var=False` (Welch) |
| **Post-hoc power analysis** | "We were underpowered" computed after a null result | Power analysis is a design tool; after the fact it is a restatement of the p-value |
| **Statistical significance reported as business significance** | A 0.01% lift shipped as a win because `n` was huge | Report the effect size and its interval; decide against a pre-agreed threshold |

### Frontier and further pointers

- **R. L. Wasserstein and N. A. Lazar, "The ASA Statement on p-Values: Context, Process, and Purpose,"
  *The American Statistician* 70(2), 2016.** Takeaway: the American Statistical Association's six
  principles state explicitly that p-values do not measure the probability of a hypothesis or the size
  of an effect, and that decisions should not be based on whether `p < 0.05` alone.
- **B. Efron, "Bootstrap Methods: Another Look at the Jackknife," *Annals of Statistics* 7(1), 1979.**
  Takeaway: resampling your own data with replacement estimates the sampling distribution of *any*
  statistic without a formula or a distributional assumption — the single most practically useful idea
  in applied statistics.
- **A. Gelman and E. Loken, "The Garden of Forking Paths" (2013).** Takeaway: multiple comparisons
  inflate false positives even when only one analysis is run, provided the analyst *would have* chosen
  differently under different data — which is why pre-registration rather than good intentions is the
  defence.
- **L. D. Brown, T. T. Cai and A. DasGupta, "Interval Estimation for a Binomial Proportion,"
  *Statistical Science* 16(2), 2001.** Takeaway: the standard Wald interval has erratic and often
  badly deficient coverage even at large `n`, and Wilson or Agresti-Coull should be the default.
- **T. Dietterich, "Approximate Statistical Tests for Comparing Supervised Classification Learning
  Algorithms," *Neural Computation* 10(7), 1998.** Takeaway: the common procedures for comparing
  classifiers have badly inflated type-I error rates, and the tests that survive scrutiny are the
  paired ones — McNemar's, and 5×2-fold cross-validated t-tests.

### Stretch challenge

Build an evaluation harness that reports uncertainty by default.

1. Implement percentile, basic and BCa bootstrap intervals. Verify the coverage of each by simulation:
   generate 1,000 datasets from a known distribution, compute an interval for each, and check what
   fraction actually contain the true value. It should be 95%. Report where each method falls short.
2. Add a **paired** comparison mode that takes two models' predictions on the same items, and
   demonstrate on the spam classifiers that the paired difference interval is decisive where the
   individual intervals overlap.
3. Add **block bootstrap** for autocorrelated data. Demonstrate on real latency data that the ordinary
   bootstrap under-covers: measure the autocorrelation, then compare interval widths from the ordinary
   and block versions.
4. Add a **minimum detectable effect** report: given the test set size and observed variance, what is
   the smallest difference this eval could detect at 80% power? Print it alongside every comparison, so
   nobody reports a difference smaller than the eval's resolution.
5. Finally, run it on a real model comparison you care about and write the readout a decision-maker
   would act on: effect size, interval, MDE, and a recommendation.

There is no single right answer — the coverage simulation in step 1 usually shows BCa doing best and
all methods struggling on skewed statistics at small `n`, and quantifying that on your own metric is
the deliverable.

## The whole idea on one whiteboard

You have a **sample**. You want to say something about the **population** it came from.

Everything you compute from a sample — a mean, an F1 score, a conversion rate — is an **estimate**,
and it would have come out differently with a different sample. So the honest output is never a single
number; it is a number **plus a range that reflects how much it would wobble**.

Two ways to get that range:

- **Formula-based** — use the CLT: the sample mean's spread is `σ/sqrt(n)`. Fast, requires assumptions,
  only exists for a handful of statistics.
- **Bootstrap** — resample your own data with replacement thousands of times and look at how much the
  statistic varies. Slow, requires almost no assumptions, and **works for any statistic you can
  compute**, including F1, AUC, p99 latency and median revenue per user.

Learn the second one properly. It is the tool you will actually reach for.

## Common mistakes

| Symptom | Cause | Fix |
|---|---|---|
| "No significant difference" from overlapping CIs | Comparing intervals instead of intervalling the difference | Bootstrap the paired difference; measured, it flipped the conclusion |
| Real improvement missed | Unpaired analysis of paired data | Pair when the same items were evaluated; shared variance cancels |
| Confidence intervals far too narrow | Bootstrap on autocorrelated data | Block bootstrap with a block longer than the autocorrelation |
| Zero-width interval on a proportion | Wald interval with `k = 0` | Wilson, Agresti-Coull or Clopper-Pearson |
| Two "significant" results in every experiment | Multiple comparisons uncorrected | One pre-declared primary metric; Holm or Benjamini-Hochberg for the rest |
| p-value interpreted as the probability the null is true | `P(data\|H₀)` confused with `P(H₀\|data)` | Report effect size with an interval; the p-value is a footnote |
| Highly significant, commercially irrelevant | Huge `n` makes trivial effects detectable | Decide a meaningful threshold before the test and compare the interval against it |
| "We were underpowered" after a null result | Post-hoc power analysis | Power analysis before the experiment; afterwards it just restates the p-value |

## Assessment

<AccordionGroup>
<Accordion title="Concept questions (8)">
1. What does a 95% confidence interval mean? *(If the procedure were repeated many times, 95% of the intervals produced would contain the true value.)*
2. How much more data to halve an interval's width? *(4×, since width scales as `1/sqrt(n)`.)*
3. What is a p-value, and name two things it is not. *(`P(data at least this extreme | H₀)`; it is not `P(H₀ | data)` and not a measure of effect size.)*
4. Two 95% CIs overlap. Are the two quantities indistinguishable? *(No — that inference is invalid. Interval the difference, paired if the same items were used.)*
5. Why does pairing help? *(Shared sources of variance — item difficulty, sample composition — affect both systems equally and cancel in the difference.)*
6. Why does the bootstrap resample with replacement? *(Without it every resample is the original sample; replacement generates genuine variability.)*
7. Among 100 independent noise variables, how many pairwise correlations come out `p < 0.05`? *(About 5% of 4,950 pairs — measured, 257.)*
8. When is the ordinary bootstrap invalid? *(When observations are not exchangeable — autocorrelated or time-series data. Use a block bootstrap.)*
