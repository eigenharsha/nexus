## The story this week tells

Last week your friend learned to *do* things: a loop, some tools, a little memory. It worked on
the demo query.

This week is everything between that and a system somebody would put on call. It starts with four
ways to send a person to the shops — improvise, plan first, check your own basket, or send a team
— because those are the four architectures agents actually come in, and choosing the wrong one
costs a month. Then the part nobody photographs: the **harness**, the unglamorous code around the
loop that validates, budgets, recovers and records. Then the design questions that decide quality
— how many tools, described how, and what the agent should still know on turn forty. Then the
frameworks, compared honestly. And finally the hardest question of all: **was that run actually
good, or merely correct?**

<Card title="This week — from a loop to a system" icon="sparkles">
  - **Name the four architectures** — ReAct, plan-then-execute, reflection, multi-agent
  - **Build ReAct by hand** — sixty lines, no framework, every line legible
  - **Write the harness** — validation, budgets, error-as-prompt, truncation, repeat detection
  - **Design six good tools instead of twenty mediocre ones** — and curate what the agent carries
  - **Choose a framework with a table you made yourself** — not a blog post
  - **Score the journey, not just the answer** — because a right answer by a terrible path is not a success
</Card>

## The five numbers you should leave with

| Number | Why it matters |
| --- | --- |
| **~6** | Tools in a well-designed catalogue — more makes choice harder and every call dearer |
| **8** | A sane default turn budget; more usually means the problem was a workflow |
| **4** | Ways agent loops fail: repeated calls, compounding error, confident dead ends, silent partial success |
| **6** | Harness responsibilities: validate, budget, recover, truncate, detect repeats, trace |
| **1** | The column that decides a framework: time to debug the first failure |
