## The story this week tells

Imagine a very smart friend locked in a room, who answers any note you slide under the door —
but has never seen a letter in their life, cannot count the r's in *strawberry*, and writes
back one numbered tile at a time. This week you find out everything about that room: how your
words get in, where meaning lives, how the words talk to each other, and how the reply comes
out. By Sunday, you will have built the room yourself.

No previous AI knowledge is needed — this is the front door of generative AI, and every idea
is introduced from zero, as part of the story.

  - **embedding** — a list of numbers standing for a thing's meaning, placed so similar things sit close together. [Coming in Week 25](/curriculum/p4/week-25/2-embeddings-positional-information)
  - **inference** — running a trained model to get answers (as opposed to training it). [Taught in Week 23](/curriculum/p3/week-23/1-from-notebook-to-service)
  - **forward pass** — pushing an input through a network, layer by layer, to get an output. [Taught in Week 21](/curriculum/p3/week-21/2-forward-pass-loss-backpropagation)
  - **neural network** — layers of simple number-mixing units that, trained together, approximate very complex functions. [Taught in Week 21](/curriculum/p3/week-21/1-from-linear-models-to-neural-networks)
  - **quantization** — storing a model's numbers in fewer bits — trading a sliver of accuracy for a lot of memory and speed. [Coming in Week 26](/curriculum/p4/week-26/1-numeric-precision-quantization)
</Accordion>

This is the week the black box opens. Everything in Phase 4 after this — quantization, LoRA,
retrieval, agents, cost models — assumes you know what is inside. If you only do one week of this
phase properly, do this one.

## The through-line

Five modules, one narrative, each one answering the question the previous one raised:

1. **Text → tokens.** A model never sees text; it sees integers. Which integers, and who decided?
2. **Embeddings & position.** Those integers become vectors by table lookup — and a stack of
   vectors has no order, so order must be injected.
3. **Self-attention.** Each vector pulls information from the others, weighted by learned
   relevance. **This is the module that matters most.**
4. **The block & the decoder.** Wrap attention in residuals, norms and a feed-forward network,
   stack it 32 times, count the parameters.
5. **Generation & cost.** Sample from the output distribution in a loop — and discover that the
   loop has two completely different performance regimes.
6. **Reasoning & thinking budgets.** Since 2025 the frontier models think before they answer;
   the dials for what that costs live here.

## The five numbers you should leave with

If someone stops you in a corridor in six months, these are the ones that should still be there.
All five are **derived** — shape algebra, parameter counts and bandwidth arithmetic — so they are
true on any hardware. The GPU throughput figures inside the modules are **reference figures**
modelled for an A10G the authors did not have; see [About the numbers](/start/about-the-numbers).

| Number | What it is |
| --- | --- |
| `(B, T, D)` → `(B, H, T, Dh)` → `(B, H, T, T)` | The shape chain. Nearly every Transformer bug is a disagreement between two of these. |
| `√d_k = 11.31` for `d_k = 128` | The attention scale factor. Without it, softmax saturates and the gradient falls to 3e-7. |
| `218.1M` per Llama-3-8B layer, 80.8% of it FFN | Where the parameters actually are, which decides where LoRA goes. |
| `512 KiB` per token (Llama-2-7B), `4 GiB` at 8k | The KV cache. It is why your GPU runs out of memory. |
| `13.5 GB ÷ 600 GB/s = 44 tok/s` | Decode speed from weight size and memory bandwidth. Predicts reality to within 10%. |
