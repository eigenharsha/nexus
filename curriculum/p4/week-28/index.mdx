## The story this week tells

Week 27 gave your friend a library card. This week the library gets good.

It starts with an embarrassment: a user types an order code, `TX-4471`, and semantic search
returns three passages about shipping delays — because a code has no meaning, only letters.
So you add the oldest trick in search back in, learn to merge two disagreeing lists honestly,
teach the system to fix vague questions before searching, put a sharper judge on the
shortlist, and make the whole pipeline cheap enough to run.

<Card title="This week — search that actually finds things" icon="sparkles">
  - **Find the code the map of meanings cannot see** — and understand why BM25 refuses to die
  - **Merge two lists in different currencies** — without inventing a false comparison
  - **Answer "why is it broken"** — by fixing the question first
  - **Move the best passage from seventh to first** — and pay for it only ten times, not ten million
</Card>

1. **Sparse retrieval & BM25.** A 50-year-old algorithm that scores 0.94 where every embedding model
   scores 0.39. Derived, tuned, and segmented.
2. **Hybrid search & fusion.** Two retrievers that fail on disjoint query sets, combined by ranks
   rather than scores. One formula, +0.04 NDCG.
3. **Query understanding.** Six techniques, each with an LLM call before retrieval. Two help, one
   is catastrophic on a specific segment, and a router gets the gain at a fifth of the cost.
4. **Re-ranking with cross-encoders.** The highest gain-per-millisecond change in the phase, and
   the arithmetic that explains why it can only run on 50 candidates.
5. **Caching, cost & operations.** What it costs, what happens when a document changes, and how you
   find out it broke without any labels.
