### Why reduce dimensions at all

Four separate reasons, which get confused with each other constantly:

1. **To see the data.** Humans read 2-D. This is the only reason t-SNE and UMAP exist.
2. **To make models faster or smaller.** Fewer columns means fewer computations and a smaller serving footprint.
3. **To remove noise.** If the signal lives in 10 directions and the other 50 are measurement noise, projecting onto the 10 can genuinely improve a downstream model.
4. **To make distances meaningful again.** From Module 4: distances concentrate in high dimensions, so clustering and nearest-neighbour search degrade. Reducing first restores contrast.

Reasons 2, 3 and 4 want PCA. Reason 1 wants t-SNE or UMAP. **Using a reason-1 tool for a reason-2 job is the mistake this module exists to prevent.**

### PCA in one paragraph

Centre the data. Find the direction in which it varies most — that is the **first principal component**. Then find the direction of most remaining variance that is perpendicular to the first — the second component. Repeat. The components are the eigenvectors of the covariance matrix, ordered by their eigenvalues, and the eigenvalue is exactly how much variance that direction carries. Projecting onto the first `k` components is the best possible `k`-dimensional linear approximation of the data in a squared-error sense (Eckart-Young).

```python
# pip install "numpy==2.5.2" "scikit-learn==1.9.0"
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)          # 569 rows, 30 features
Xs = StandardScaler().fit_transform(X)              # PCA is variance-based: SCALE FIRST
p = PCA().fit(Xs)

ev = p.explained_variance_ratio_
print("first 6 components explain:", np.round(ev[:6], 4))
print("cumulative:              ", np.round(np.cumsum(ev)[:6], 4))
for thr in (0.80, 0.90, 0.95, 0.99):
    print(f"components for {thr:.0%} of variance:",
          int(np.searchsorted(np.cumsum(ev), thr) + 1))
```

```
first 6 components explain: [0.4427 0.1897 0.0939 0.066  0.055  0.0402]
cumulative:               [0.4427 0.6324 0.7264 0.7924 0.8473 0.8876]
components for 80% of variance: 5
components for 90% of variance: 7
components for 95% of variance: 10
components for 99% of variance: 17
```

Thirty features, and **7 components carry 90% of the variance**. That is what "these features are redundant" looks like as a number.

<Warning>
**Scale before PCA, always.** PCA maximises variance, and variance is not scale-invariant. A feature measured in millimetres has a thousand times the variance of the same feature in metres and will dominate the first component entirely. `StandardScaler` before `PCA` is not optional; it is part of the method.
</Warning>

### What the components cost you

```python
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline

print("2 PCs :", cross_val_score(make_pipeline(StandardScaler(), PCA(2),
        LogisticRegression(max_iter=5000)), X, y, cv=5).mean())
print("all 30:", cross_val_score(make_pipeline(StandardScaler(),
        LogisticRegression(max_iter=5000)), X, y, cv=5).mean())
```

```
2 PCs : 0.9508
all 30: 0.9807
```

Two components — a 15x reduction — cost **3 accuracy points**. That is the trade in a sentence. Sometimes it is worth it; you now know how to price it.

### t-SNE and UMAP: a different job

**t-SNE** (t-distributed Stochastic Neighbour Embedding) does not find axes. It picks a random 2-D arrangement of your points and then moves them around until each point's *neighbourhood* in 2-D matches its neighbourhood in the original space, where "neighbourhood" means a probability distribution over which other points are near. **UMAP** does something similar via a graph construction with a topological justification. Both:

- Have **no `transform` method for new data** in the classic formulation. t-SNE in scikit-learn genuinely cannot embed a new point; you must refit everything. (UMAP does provide a `transform`.)
- Are **stochastic**: a different `random_state` gives a visibly different picture.
- Have a key parameter controlling how big "neighbourhood" is: `perplexity` for t-SNE (default 30, sensible range 5–50), `n_neighbors` for UMAP (default 15).
- **Deliberately do not preserve global structure.** This is the point of Layer 3 and it is not a caveat, it is the design.

```python
# pip install "umap-learn==0.5.12"
from sklearn.manifold import TSNE
E = TSNE(n_components=2, perplexity=30, random_state=0, init="pca").fit_transform(Xs)
```

`init="pca"` is worth setting explicitly: it makes the result more reproducible and preserves a little more global structure than the random default. In scikit-learn 1.2 and later it is already the default, but state it so the reader knows.

### Guided practice

1. Run PCA without the `StandardScaler` on `load_breast_cancer`. How much variance does the first component explain now?
2. Run t-SNE twice with `random_state=0` and `random_state=1`. Are the pictures the same?
3. Set `perplexity=2` and `perplexity=200` on 569 points. What happens?

<Accordion title="Answers">
1. About **98%**, from a single component. That is not a discovery, it is `worst area`, whose raw values run into the thousands while other features are fractions. Unscaled PCA on mixed-unit data measures your unit choices.
2. No. The blobs will be in different places and possibly different apparent shapes. If your conclusion changes between seeds, it was not a conclusion. Always show at least two seeds before believing a t-SNE picture.
3. `perplexity=2` fragments the data into many tiny groups — it is only looking at 2 neighbours, so it sees nothing global at all. `perplexity=200` on 569 points is over a third of the dataset per neighbourhood, so everything smears into one blob. scikit-learn requires `perplexity < n_samples` and warns below about 5. The measured effect on cluster spread is in Layer 3.
</Accordion>

### Checkpoint

<AccordionGroup>
  <Accordion title="1. Are principal components features you can name?">
  No. Each is a weighted combination of all original features. You can inspect `pca.components_` to see the weights and sometimes a component has an obvious interpretation ("overall size"), but in general the axes are not nameable — which is exactly why PCA before a decision tree destroys the tree's interpretability.
  </Accordion>
  <Accordion title="2. Where must the PCA be fitted?">
  On the training split only, inside a `Pipeline`. Fitting on all data lets the test rows influence the axes. Week 19 Module 4 measures how much this specific leak inflates a score.
  </Accordion>
  <Accordion title="3. Can you use t-SNE output as features for a model?">
  Almost never. It has no `transform` for new rows, it is stochastic, and it discards global structure. If you want learned low-dimensional features, use PCA, an autoencoder, or an embedding model — not a visualisation algorithm.
  </Accordion>
  <Accordion title="4. What does the explained variance ratio sum to?">
  1.0 across all components. It is the fraction of total variance each direction accounts for, so cumulative explained variance is a monotone curve from the first component's share up to 1.
  </Accordion>
  <Accordion title="5. Two clusters in a t-SNE plot are far apart. What can you conclude?">
  That they were not near neighbours in the original space. You cannot conclude they are *more* different than two clusters that appear closer together — Layer 3 measures a case where the true ratio is 6.63 and t-SNE renders it as 1.09.
  </Accordion>
</AccordionGroup>

### PCA as an engineering tool

The three legitimate production uses, with the measurement that decides each.

**1. Speed and size.** Measured on `load_digits` (1,797 rows x 64 features), 5-fold cross-validated logistic regression:

| `n_components` | 5-fold accuracy | Share of columns |
| --- | --- | --- |
| none (64) | **0.9204** | 100% |
| 40 | 0.9138 | 62% |
| 20 | 0.8993 | 31% |
| 10 | 0.8403 | 16% |

Cutting to 40 components costs 0.7 accuracy points for a 38% column reduction; cutting to 10 costs 8 points. **The curve is not linear** — there is a plateau and then a cliff, and where the cliff is depends entirely on the data. Measure it; do not assume "95% variance" is the right rule for your problem, because variance retained and *task* performance retained are different things.

**2. Denoising.** If your signal lives in a low-dimensional subspace and the rest is measurement noise, projecting and reconstructing removes noise. This is the same operation as low-rank image approximation from Week 11, and the same one behind LoRA in Week 26.

**3. Decorrelation before a distance-based method.** From Module 4: distances concentrate in high dimensions and one-hot columns are nearly orthogonal noise. PCA first, then cluster.

The one place PCA is usually a mistake: **before a tree ensemble.** Trees are already invariant to monotone per-feature transforms and unaffected by irrelevant features, so PCA buys almost nothing — and it rotates the axes away from the named features that made the tree interpretable in the first place (Module 1's axis-alignment result, seen from the other side).

### Fit on train only

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.linear_model import LogisticRegression

model = Pipeline([
    ("scale", StandardScaler()),
    ("pca",   PCA(n_components=0.95, random_state=0)),   # keep 95% of variance
    ("clf",   LogisticRegression(max_iter=5000)),
])
```

`n_components` accepts a float between 0 and 1, meaning "enough components for this fraction of variance". Inside a `Pipeline` the number of components is re-chosen per fold from that fold's training data, which is correct — deciding it once on the full dataset is a leak.

<Warning>
`PCA` is unsupervised, so fitting it on all of `X` (without `y`) *feels* safe. It is not: the principal directions are computed from the test rows' feature values, so information about the test distribution enters the training. It is usually a small leak, but it is free to avoid and Week 19 Module 4 quantifies exactly this family of mistakes.
</Warning>

### Variants worth knowing

| Variant | Use when | Cost |
| --- | --- | --- |
| `PCA(svd_solver="randomized")` | `n_components` is much smaller than `min(n, p)`; large matrices | approximate, much faster; the default `"auto"` already picks it when it applies |
| `IncrementalPCA` | data does not fit in memory | `partial_fit` over batches; slightly different result |
| `TruncatedSVD` | **sparse** input (TF-IDF) — `PCA` centres the data and centring densifies a sparse matrix | does not centre; on TF-IDF this is called LSA |
| `KernelPCA` | the structure is non-linear and you need a `transform` for new rows | `O(n^2)` kernel matrix; does not scale past tens of thousands of rows |
| `SparsePCA` | you want components that load on few original features, for interpretability | much slower; an optimisation problem rather than an eigendecomposition |

The `TruncatedSVD` row is the one that bites people. Calling `PCA` on a 50,000-column TF-IDF matrix raises a `TypeError` for sparse input in scikit-learn — and if you densify it first to "fix" that, you allocate an array that will not fit. Use `TruncatedSVD`.

### t-SNE and UMAP: the parameters that matter

| Parameter | t-SNE | UMAP | What it controls |
| --- | --- | --- | --- |
| Neighbourhood size | `perplexity` (5–50, default 30) | `n_neighbors` (default 15) | small values emphasise local structure and fragment; large values emphasise global structure and smear |
| Spread | (fixed) | `min_dist` (default 0.1) | how tightly UMAP packs points within a cluster; purely cosmetic, but it changes what the picture *looks* like it says |
| Initialisation | `init="pca"` | `init="spectral"` | PCA init preserves more global structure and is more reproducible than random |
| Optimisation | `learning_rate="auto"`, `n_iter` | `n_epochs` | scikit-learn's `"auto"` learning rate is `max(n/12, 50)`; the old default of 200 produced the well-known "one dense ball" artifact on large datasets |

UMAP is typically much faster than t-SNE on large datasets and provides a `transform` for new points. t-SNE is more established and its failure modes are better documented. Neither preserves what Layer 3 shows they do not preserve.

### Reading an embedding plot honestly

Four rules, each of which you can defend with a measurement from Layer 3:

1. **Local neighbourhood claims are supported.** "These documents are near each other" is a claim about neighbourhoods, which is what the method optimises.
2. **Cluster size claims are not.** t-SNE equalises apparent cluster sizes: a cluster that is 3.95x wider in the data renders at 0.97x.
3. **Inter-cluster distance claims are not.** A cluster 6.63x further away renders at 1.09x, and UMAP can render it *nearer* (0.90x — the order reverses).
4. **"There are N clusters" is not supported by the picture alone.** t-SNE produces convincing separated blobs from pure Gaussian noise.

Two habits that make plots defensible: always show **at least two random seeds** side by side, and always show at least two `perplexity` / `n_neighbors` values. Structure that survives both is worth talking about; structure that does not is an artifact.

### Trade-offs

| Decision | Choose the first when… | Choose the second when… |
| --- | --- | --- |
| **PCA** vs **t-SNE/UMAP** | anything that feeds a model, or where distances and sizes must mean something | you are looking at the data with your eyes, and only that |
| **PCA** vs **TruncatedSVD** | dense input | sparse input (TF-IDF, one-hot) — `PCA` centres, which densifies |
| **`n_components` by variance** vs **by downstream metric** | you want a quick, defensible default | accuracy matters; the variance/accuracy curves have different shapes and the second is the one you care about |
| **t-SNE** vs **UMAP** | you want the better-documented method and `n` is under ~50,000 | `n` is large, or you need `transform` for new points |
| **Reduce then cluster** vs **cluster in full space** | dimension is above ~50, or many columns are one-hot | dimension is small and every feature is meaningful — reduction can destroy the very structure you are looking for |

### War story: the deck with the arrow on it

A product analytics team embedded 40,000 users on 120 behavioural features, ran UMAP, produced a genuinely beautiful plot with seven visible islands, and built a quarterly strategy around it. The headline slide had an arrow between two adjacent islands and a caption: "power users and at-risk trialists are adjacent — a small nudge moves people between them."

Two things were wrong and only one was obvious.

The obvious one: nobody had checked a second seed. Re-running with `random_state=1` put those two islands on opposite sides of the plot. Adjacency in a UMAP layout is not a stable property.

The subtle one: two of the seven islands were the same behavioural group split by a single binary feature, `has_mobile_app`, which had been one-hot encoded into two columns and therefore contributed a constant offset to every distance between the groups. UMAP faithfully rendered a gap that was an encoding artifact.

The measurements that settled it: mean adjusted Rand index between UMAP-derived cluster assignments across 10 seeds was **0.41** — barely more than chance agreement for that number of clusters — and dropping the two one-hot columns merged the two islands entirely.

The team kept the plot as a *hypothesis generator*, which is what it is good for, and moved the strategy onto a K-Means clustering with the stability tests from Module 4 plus a supervised model for the "at-risk" question, which was a labelled problem all along. The general lesson: **a projection is a picture of an algorithm's output, not a picture of your data.** Anything you want to claim from it, verify in the original space.

### Design checkpoint

> You have 10,000 document embeddings at 768 dimensions and want to check whether your retrieval corpus has coherent topics. Design the analysis.

<Accordion title="Model answer">
Start in the original space, not in a plot. First, compute the intrinsic dimensionality: PCA on the 768-D embeddings and look at the explained-variance curve — sentence embeddings typically have far lower effective rank than 768, and the number tells you how much redundancy there is. Second, cluster **in a moderately reduced space** (PCA to 90–95% variance, then K-Means or HDBSCAN) with the stability tests from Module 4, because that is a claim you can defend. Third, *then* make the picture: UMAP coloured by the cluster labels you already computed, at two seeds and two `n_neighbors` values. The plot's job is to communicate the clustering, not to produce it — that ordering is the whole design. Fourth, validate topics by reading: sample 10 documents nearest each cluster centroid **in the original 768-D space**, not from the plot, and write the topic name from those. Finally, state explicitly in the deliverable which claims are supported: "these clusters exist and are stable across seeds" is supported; "topic A is broader than topic B" and "A and B are more related than A and C" are not, unless you computed them in 768-D — in which case report the numbers rather than the picture. This is exactly the workflow Week 27 uses to inspect retrieval quality.
</Accordion>

### The counterexample: constructing data where t-SNE must lie

Build 20-dimensional data with three clusters whose *global* properties are known exactly by construction:

- **A**: 400 points, standard deviation 1.0, centred at the origin
- **B**: 400 points, standard deviation 1.0, centred 6 units away — same size as A, close to it
- **C**: 400 points, standard deviation **4.0**, centred **40 units** away — four times wider, far away

So the ground truth is unambiguous: C's spread is about 4x A's, and C is about 6.6x further from A than B is.

```python
# numpy 2.5.2, scikit-learn 1.9.0, umap-learn 0.5.12
import numpy as np
from sklearn.manifold import TSNE
from sklearn.decomposition import PCA
import umap

rng = np.random.default_rng(0)
A = rng.normal(0, 1.0, size=(400, 20))
B = rng.normal(0, 1.0, size=(400, 20)); B[:, 0] += 6.0
C = rng.normal(0, 4.0, size=(400, 20)); C[:, 0] += 40.0
Z = np.vstack([A, B, C])
lab = np.r_[np.zeros(400), np.ones(400), 2*np.ones(400)].astype(int)

def report(P, name):
    cen = [P[lab == k].mean(0) for k in range(3)]
    spread = [np.sqrt(((P[lab == k] - cen[k]) ** 2).sum(1)).mean() for k in range(3)]
    dAB = np.linalg.norm(cen[0] - cen[1]); dAC = np.linalg.norm(cen[0] - cen[2])
    print(f"{name:<22} spread C/A {spread[2]/spread[0]:5.2f}   d(A,C)/d(A,B) {dAC/dAB:5.2f}")

report(Z, "TRUTH (20-D)")
report(PCA(2).fit_transform(Z), "PCA 2-D")
for p in (5, 30, 100):
    report(TSNE(2, perplexity=p, random_state=0, init="pca").fit_transform(Z), f"t-SNE perplexity={p}")
for nn in (5, 15, 50):
    report(umap.UMAP(n_components=2, n_neighbors=nn, random_state=0).fit_transform(Z), f"UMAP n_neighbors={nn}")
```

| Method | cluster-size ratio C/A | distance ratio d(A,C)/d(A,B) |
| --- | --- | --- |
| **TRUTH (20-D)** | **3.95** | **6.63** |
| PCA 2-D | 4.23 ✓ | 6.64 ✓ |
| t-SNE, perplexity 5 | 1.01 ✗ | 1.22 ✗ |
| t-SNE, perplexity 30 | **0.97** ✗ | **1.09** ✗ |
| t-SNE, perplexity 100 | 0.95 ✗ | 1.86 ✗ |
| UMAP, n_neighbors 5 | 0.97 ✗ | 1.49 ✗ |
| UMAP, n_neighbors 15 | 0.90 ✗ | **0.90** ✗✗ |
| UMAP, n_neighbors 50 | 0.91 ✗ | 2.33 ✗ |

Read the two failure columns.

**Cluster sizes are equalised.** Every t-SNE and UMAP setting renders C at roughly the *same* size as A, when it is genuinely 3.95x wider. If you look at such a plot and say "cluster C is a tight, homogeneous group", you have it exactly backwards.

**Inter-cluster distances are destroyed.** The true ratio is 6.63. t-SNE at the default perplexity renders it as **1.09** — the far cluster appears essentially the same distance away as the near one. And UMAP at its default `n_neighbors=15` renders it as **0.90**, which means it puts the *far* cluster **closer** than the near one. The ordering is reversed.

Note also that changing `perplexity` from 5 to 100 moves the distance ratio from 1.22 to 1.86 without ever approaching 6.63. There is no setting that fixes this, because preserving global distance is not what the algorithm is trying to do.

PCA gets both right (4.23 and 6.64), because a linear projection cannot invent or destroy relative geometry in the directions it keeps.

### How much distance information survives at all

Spearman correlation between all pairwise distances in the 20-D truth and in the embedding:

| Method | Spearman correlation of pairwise distances |
| --- | --- |
| PCA (2 components) | **0.9585** |
| t-SNE, perplexity 30 | 0.6214 |
| UMAP, n_neighbors 15 | **0.4372** |

UMAP retains **less than half** the rank-order information about pairwise distances. This is not a criticism of UMAP; it is a description of its objective, which is to preserve a fuzzy topological representation of local neighbourhoods, explicitly at the cost of global metric structure. But it means that any statement of the form "these two things are closer than those two things", read off a UMAP plot, is at about the confidence level of a coin flip weighted 0.44.

### t-SNE on pure noise

The harder failure, because it produces a picture that looks like a finding.

```python
N = rng.normal(size=(900, 50))            # PURE isotropic Gaussian noise. No clusters.
E = TSNE(2, perplexity=30, random_state=0, init="pca").fit_transform(N)

from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score
print("silhouette of k=3 on the t-SNE map :", silhouette_score(E, KMeans(3, n_init=10, random_state=0).fit_predict(E)))
print("silhouette of k=3 on the raw 50-D  :", silhouette_score(N, KMeans(3, n_init=10, random_state=0).fit_predict(N)))
```

```
silhouette of k=3 on the t-SNE map : 0.3461
silhouette of k=3 on the raw 50-D  : 0.0168
```

**A 20.6x increase in apparent cluster structure, from data that contains none.** The mechanism: t-SNE's objective pushes dissimilar points apart with a heavy-tailed (Student-t) kernel in the low-dimensional space, and in a 900-point cloud there are always *some* points that happen to be slightly nearer each other. The optimisation amplifies those chance neighbourhoods into visible separation, because it has 2 dimensions to arrange 900 points in and no way to represent "everything is equally far from everything".

This is why "there are five clusters, you can see them" is never a conclusion. Wattenberg, Viégas and Johnson's *Distill* article ("How to Use t-SNE Effectively", 2016) shows the same effect interactively and is the single best thing to send a colleague who has over-read a plot.

### What the algorithms actually optimise

**t-SNE** (van der Maaten & Hinton, 2008) converts distances into probabilities. In the high-dimensional space, `p_{j|i}` is a Gaussian centred on point `i` whose bandwidth is tuned per point so that the distribution has a fixed **perplexity** — an effective number of neighbours. In the low-dimensional space, `q_{ij}` uses a Student-t distribution with one degree of freedom. Then it minimises the Kullback-Leibler divergence `KL(P || Q)` by gradient descent.

Two consequences follow directly from that definition and explain the whole table above:

- **The per-point bandwidth is why cluster sizes are equalised.** A point in the diffuse cluster C gets a *wide* Gaussian so that it still has `perplexity` effective neighbours; a point in the tight cluster A gets a narrow one. After that normalisation, both clusters look identically dense to the objective.
- **`KL(P || Q)` is asymmetric, and that asymmetry is deliberate.** A large `p_ij` (near in the data) paired with a small `q_ij` (far in the map) is heavily penalised; the reverse is barely penalised at all. So the objective *insists* on keeping near things near and is nearly indifferent to whether far things stay far. Global distance is not approximately preserved — it is explicitly not in the loss.

**UMAP** (McInnes, Healy & Melville, 2018) builds a weighted k-nearest-neighbour graph, symmetrises it into a fuzzy simplicial set, and optimises a low-dimensional graph to have a similar fuzzy topology via a cross-entropy objective. Its theoretical framing (Riemannian geometry and algebraic topology, assuming the data is uniformly distributed on a manifold) sounds more global than t-SNE's, and it does tend to preserve *somewhat* more global structure in practice — but "somewhat more" is 0.4372 versus 0.6214 Spearman here, which happens to be *worse* on this construction. Do not treat UMAP as the global-structure-preserving alternative. It is not.

### Inspecting 10,000 text embeddings without being fooled

This is the Week 27 workflow, stated here because the machinery is this module's.

| The misreading | The correct check, in the original space |
| --- | --- |
| "This topic cluster is broad and diffuse" | mean pairwise cosine distance within the cluster, compared against other clusters |
| "These two topics are closely related" | cosine similarity between the two cluster centroids |
| "There are 8 topics" | cluster in the embedding space with stability tests across seeds; the plot only *displays* the labels |
| "This outlier is far from everything" | its distance to its k-th nearest neighbour in the original space, versus the distribution of that statistic |
| "Retrieval is failing for this region" | actual recall@k on labelled queries from that region — the ranking metrics in Week 19 Module 2 |

The rule that makes it all work: **compute the claim in the original space; use the projection only to show it.** Colour the projection by a quantity you computed in 768 dimensions, and every arrow you draw on the slide is then defensible.

### Failure modes

| Failure | Signature | Detector |
| --- | --- | --- |
| Conclusions from cluster size in a t-SNE plot | "cluster A is more homogeneous" | measure mean intra-cluster distance in the original space |
| Conclusions from inter-cluster distance | an arrow between two adjacent blobs | measure centroid distance in the original space; check a second seed |
| Clusters found in a projection of noise | convincing blobs, no downstream signal | silhouette in the original space; a projection of a shuffled label version as a control |
| Unstable layout | islands move between seeds | run 2+ seeds; report ARI between projection-derived clusterings |
| PCA on unscaled mixed-unit data | one component explains 95%+ | check `explained_variance_ratio_[0]`; add `StandardScaler` |
| `PCA` on sparse input | `TypeError`, or a memory explosion after densifying | `TruncatedSVD` |
| Reducer fitted on all data | small consistent optimism in CV | put it in a `Pipeline` |
| One-hot columns dominating the projection | an apparent split that maps exactly onto one binary feature | cross-tab projection-derived clusters against each binary feature |

### Papers

- **van der Maaten, L. & Hinton, G. (2008), "Visualizing Data using t-SNE," JMLR 9.** *Takeaway:* the per-point Gaussian bandwidth tuned to a fixed perplexity, plus an asymmetric KL objective, is precisely why cluster sizes are equalised and global distances are not preserved — the failures are the design.
- **Wattenberg, M., Viégas, F., Johnson, I. (2016), "How to Use t-SNE Effectively," Distill.** *Takeaway:* an interactive demonstration that cluster sizes mean nothing, inter-cluster distances mean nothing, and random noise produces convincing clusters — send this to anyone who over-reads a plot.
- **McInnes, L., Healy, J., Melville, J. (2018), "UMAP: Uniform Manifold Approximation and Projection for Dimension Reduction," arXiv:1802.03426.** *Takeaway:* a fuzzy-topological construction that is much faster than t-SNE and supports transforming new points, but that also does not guarantee global distance preservation — measured here at Spearman 0.4372.
- **Chari, T. & Pachter, L. (2023), "The specious art of single-cell genomics," PLOS Computational Biology 19(8).** *Takeaway:* across single-cell datasets, 2-D embeddings distort local and global structure enough that published biological conclusions drawn from them are frequently unsupported — the clearest documented case of a whole field over-reading these plots.
- **Kobak, D. & Berens, P. (2019), "The art of using t-SNE for single-cell transcriptomics," Nature Communications 10.** *Takeaway:* PCA initialisation, a larger learning rate and exaggeration schedules substantially improve how much global structure t-SNE retains — the practical counterweight, and the reason `init="pca"` matters.
- **Eckart, C. & Young, G. (1936), "The approximation of one matrix by another of lower rank," Psychometrika 1.** *Takeaway:* the truncated SVD is the optimal low-rank approximation in the Frobenius norm, which is the theorem that makes PCA the *right* linear reduction rather than merely a popular one.

### Stretch challenge

Quantify how much of a projection's structure is real, using a **label-shuffle control**. Take a labelled dataset. Compute an embedding (t-SNE and UMAP, two seeds each). Then compute a "trustworthiness" curve — scikit-learn has `sklearn.manifold.trustworthiness` — as a function of neighbourhood size `k` from 5 to 500, for both methods and for PCA.

Then the control: shuffle the *data* (permute each column independently, destroying all inter-feature structure while preserving each marginal), re-embed, and compute the same curves. The gap between the real and shuffled curves at each `k` is how much structure the projection is genuinely showing at that scale.

The open question, and the deliverable: **at what neighbourhood size does the real curve become indistinguishable from the shuffled one?** That value is the honest upper bound on the scale at which your plot means anything, and it will be much smaller than the plot's apparent scale. Report it, and then argue whether any conclusion in your team's most recent embedding plot was drawn at a scale below it.

## The whole idea on one whiteboard

Two families of method with different jobs. **PCA** finds new axes — linear combinations of your features — ordered by how much of the data's variance each captures, and keeps the first few. It is a *transformation*: reversible, applicable to new rows, and it preserves global geometry, so distances and relative sizes in the projection are meaningful. **t-SNE and UMAP** find a low-dimensional arrangement in which each point's *near neighbours* are still near, and they explicitly sacrifice everything else — cluster sizes, distances between clusters, the density of a region — to do it. PCA is an engineering tool you put in a pipeline. t-SNE is a viewing tool you put in a notebook, and the only claims it supports are about local neighbourhoods.

## Common mistakes

| Symptom | Cause | Fix |
| --- | --- | --- |
| First component explains 98% of variance | unscaled mixed-unit features | `StandardScaler` before `PCA`, always |
| "Cluster A is broader than B" from a t-SNE plot | t-SNE equalises apparent cluster sizes | measure mean intra-cluster distance in the original space |
| "A and B are more similar than A and C" from a plot | inter-cluster distances are not preserved; UMAP can reverse the order | measure centroid distances in the original space |
| Clusters found in a projection of noise | the projection manufactures apparent separation | silhouette in the original space; run a shuffled-data control |
| Plot changes completely between runs | t-SNE and UMAP are stochastic | always show two seeds; report ARI between seed-derived clusterings |
| `TypeError` from `PCA` on a sparse matrix | `PCA` centres, which densifies | `TruncatedSVD` |
| t-SNE output used as model features | it has no `transform` and no stable geometry | `PCA`, an autoencoder, or an embedding model |
| CV score slightly optimistic | reducer fitted outside the folds | put it in a `Pipeline` |
