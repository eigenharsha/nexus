## Outcome

<Note>By Sunday your Week-22 blood-cell model is a live HTTP endpoint: validated input, health
checks, a load-tested throughput number, a multi-stage Docker image under 600 MB, a CI pipeline
that refuses to deploy a model whose accuracy regressed, and a cost-per-prediction figure you
can defend.</Note>

## Where this week sits

Weeks 17–22 produced models. This week is the first one where **the deliverable is a running
system**, and the skills stop being ML-specific: a Dockerfile, a CI pipeline and a cost model
work the same whether the thing inside is a classifier or a Transformer.

That transferability is the point. Week 24 puts this service on Kubernetes; Week 32 puts an LLM
agent behind the identical scaffolding. **Build it properly once.**

## Where this week's numbers come from, and versions

Each figure carries its class — see [About the numbers](/start/about-the-numbers).

| Label | Machine | Class |
| --- | --- | --- |
| **Machine B** | Ubuntu 22.04, Ryzen 9 7950X, 64 GB, RTX 4090, CUDA 12.4 — training and image builds | **Reference figure** — modelled, not run by the authors |
| **Machine C** | AWS `c7i.xlarge` — 4 vCPU Sapphire Rapids, 8 GB, Ubuntu 22.04 — serving figures | **Reference figure** — modelled from vendor specs and published benchmarks |
| **Lambda** | AWS Lambda, x86_64, container image, 2,048 MB memory, `eu-west-1` | **Reference figure** — modelled pricing and cold-start behaviour |
| **Local Docker** | Image builds and layer sizes on a laptop-class machine | **Measured** — image bytes do not depend on the host, so you should reproduce these exactly |
| **GitHub Actions** | `ubuntu-24.04` runners, pipeline durations in Module 4 | **Reference figure** — modelled; no CI has run for this course |

The Lambda-versus-container cost crossover in Module 5 is **derived**: it is arithmetic over
published per-request and per-hour prices, shown term by term, and it is the number in this week
you should trust most. Latency figures on Machine C are modelled — measure your own before you
size anything.

Pinned throughout: **Docker 24.0.7** (BuildKit enabled), `python:3.12.6-slim-bookworm`,
`fastapi==0.115.0`, `uvicorn[standard]==0.30.6`, `pydantic==2.9.2`, `onnxruntime==1.19.2`,
`uv==0.4.18`, `pytest==8.3.3`, `ruff==0.6.8`, `mypy==1.11.2`, `locust==2.31.6`,
GitHub Actions `ubuntu-24.04` runners.

<Warning>
**Cost discipline.** Everything in this week fits inside the AWS free tier if you follow the
teardown steps: Lambda's free tier is 1M requests and 400,000 GB-seconds per month, and the
labs use far less. The one thing that will cost you money is leaving an ECR repository or a
NAT gateway running. Module 5 has the teardown checklist. Run it.
</Warning>

## Exit checks

<AccordionGroup>
  <Accordion title="Can you do these six things by Sunday?" icon="circle-check">
    1. Take a notebook and produce `train.py` + `predict.py` + a versioned artifact, with one shared preprocessing module.
    2. Explain what `pickle.load` can do to your machine, and name two safer formats.
    3. Produce an RPS-versus-p99 curve for a service, find the bottleneck, fix it, and re-measure.
    4. Cut an ML image from over 3 GB to under 600 MB and state what each change saved.
    5. Write a CI pipeline that fails the build when model accuracy regresses more than 1%.
    6. Compute the monthly cost of a service at 10, 1,000 and 100,000 requests per day for both serverless and an always-on container, and state the crossover.
