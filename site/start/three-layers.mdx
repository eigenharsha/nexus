Most courses pick an audience and lose everyone else. A beginner course bores an experienced
engineer by week three. An advanced course loses a student in the first hour and never gets
them back. Nexus refuses that trade by writing **the same topic three times, at three depths.**

<CardGroup cols={3}>
  <Card title="🟢 Ground" icon="seedling">
    **Beginner.** Assumes nothing. Every term defined where it first appears.
  </Card>
  <Card title="🔵 Build" icon="hammer">
    **Practitioner.** Real tools, real versions, real trade-offs.
  </Card>
  <Card title="🟣 Edge" icon="microscope">
    **Expert.** Internals, scale, cost, and the failure modes you only meet in production.
  </Card>
</CardGroup>

## Layer 1 — Ground

Written for someone who has never seen the idea before. One physical analogy, the smallest
example that runs in under a minute, a line-by-line walkthrough, and guided practice where most
of the code is already written for you.

**You've finished Layer 1 when** you can explain the idea to a friend without looking at notes.

## Layer 2 — Build

Written for someone who ships software and needs this to work on Monday. The proper theory, the
library surface the industry actually uses, a trade-offs table (*choose X when… choose Y when…*),
a complete tested reference implementation, and one true story about how it breaks.

**You've finished Layer 2 when** you can implement it at work without opening the docs for the happy path.

## Layer 3 — Edge

Written for someone who has shipped Layer 2 and been burned by it. What the library actually
does under the hood. What happens at 100× the load. The cost, latency and memory arithmetic.
The failure modes that never appear in a tutorial. And a stretch challenge with no single right answer.

**You've finished Layer 3 when** you can review someone else's design and find the flaw in it.

<Warning>
Layer 3 is **more depth on the same topic**, never a new topic in harder words. If a Layer 3
section introduces something the earlier layers never touched, that's a bug — [report it](/start/faq).
</Warning>

## How to actually use them

<Tabs>
  <Tab title="If you're new">
    Read Ground fully. Attempt Build — expect it to be uncomfortable, that's the point. Skim Edge
    to know what exists, and come back to it after the lab. Do the `basic` lab track, then push
    yourself into `standard`.
  </Tab>
  <Tab title="If you're working">
    Skim Ground in 60 seconds to check the vocabulary matches yours. Live in Build. Read Edge
    properly — it's where the seniority is. Start the lab at `standard`; `hard` is where your
    next interview story comes from.
  </Tab>
  <Tab title="If you're revising">
    Read only the Layer 3 numbers and the "common mistakes" table, then redraw the module's
    diagram from memory. Fifteen minutes per module.
  </Tab>
</Tabs>
