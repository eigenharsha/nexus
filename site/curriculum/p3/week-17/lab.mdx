You are given `starter/basic/` containing the data loader, the plotting code, the test file and this skeleton:

```python
import numpy as np

def fit_gd(x: np.ndarray, y: np.ndarray, lr: float = 1e-3,
           n_iter: int = 2000) -> tuple[float, float, list[float]]:
    """Fit y ~ w*x + b by batch gradient descent.

    Returns (w, b, loss_history).
    """
    w, b = 0.0, 0.0
    history: list[float] = []
    for _ in range(n_iter):
        yhat = w * x + b
        err = yhat - y
        history.append(float(np.mean(err ** 2)))
        # TODO 1: compute dw = dL/dw for mean squared error
        # TODO 2: compute db = dL/db
        # TODO 3: update w and b using lr
    return w, b, history
```

4. Plot `history` on a log-y axis. Mark the iteration where the loss stops improving by more than 1% per 100 steps.

### Acceptance criteria

| # | Criterion | How it is checked |
| --- | --- | --- |
| A1 | Gradient correctness | `gradient_check` relative error &lt; `1e-8` at `eps=1e-6`, central difference, on all three losses |
| A2 | Agreement with scikit-learn | on `california`, `breast_cancer`, `digits`: metric difference &lt; `1e-4`; **objective** difference &lt; `1e-6` |
| A3 | No `log(p)` anywhere | `grep -n "np.log(" scratchml/logistic.py` returns nothing; use `np.logaddexp` |
| A4 | Solvers agree | `solver="normal"` and `solver="gd"` land within `1e-6` in objective on standardised inputs |
| A5 | Convergence is reported | `n_iter_` is set; the fit raises if it hit `n_iter` without meeting `tol` |
| A6 | Divergence is loud | a learning rate that overflows raises `FloatingPointError` naming the iteration, not `nan` coefficients |
| A7 | Clone-safe | `type(est)(**est.get_params())` produces an estimator that fits to the same coefficients |

<Warning>
A2 says **objective**, not coefficients. Module 3's Layer 3 explains why: on `breast_cancer` several features correlate above 0.99, so the objective is flat along the directions that trade them and coefficients can legitimately differ by `2.6e-3` while the objective agrees to `4.9e-08`. If your test asserts on coefficients it will fail for the wrong reason.
</Warning>

### The two things that will cost you an hour each

1. **The regularization convention.** scikit-learn minimises `C * sum_i loss_i + 0.5 ||w||^2`. If your objective is `mean_i loss_i + (alpha/2) ||w||^2`, then `alpha = 1/(n*C)`. Write this in a comment at the top of `logistic.py` before you start.
2. **The intercept is not penalised.** Append the ones column, then exclude index 0 from the penalty in both the objective and the gradient. Getting this wrong shows up only at large `alpha`, so your first tests will pass.

Time box: **6 hours.**

**Softmax multiclass, early stopping, a learning-curve diagnostic, and 1M rows inside a memory budget.**

Everything from `standard`, plus:

| # | Criterion | Budget |
| --- | --- | --- |
| H1 | Softmax multiclass with stable log-sum-exp | must not overflow when a logit reaches 800 |
| H2 | Early stopping | `validation_fraction`, `n_iter_no_change`, `best_iter_`; restores the best parameters, not the last |
| H3 | Learning-curve tool | `learning_curve(est, X, y, sizes, cv)` returning train and validation scores, and a `diagnose()` that returns one of `"high_bias"`, `"high_variance"`, `"at_floor"` with the numeric justification |
| H4 | **1,000,000 rows x 100 float32 features** | peak RSS &lt; **1.5 GB**, wall clock &lt; **60 s**, final objective within `1e-4` of the full-batch optimum |
| H5 | No full copy of `X` | assert that `fit` never materialises an array larger than the input |

H4 is the constraint the `standard` solution fails. A `standard` implementation that calls `np.c_[np.ones(n), X]` allocates a **new** `n x (p+1)` array — for 1M x 100 in float64 that is 808 MB on top of the 400 MB input, and the design-matrix copy alone breaks the budget. You need one of: an explicit intercept term carried outside the matrix, in-place batch slicing, or `np.float32` end to end with a documented precision analysis.

<Warning>
Measure peak RSS with `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss`, not with a profiler's estimate. On macOS the value is in bytes; on Linux it is in kilobytes. Handle both — the graders run Linux.
</Warning>

For reference, the numbers the module pages measured on 10M x 10 float32 (M3 Pro, 18 GB): normal equation **0.65 s**, SGD to the same optimum in **0.03 s**, peak RSS **0.56 GB** for 400 MB of data. Your 1M x 100 case is a different shape; do not assume the ratios transfer.

Time box: **8 hours.**

The write-up is not optional and it is not a README stub. It must contain, in order:

1. The MSE gradient derived in scalar and matrix form, with the chain-rule step shown.
2. The cross-entropy gradient derived from maximum likelihood, including the `p(1-p)` cancellation.
3. Your gradient-check plot: relative error against `eps` on log-log axes, showing the U.
4. Your crossover plot: exact solve vs SGD wall clock against `p`, annotated with the `8*p^2` memory number.
5. One paragraph on where your numbers disagree with scikit-learn and why. "They matched" is not an acceptable answer to this section — find the disagreement, it is there.

Then: tag `v1.0.0`, push, and put the link on your CV. Hiring managers read repositories with derivations in them.

## Common ways this lab goes wrong

| Symptom | Cause | Fix |
| --- | --- | --- |
| Tests pass on `california`, fail on `breast_cancer` | asserting on coefficients, not objective | assert on objective and predictions (see A2's warning) |
| Objective disagrees by a constant factor | `C` vs `lambda` convention | `alpha = 1/(n*C)` |
| Disagreement grows with `alpha` | intercept is being penalised | exclude index 0 from the penalty in both objective and gradient |
| Gradient check fails at `1e-8` relative | forward difference, or `eps` too small | central difference at `eps=1e-6`; see the U-curve in M3 |
| `nan` coefficients on `digits` | naive `exp` in softmax | subtract the row max before exponentiating |
| H4 fails on memory but not on time | the ones column is being materialised | carry the intercept separately |
| `make verify` green locally, red in CI | `ru_maxrss` units differ between macOS and Linux | branch on `sys.platform` |
