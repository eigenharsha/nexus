## The ticket

> **NEX-1904 — We cannot tell which of our models are real**
> **Reporter:** Sam, Head of Data
> **Priority:** P1
>
> We have shipped four models in eighteen months. Two performed roughly as advertised. One
> was 0.94 offline and 0.71 in production and we never established why. One was quietly
> switched off by the team it was built for and nobody noticed for five weeks.
>
> Every one of those was reported as a single number in a slide. I want a harness that every
> model goes through before review, that produces the same report every time, and that fails
> loudly when the number is not trustworthy.
>
> Non-negotiable: it must catch the 0.94-that-was-really-0.71 case. I do not want to be told
> "be careful about leakage" again.

The ticket is asking for **evidence generation**, not for a metric function. That distinction is what separates the three tracks.

<Info>
**The ticket is a scenario; the reference numbers are not.** The company, the people and the
business figures in the ticket above are invented to give the work a shape. Every **reference
number** quoted in the tracks below — scores, costs, timings — was produced by actually running
the pipeline on an Apple M3 Pro (11 cores, 18 GB, macOS arm64, no GPU) with Python 3.12.9 and the

### Acceptance criteria

| # | Criterion | How it is checked |
| --- | --- | --- |
| A1 | Metric suite | classification, regression, ranking and probabilistic metrics matching scikit-learn to `1e-10` where an equivalent exists |
| A2 | Ranking metrics | `recall_at_k`, `precision_at_k`, `mrr`, `ndcg_at_k` with **both** gain conventions; NDCG must equal `sklearn.metrics.ndcg_score` exactly under linear gain |
| A3 | Bootstrap CIs | `bootstrap_ci` and `paired_bootstrap`; the paired interval must be measurably narrower than the unpaired one on the same data |
| A4 | CV strategy selector | `select_cv(df, target, group_col=None, time_col=None)` returns the correct splitter and **raises** if a time column is present and no time-aware splitter was requested |
| A5 | Leakage audit | the five automatable checks from Module 4 Layer 3, returning a structured report |
| A6 | Slice analysis | `slice_report` sorted worst-first, with `n`, row share, weight share, metric and 95% interval; `min_rows` enforced |
| A7 | Calibration | reliability curve with quantile bins, an ECE-style summary, and Platt/isotonic wrappers using `FrozenEstimator` |
| A8 | Threshold optimiser | both modes — cost matrix (`c_fp`, `c_fn`) and capacity (`top_k`) — returning theoretical and empirical thresholds and the realised cost of each |
| A9 | HTML report | one self-contained file, no external assets, generated by `python -m evalkit.report` |
| A10 | Validated on 3 datasets | the harness runs end to end on all three clean datasets with no manual intervention |

### The two design decisions that make it reusable

**1. `select_cv` should refuse, not guess.** The whole point of the ticket is a harness that fails loudly. If the dataframe has a datetime column and the caller asked for `KFold`, raise with a message naming the column. A harness that silently does the reasonable thing does not prevent the 0.94-to-0.71 case.

```python
def select_cv(df, target, group_col=None, time_col=None, n_splits=5, allow_random=False):
    if time_col is not None and not allow_random:
        return TimeSeriesSplit(n_splits=n_splits, gap=infer_gap(df, target))
    if time_col is not None:
        raise ValueError(f"'{time_col}' looks like a timestamp; a random split will "
                         f"inflate the estimate. Pass allow_random=True to override.")
    if group_col is not None:
        return StratifiedGroupKFold(n_splits) if is_classification else GroupKFold(n_splits)
    return StratifiedKFold(n_splits, shuffle=True, random_state=0)
```

**2. Every metric returns a point estimate and an interval, or it returns neither.** Make the interval the default return type. A harness that makes it easy to print a bare number will be used to print bare numbers.

  <Tab title="hard">

**Nested CV, adversarial validation, automated leakage detection, under a runtime budget.**

| # | Criterion | Budget |
| --- | --- | --- |
| H1 | **Catches all five planted leaks** | detection rate 5/5 |
| H2 | **Zero false positives on 20 clean datasets** | this is the hard half |
| H3 | Nested CV | `nested_score()` returning the honest estimate and the measured optimism against the non-nested number |
| H4 | Adversarial validation | AUC, a permutation-importance ranking of shifting features, **and** a same-distribution control run |
| H5 | **Full harness under 180 seconds** | on the largest provided dataset (200,000 x 40), single machine, `time.perf_counter` |

**H2 is the criterion that makes this hard, and it is the one that matters.** A detector that flags a quarter of clean runs gets switched off inside a month, which makes it worse than no detector — you have spent the effort and gained a false sense of coverage.

Concretely, each check needs a threshold tuned against a null distribution rather than guessed:

- **Shuffled-label test.** Chance is not always 0.5 — for accuracy it is the majority-class rate. Run it `n_repeats` times and compare the mean against chance using the *observed* spread, not a fixed tolerance.
- **Near-duplicate detection.** "Distance below 0.01" is meaningless without knowing the data's scale. Compute the nearest-neighbour distance distribution *within* the training set and flag cross-split pairs below its 1st percentile.
- **Single-feature dominance.** Some datasets genuinely have one dominant feature. Flag on the *ratio* to the sum of the others, with a threshold calibrated on your clean datasets — and report it as a warning, not an error.

H5 forces the engineering: 2,000 bootstrap resamples per slice across 30 slices is 60,000 metric evaluations, and a naive implementation will not finish. Vectorise the resampling (draw all indices at once), compute AUC via the rank-based formula rather than by sorting per resample, and subsample slices above a size threshold.

<Warning>
Report your **false-positive rate per check**, not just for the suite. One noisy check with a 20% false-positive rate is what gets the whole harness disabled, and the aggregate number hides it.
</Warning>

Time box: **10 hours.**

## Rubric

| Dimension | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| Correctness | fails tests | metrics match sklearn | all five leaks detected | five detected **and** zero false positives on 20 clean datasets, with the per-check rate reported |
| Code quality | works | readable | `mypy --strict` clean, tested, importable | someone else adds a metric without reading the whole package; intervals are the default return type |
| Performance | untested | measured | meets the 180 s budget | beats it with a breakdown of where the time went and what was vectorised |

## Common ways this lab goes wrong

| Symptom | Cause | Fix |
| --- | --- | --- |
| Leakage audit flags half the clean datasets | thresholds guessed rather than calibrated | tune each threshold against a null distribution; report the per-check false-positive rate |
| Shuffled-label test passes on the selection leak | the shuffle happened after the leaky step | the test must wrap the **entire** pipeline, including selection |
| Near-duplicate check finds nothing, or everything | an absolute distance threshold | use the within-training nearest-neighbour distribution's 1st percentile |
| NDCG disagrees with `sklearn.metrics.ndcg_score` | exponential versus linear gain | implement both; the linear one must match exactly |
| Paired bootstrap no narrower than unpaired | different resample indices for the two models | draw the indices once and use them for both |
| Slice report full of 8-row slices | `min_rows` not enforced | enforce it, and print the interval next to every slice metric |
| H5 times out | per-resample sorting inside a Python loop | vectorise the index draw; use the rank-based AUC formula |
| `select_cv` silently returns `KFold` | it guessed instead of refusing | raise on a datetime column unless explicitly overridden — this is the ticket's actual requirement |
