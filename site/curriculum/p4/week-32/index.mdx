## Outcome

<Note>
By Sunday you can see what your system did, say what it cost to the cent, operate it under a
provider outage and a rate limit, detect a degradation nobody deployed, and hand someone a one-page
picture of the whole thing with real numbers on it.
</Note>

This is the last week. Nothing in it is conceptually new if you have run services before — spans,
SLOs, error budgets, canaries. Three things are different, and they are the week:

- **Latency is perceptual.** Streaming changes time-to-first-token from 4.00 s to 0.90 s and total time not at all.
- **Failures are silent.** The system returns a confident wrong answer with a 200. Your only detector is a quality metric you built.
- **The dependency changes underneath you.** A provider's model update is a deploy you did not do. A scheduled eval is the only thing that tells you.

And one unit of measure runs through all five modules: **cost per successful task, never cost per
call.** A cheaper model that fails twice as often is more expensive.

## The scope of the numbers

Weeks 29–31 measured the incident assistant on its own — roughly 75 runs a day. Week 32 operates the
whole **platform**: the incident assistant plus the support assistant, **4,200 runs a day combined**.
Where a number in this week depends on volume — trace storage, rate limits, the self-hosting
crossover, the TCO — it is at platform scale, and it is labelled as such.

## The pinned stack

Written and tested against these exact versions on 2026-08-30. Weeks 29–31's stack still applies.

```
opentelemetry-api                1.29.0
opentelemetry-sdk                1.29.0
opentelemetry-exporter-otlp      1.29.0
opentelemetry-semantic-conventions 0.50b0
otel/opentelemetry-collector     0.115.0
langfuse                         2.57.0
langfuse/langfuse (image)        2.57.0
redis                            7.4        # semantic cache + rate-limit buckets
argo-rollouts                    1.7        # or Flagger, or a script — the gate is the point
prometheus                       2.55
```

Prices used throughout, from the provider's published rates: `claude-opus-5` $5 / $25 per million
input / output tokens; `claude-sonnet-5` $2 / $10; `claude-haiku-4-5` $1 / $5. Cache reads bill at
about 0.1× and cache writes at about 1.25×, in **separate usage fields** — a cost function that
misses them under-reports a cached workload by 40–80%.

Total API spend for a learner completing every module and the `standard` lab: **about $7**, measured.
The cost-reduction experiment is most of it, and it pays for itself in the write-up.

## Numbers to carry out of this week

| Number | Where it came from |
| --- | --- |
| Tracing overhead **0.4 ms per span, 0.18% per run** | M1 — there is no cost argument against instrumenting |
| Tail sampling: **8.1% of traces, 100% of errors** | M1 — against head sampling's 10% of both |
| `user_id` as a metric label: **39.6 M series, ~$7,920/month** | M1 — high cardinality on spans, never on metrics |
| Prompt rollback **42 s** versus 14 min by deploy | M2 — why prompts are labelled objects, not source strings |
| Failure to eval case: **9 days → 4 minutes** | M2 — and the missing piece was a recurring half-hour, not a tool |
| Offline/online gap **13 → 4 points** over 8 weeks | M2 — the metric that says the flywheel is working |
| Cost per successful task **$0.253 → $0.098 (−61%)** | M3 — with no regression on the 120-case suite |
| All-cheap config: **$0.058/run but $0.107 per success** | M3 — the cheapest per call is the most expensive per outcome |
| Verify-and-retry: **+$0.008/run, +10.3 points of success** | M3 — the lever a per-call optimizer would delete |
| TTFT **0.90 s streamed vs 4.00 s buffered**, same total | M4 — latency is perceptual |
| Blind 429 retries vs admission control: **8.1% → 0.2%**, p99 **210 s → 94 s** | M4 — back-pressure is faster *and* cheaper |
| Same input, 20 replays: **14 distinct outputs, 3 reproduce the bug** | M4 — you cannot debug by re-running |
| Silent model change detected in **11 h** instead of 9 days | M4 — six-hourly evals against production config |
| **3 of 14 rollouts** stopped by an eval gate | M5 — the return on all of Week 31 |
| TCO **$14,872/month: 71% API, 21% people** | M5 — and the 21% is the line nobody budgets |

## Also this week

- **Flashcard deck:** the GenAI attribute set, cardinality rules, tail-sampling policies, the cost waterfall, cost per successful task, TTFT versus total, the error-budget policy, the three kinds of drift, the deployable unit.
- **Explain it in 5 minutes:** the capstone poster presentation. What problem, what it decides, one number proving it works, one number proving you can afford it, and what breaks first.
- **Peer review:** exchange posters. Ask of every component: what number is on it, and where did that number come from? A component with no number is one nobody measured, and finding those in someone else's poster is the fastest way to find them in your own.
