## Outcome

<Note>
By Sunday you can look at an unfamiliar problem and decide, in under two minutes, whether it is a
tree, a graph, or a dynamic-programming problem — and then apply the right template. You will have
built a trie, a heap, a topological sort with cycle detection, a Dijkstra route planner and an
edit-distance diff, and you will have measured every one of them.
</Note>

## Why this week decides how the rest of the course feels

Week 13's structures were linear: one thing after another. Week 14's are *branching*, and
branching is where the systems you build later actually live.

| What you build later | What it actually is | Week |
| --- | --- | --- |
| A database index page walk | a B-Tree — a BST that gave up on being a BST to fit disk pages | 8, and here |
| Autocomplete over a token vocabulary | a trie, or the sorted array that beats it | 25 |
| HNSW's candidate queue during graph descent | a bounded min-heap — the same one as week 13 module 5 | 27 |
| Validating an agent's step graph before running it | topological sort with cycle detection | 30 |
| Deadlock detection across tool calls | cycle detection in a directed graph | 30 |
| Beam search over token sequences | best-first search with a bounded frontier — A* without an admissible heuristic | 25 |
| Fuzzy matching a retrieved chunk against a claim | edit distance with backtracking | 27, 28 |
| A build system deciding what to rebuild | topological sort over a dependency DAG | 24 |

Every row of that table is a thing you will implement in this course. **This is the week where you
learn the shape once, so that later you recognise it instead of re-deriving it.**

## The measurement environment

| | |
| --- | --- |
| Machine | Apple M3 Pro, 18 GB unified memory, macOS 15 |
| Python | CPython 3.12.9 (Homebrew) |
| Timing | `time.perf_counter`, best-of-3 or best-of-5, `gc.collect()` between reps |
| Memory | recursive `sys.getsizeof` walk for structure size; `ru_maxrss` for whole-process figures |

<Warning>
Two of this week's headline numbers are *negative* results — the trie loses to a sorted array, and
plain A* only beats Dijkstra by 1.49× rather than the 3× the textbook implies. Both are real, both
are reproduced across runs, and both are more instructive than the results that came out the way
the textbook predicted. When your own measurements disagree with a lesson, the measurement is
usually right and the lesson is usually missing a constraint.
</Warning>

## Exit checks

1. Traverse a tree four ways (pre/in/post-order and level-order) on paper, and write the iterative
   version of each without looking.
2. Explain why a B-Tree node holds hundreds of keys while a BST node holds one, in terms of the
   4 KB disk page — and connect it to what you measured in week 8.
3. Detect a cycle in a directed graph and *print the cycle path*, not just report that one exists.
4. Run Dijkstra by hand on a 6-node weighted graph, and state exactly why it breaks with a negative
   edge.
5. Write edit distance from scratch, then reduce its space from O(nm) to O(min(n,m)) and say what
   you lost by doing so.
