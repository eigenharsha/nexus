## What scikit-learn is

A library of ready-made models and data-preparation steps, all sharing one small interface. That
shared interface is the entire point: once you know it for one thing, you know it for everything.

```bash
uv pip install scikit-learn      # already installed if you ran ./bootstrap.sh
```

## Idea 1 — fit and transform

Every object in scikit-learn does one of two jobs.

A **transformer** changes data. A **model** (they call it an *estimator*) makes predictions. Both
learn what they need from data first, in a step called `fit`.

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
scaler.fit(train_data)              # LEARN: work out each column's mean and spread
clean = scaler.transform(train_data)  # APPLY: subtract the mean, divide by the spread
```

Two separate steps, and the separation is the whole lesson of Week 16.

`fit` **learns something and remembers it**. `transform` **applies what was remembered**. If you
`fit` on data you were not supposed to look at, that knowledge leaks into your results and your
score becomes a lie. That is the entire subject of Module 3, and now you can read its code.

Models use `fit` then `predict` instead of `transform`, but the shape is identical:

```python
model.fit(X_train, y_train)     # learn the pattern
model.predict(X_test)           # apply it to data it has never seen
```

<Tip>
**`X` and `y` are a convention you will see everywhere.** `X` is the input — a table, one row per
example, one column per feature. Capital, because it is a matrix. `y` is the answer for each row —
one value per example. Lowercase, because it is a single column.
</Tip>

## Idea 2 — the train/test split

You cannot judge a model on the data it learned from, for the same reason you cannot judge a
student on questions they were given in advance.

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, random_state=0)
```

That splits off 20% of the rows and hides them. You train on the other 80%, then check yourself
against the hidden part **once**. `random_state=0` fixes the shuffle so you get the same split every
run — the reproducibility idea from Week 11's primer, again.

The rule Module 3 exists to teach: **anything you `fit`, you fit on the training half only.**
Fit a scaler on all the data and you have already lost, because the test rows influenced the mean.

## Idea 3 — Pipeline and ColumnTransformer

If the rule is "only ever fit on the training half", the reliable way to obey it is to stop relying
on remembering.

A **`Pipeline`** chains steps into one object. When you `fit` the pipeline, each step is fitted in
order, on the training data only. It becomes structurally difficult to leak.

```python
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer

pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),   # fill in missing values
    ("scale",  StandardScaler()),                   # then standardise
])
pipe.fit(X_train)          # fits BOTH steps, on training data only
```

A **`ColumnTransformer`** applies different steps to different columns — numbers need scaling, text
categories need encoding:

```python
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder

prep = ColumnTransformer([
    ("nums", StandardScaler(),  ["age", "income"]),
    ("cats", OneHotEncoder(),   ["city"]),
])
```

**One-hot encoding** turns a column of categories into one yes/no column per category, because a
model does arithmetic and cannot do arithmetic on the word "Delhi".

## Idea 4 — cross-validation, in one paragraph

A single split is one opinion, and it might be a lucky one. **Cross-validation** splits the data
several ways and reports every result.

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(pipe, X, y, cv=5)   # five different splits
print(scores.mean(), scores.std())
```

`cv=5` means: cut the data into five parts, train on four and test on the fifth, five times over so
each part is the test set exactly once. Those five parts are called **folds**. You get five scores;
their spread tells you how much your single number was luck.

That is all you need. Week 19 covers when this is the right tool and when it quietly lies to you.

## The names you will meet this week

| Name | Read it as |
| --- | --- |
| `estimator` | any scikit-learn object with a `fit` method |
| `SimpleImputer` | fill missing values with the median, mean, or a constant |
| `StandardScaler` | rescale so each column has mean 0 and spread 1 |
| `OneHotEncoder` | one yes/no column per category |
| `Pipeline` | run these steps in order, fit them together |
| `ColumnTransformer` | apply different steps to different columns |
| `train_test_split` | hide some rows to test on later |
| `cross_val_score` | score across several splits, not one |
| `GroupKFold` | split so related rows never straddle the boundary |
| `DecisionTreeClassifier`, `RandomForestClassifier` | two models used here only as measuring instruments |
