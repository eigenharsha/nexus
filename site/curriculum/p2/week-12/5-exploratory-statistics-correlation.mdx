## The mental model

A correlation between X and Y has exactly four possible explanations:

1. **X causes Y.**
2. **Y causes X.**
3. **Something else (Z) causes both.** — the confounder.
4. **Chance**, or an artefact of how the data was selected.

Correlation cannot distinguish between them. Data alone never can — you need either an experiment
(Module 4) or an assumption about the causal structure, written down explicitly.

The most common practical failure is not "believing causation" in the abstract. It is **not noticing
that a third variable exists**, and the sharpest version of that failure is Simpson's paradox, where
including or excluding one variable *reverses the sign* of the relationship.

### Descriptive statistics, and where each one lies

- **Mean** — the average. Pulled by outliers.
- **Median** — the middle value. Robust to outliers.
- **Mode** — the most common value. Useful for categories.
- **Range** — max minus min. Determined entirely by the two most extreme points.
- **IQR (interquartile range)** — p75 minus p25. Robust.
- **Standard deviation** — typical distance from the mean. Not robust.
- **Skewness** — asymmetry. Positive means a long right tail.
- **Kurtosis** — how heavy the tails are relative to a normal.

The rule Module 2 established: **look at the histogram first.** Anscombe's quartet is the canonical
demonstration — four datasets with identical means, variances, correlations and regression lines, and
completely different shapes. One is a clean line, one is a parabola, one is a line with an outlier, and
one is a vertical stack with a single far point.

```python
import numpy as np
from scipy import stats
rng = np.random.default_rng(0)

for name, data in [("symmetric", rng.normal(100, 15, 10_000)),
                   ("skewed", rng.lognormal(3, 1, 10_000))]:
    print(f"{name:<10} mean={data.mean():8.2f} median={np.median(data):8.2f} "
          f"sd={data.std():8.2f} IQR={stats.iqr(data):8.2f} skew={stats.skew(data):6.2f}")
```

```
symmetric  mean=  100.09 median=   99.86 sd=   14.97 IQR=   20.35 skew= -0.03
skewed     mean=   33.01 median=   20.00 sd=   43.15 IQR=   29.52 skew=  5.98
```

For the skewed data the mean (33.01) sits **65% above** the median (20.00) — the same effect you measured on real latency
in Module 2, where only 19.8% of requests were slower than the mean.

### Correlation

**Pearson's r** measures *linear* association:

```
r = Cov(X, Y) / (σ_X · σ_Y)
```

It runs from −1 (perfect negative line) through 0 (no linear relationship) to +1 (perfect positive
line).

**Spearman's ρ** is Pearson's r computed on the *ranks* rather than the values. It measures *monotone*
association — does Y consistently increase with X, by any shape of curve?

Three cases where they diverge, measured:

```python
import numpy as np
from scipy import stats
rng = np.random.default_rng(0)

x = rng.uniform(0, 10, 500)
y = np.exp(x / 2) + rng.normal(0, 1, 500)             # monotone but very non-linear
print(f"exponential:  pearson={stats.pearsonr(x,y)[0]:.3f}  spearman={stats.spearmanr(x,y)[0]:.3f}")

x2 = rng.uniform(-3, 3, 500); y2 = x2**2 + rng.normal(0, 0.5, 500)   # strong, non-monotone
print(f"parabola:     pearson={stats.pearsonr(x2,y2)[0]:.3f}  spearman={stats.spearmanr(x2,y2)[0]:.3f}")

x3 = rng.normal(0, 1, 500); y3 = 2*x3 + rng.normal(0, 1, 500)
x3o = np.append(x3, 20); y3o = np.append(y3, -40)     # ONE outlier added
print(f"with outlier: pearson={stats.pearsonr(x3o,y3o)[0]:.3f}  spearman={stats.spearmanr(x3o,y3o)[0]:.3f}"
      f"   (without: pearson={stats.pearsonr(x3,y3)[0]:.3f})")
```

Measured:

```
exponential:  pearson=0.856  spearman=0.993
parabola:     pearson=-0.069  spearman=-0.058
with outlier: pearson=0.087  spearman=0.885   (without: pearson=0.895)
```

Three lessons:

1. **Exponential:** a perfect monotone relationship, and Pearson reports only 0.856 because it is not a
   straight line. Spearman gets 0.993.
2. **Parabola:** a *deterministic* relationship — `y` is completely determined by `x` — and **both
   correlations are essentially zero.** Correlation measures monotone or linear association only. A
   correlation of 0 does not mean independence.
3. **One outlier out of 501 points** takes Pearson from 0.895 to **0.087** — it destroys the
   correlation entirely — while Spearman barely moves (0.885). Pearson is not robust. A single bad row
   in your data can invert a conclusion.

The practical rule: **compute both, and if they disagree, plot the data.** The disagreement is telling
you something specific — non-linearity or outliers — and which one it is is visible immediately.

### Spurious correlation

With a small sample, large correlations arise from pure noise routinely.

```python
import numpy as np
rng = np.random.default_rng(0)
for n in (10, 20, 50, 200):
    cnt = sum(1 for _ in range(20_000)
              if abs(np.corrcoef(rng.standard_normal(n), rng.standard_normal(n))[0, 1]) > 0.5)
    print(f"n={n:>4}: P(|r| > 0.5) between two independent noise variables = {cnt/20000:.4f}")
```

Measured:

```
n=  10: P(|r| > 0.5) between two independent noise variables = 0.1386
n=  20: P(|r| > 0.5) between two independent noise variables = 0.0244
n=  50: P(|r| > 0.5) between two independent noise variables = 0.0001
n= 200: P(|r| > 0.5) between two independent noise variables = 0.0000
```

**With 10 data points, two completely unrelated variables have a 14% chance of showing |r| > 0.5.** If
you have ten quarterly data points and you correlate them against twenty candidate drivers, you will
find something impressive, and it will mean nothing.

### Simpson's paradox: the real Berkeley case

In 1973, UC Berkeley's graduate admissions data looked like clear evidence of bias. Here are the six
largest departments, the actual published figures (Bickel, Hammel and O'Connell, *Science*, 1975):

```
AGGREGATED: men 1198/2691 = 44.5% admitted
            women 557/1835 = 30.4% admitted     ->  a 14.2 point gap
            chi-square on the aggregate: chi2 = 91.6, p = 1.06e-21
```

A 14-point gap with `p = 1e-21`. Overwhelming.

Now split by department:

| Dept | Men applied | Men admitted | Women applied | Women admitted | Gap (women − men) |
|---|---|---|---|---|---|
| A | 825 | 62.1% | 108 | **82.4%** | **+20.3%** |
| B | 560 | 63.0% | 25 | **68.0%** | **+5.0%** |
| C | 325 | 36.9% | 593 | 34.1% | −2.9% |
| D | 417 | 33.1% | 375 | **34.9%** | **+1.8%** |
| E | 191 | 27.7% | 393 | 23.9% | −3.8% |
| F | 373 | 5.9% | 341 | **7.0%** | **+1.1%** |

**Women had the higher admission rate in four of the six departments**, and the two where they did not
were by under 4 points. The aggregate says men were favoured by 14 points. Every level of the data
disagrees with the level above it.

### Why the reversal happens

The explanation is a third variable: **which department you apply to.**

| Dept | Overall admission rate | % of applicants who were women |
|---|---|---|
| A | 64.4% | 11.6% |
| B | 63.2% | 4.3% |
| C | 35.1% | 64.6% |
| D | 34.0% | 47.3% |
| E | 25.2% | 67.3% |
| F | 6.4% | 47.8% |

The correlation between a department's admission rate and its share of women applicants is
**−0.786**. Women applied disproportionately to the *competitive* departments (C, E, F — admission
rates of 35%, 25% and 6%) while men applied to the easier ones (A and B, at 64% and 63%).

So the aggregate gap is not about how each department treated applicants. It is about which
departments people applied to.

**The general structure:** if a third variable Z affects both your grouping variable X and your outcome
Y, and the groups are distributed unevenly across Z, then the aggregate can point the opposite way from
every subgroup.

### Which number is right?

Both are arithmetically correct. Which one *answers your question* depends on what you are asking:

- **"Does the admissions process treat equally qualified applicants differently within a department?"**
  → Look at the departmental breakdown. Answer: mostly no, and slightly favouring women.
- **"Are women less likely to be admitted to Berkeley overall?"** → The aggregate. Answer: yes.
- **"Why?"** → Because of differential application patterns, which is a real and important finding —
  it just points at a completely different intervention (why do women apply to underfunded, oversubscribed
  departments?) than "fix the admissions committees" would.

**This is why "just look at the data" is not a method.** The same data supports opposite readings, and
choosing between them requires knowing what causes what.

**The treatment is better in both groups and worse overall.**

The confounder is severity, and it is distributed unevenly: 80% of treated patients were severe, and
only 20% of control patients were. Doctors gave the new treatment to the sicker patients — which is
exactly what a doctor should do, and exactly what destroys a naive comparison.

**This is confounding by indication**, and it is why observational medical studies are hard and why
randomised trials exist. Randomisation (Module 4) makes severity equal in both arms by construction, so
the aggregate and the subgroups agree.

The correct conclusion from this data: *the treatment appears beneficial within each severity stratum,
but assignment was not random, so the estimate is confounded by whatever else determined who received
it. A randomised trial is needed to establish the effect.*

### Correlation matrices and multicollinearity

<Note>
**First time seeing pandas?** It is taught properly in Week 16; you only need three things here.
A **DataFrame** is a table — think a spreadsheet with named columns.
`pd.read_csv("f.csv")` loads one from disk. `df.groupby("col").mean()` splits the table by the
values in a column and summarises each group. `df.iloc[0]` is the first row by position.
That is enough to read every pandas line in this week.
</Note>

```python
import numpy as np
import pandas as pd

def correlation_report(df, threshold=0.8):
    c = df.corr(method="spearman")           # Spearman: robust to outliers and monotone non-linearity
    pairs = []
    cols = c.columns
    for i in range(len(cols)):
        for j in range(i + 1, len(cols)):
            if abs(c.iloc[i, j]) > threshold:
                pairs.append((cols[i], cols[j], c.iloc[i, j]))
    return c, sorted(pairs, key=lambda t: -abs(t[2]))
```

**Multicollinearity** — features that are highly correlated with each other — does not hurt a model's
*predictions*. It destroys the *interpretability* of its coefficients: with two features correlated at
0.95, the fitted coefficients can be enormous and opposite, and they flip sign between refits on
slightly different data.

Measure it with the **Variance Inflation Factor**: regress each feature on all the others, and
`VIF = 1/(1 − R²)`.

```python
from statsmodels.stats.outliers_influence import variance_inflation_factor
vifs = [variance_inflation_factor(X.values, i) for i in range(X.shape[1])]
```

Conventional readings: VIF above 5 is worth noting, above 10 is a problem. The fixes are to drop one of
the pair, combine them, or use a regularised model (ridge handles collinearity gracefully by design).

**But do not drop features just because they are correlated** if prediction is your goal. Tree models
are essentially unaffected; regularised linear models handle it. The problem is specifically with
*interpreting coefficients*, and it is worth being clear about which of those two things you are doing.

### Detecting Simpson's paradox systematically

You will not spot it by looking. Automate it.

```python
import numpy as np
import pandas as pd

def simpson_check(df, group_col, outcome_col, segment_cols):
    """Flag any segmentation where the aggregate effect reverses in a majority of segments."""
    agg = df.groupby(group_col)[outcome_col].mean()
    agg_dir = np.sign(agg.iloc[1] - agg.iloc[0])
    findings = []
    for seg in segment_cols:
        dirs, weights = [], []
        for value, sub in df.groupby(seg):
            if sub[group_col].nunique() < 2:
                continue
            m = sub.groupby(group_col)[outcome_col].mean()
            dirs.append(np.sign(m.iloc[1] - m.iloc[0]))
            weights.append(len(sub))
        if not dirs:
            continue
        dirs, weights = np.array(dirs), np.array(weights)
        reversed_share = weights[dirs == -agg_dir].sum() / weights.sum()
        if reversed_share > 0.5:
            findings.append((seg, reversed_share, len(dirs)))
    return sorted(findings, key=lambda t: -t[1])
```

Run this against every categorical variable you have before drawing a conclusion from an aggregate. It
takes seconds and it is the only reliable way to catch the reversal.

**The variables that most often cause it in practice:** time period (a mix shift between months),
customer segment, device or platform, geography, and — the most common of all — **acquisition
channel**, because channels differ in both volume and quality and their mix changes constantly.

### Causal DAGs: confounders, colliders, mediators

Draw the causal structure before you decide what to control for. Three shapes, three different
prescriptions, and getting them mixed up is the standard error.

**Confounder** — `Z → X` and `Z → Y`.

```
Z (department) ──→ X (gender applies here)
   │
   └──────────────→ Y (admission rate)
```

Z creates a spurious association between X and Y. **Control for Z** (stratify, or include it in the
model). This is the Berkeley case.

**Collider** — `X → Z ← Y`.

```
X (talent) ──→ Z (gets hired) ←── Y (interview skill)
```

X and Y may be completely independent in the population. But among those hired, they become
**negatively correlated** — if you got hired despite low talent, you must have interviewed well.
**Controlling for a collider creates a spurious association that was not there.**

This is the mechanism behind **Berkson's paradox** and behind a huge amount of confusing published
correlation. It is also why "among our customers, X and Y are negatively related" is often an artefact
of who becomes a customer.

**Mediator** — `X → Z → Y`.

```
X (new UI) ──→ Z (page load time) ──→ Y (conversion)
```

Z is *how* X affects Y. **Controlling for Z removes the very effect you wanted to measure.** If your
new UI improves conversion by being faster, and you control for load time, you will conclude the UI
does nothing.

**The one-line summary you should memorise:** *control for confounders, never for colliders, and only
control for mediators if you specifically want the direct effect excluding that pathway.*

The reason "control for everything you have" is wrong is that it will include colliders and mediators
and make your estimate worse. `dowhy` and `causal-learn` are the Python libraries for doing this
properly, and both start by asking you to draw the graph.

### Correlation is not causation: the useful version

The slogan is useless. The useful version is a checklist you can actually run:

| Question | If yes | If no |
|---|---|---|
| Could Y cause X? (reverse causation) | Check the temporal order | Rules out one of four |
| Is there a plausible common cause Z? | Measure it and stratify | Rules out another |
| Could selection into the dataset create it? (collider) | Look at how the sample was formed | The most-missed one |
| Would the association survive an intervention? | **Run an experiment** (Module 4) | You cannot conclude causation |
| Is it large enough to matter, and stable across time and segments? | Worth pursuing | Probably noise |

Hill's criteria (1965) add: strength, consistency across studies, specificity, temporality, a
dose-response gradient, biological plausibility, coherence, experiment and analogy. **Temporality is
the only necessary one** — the cause must precede the effect. The rest raise or lower plausibility.

### Trade-offs

| Decision | Choose this when… | Choose the other when… | The number |
|---|---|---|---|
| **Spearman** | Outliers possible; relationship may be monotone-but-curved | You specifically want linear strength | One outlier in 501 points took Pearson from 0.895 to 0.087; Spearman held at 0.885 |
| **Drop correlated features** | You are interpreting coefficients | You are only predicting, or using trees or ridge | Multicollinearity harms interpretation, not prediction |
| **Stratify** | The confounder is categorical and has enough data per stratum | Many confounders, or continuous ones | Berkeley: six strata, each with hundreds of applicants |
| **Regression adjustment** | Multiple or continuous confounders | The functional form is unknown | Assumes you got the model right; misspecification reintroduces bias |
| **Just run an experiment** | You can randomise | Ethics, cost or feasibility forbid it | Randomisation handles *unmeasured* confounders, which no observational method can |

### What breaks in the real world

A growth team observed that users who enabled push notifications retained at **62%** at day 30, against
**31%** for users who did not. They ran a campaign to push more users into enabling notifications. Day-30
retention across the base did not move.

The correlation was real; the causal reading was backwards. **Users who were already engaged enabled
notifications.** Enabling was a *symptom* of intent to keep using the product, not a cause of it.

The confounder was pre-existing engagement, and it was measurable: segmenting by sessions in the first
week made the gap almost vanish. Among users with 5+ first-week sessions, retention was 71% with
notifications and 68% without — a 3-point gap, not 31.

They then ran a proper experiment: randomly prompt half of new users to enable notifications. The
measured effect was **+2.1 points** of day-30 retention, 95% CI `[+0.4, +3.8]` — real, worth having, and
**fifteen times smaller** than the observational number.

**The general pattern: any voluntary user action is selected-into by people who were going to be
retained anyway.** Feature adoption, profile completion, newsletter sign-up, connecting an integration —
all of them correlate powerfully with retention and almost none of them cause it at the observed
magnitude. The correct move is always the same: segment by prior engagement first, then randomise.

### Design checkpoint

<Accordion title="Your model's feature importance says 'number of support tickets' is the strongest predictor of churn. Product wants to reduce support tickets. What do you say?">

Feature importance is **associational, not causal**, and this specific case has at least four
explanations that lead to four different actions.

**1. Reverse causation.** Customers about to churn contact support more, because they are frustrated.
The tickets are a *symptom*. Reducing tickets by making support harder to reach would raise churn while
improving the metric — an actively harmful intervention that the model would score as a success.

**2. Confounding.** A broken feature causes both the tickets and the churn. Fixing the feature fixes
both; suppressing tickets fixes neither.

**3. Collider bias.** If the training data conditions on something downstream of both — "customers who
were engaged enough to have an account for 6 months", say — spurious associations can appear.

**4. Genuine causation.** Bad support experiences do cause churn. Plausible, and probably part of the
story.

**What to check, in order:**

- **Temporality.** When do tickets occur relative to the churn signal? If they cluster in the final two
  weeks, reverse causation dominates. If they are spread evenly, causation is more plausible. This is a
  one-query check and it is decisive more often than people expect.
- **Ticket sentiment and type.** "How do I use X" is a different signal from "X is broken and I want a
  refund". Splitting by type usually splits the effect.
- **Resolution outcome.** If tickets *resolved quickly* predict retention while unresolved ones predict
  churn, that is evidence for a real causal path through support quality — and it points at a very
  different intervention.
- **Segment by pre-existing engagement**, as in the war story. Much of the association may vanish.

**What to actually propose:** an experiment. Randomly assign a subset of ticket-raising customers to a
faster or higher-touch support tier and measure churn. That answers the causal question directly, and
it will give an effect far smaller than the feature importance implies — as the notifications case did,
by a factor of fifteen.

**And say this explicitly:** "the model is a churn *predictor*, not a churn *explainer*. It is doing its
job — flagging accounts at risk — and using its feature ranking as a list of interventions is a
category error. SHAP values tell you what the model used, not what the world does."

That last distinction is the one worth being able to state cleanly, because interpretability tooling
makes it very easy to blur.

### The multiple-comparisons trap in exploratory analysis

Exploratory data analysis is, structurally, a multiple-comparison problem with an unbounded number of
comparisons. Measured on pure independent noise (200 samples per variable):

| Variables `k` | Pairs tested | `p < 0.05` | Observed rate | Bonferroni threshold | Survivors |
|---|---|---|---|---|---|
| 5 | 10 | 0 | 0.00% | 5.00e-03 | 0 |
| 20 | 190 | 6 | 3.16% | 2.63e-04 | 0 |
| **100** | **4,950** | **257** | **5.19%** | 1.01e-05 | **0** |

**257 significant correlations among 100 variables that are all independent noise.** The rate matches
the nominal 5% exactly — `α` is doing precisely what it promises, and the promise is much weaker than
people assume.

A correlation heatmap over 100 features contains 4,950 comparisons. Looking at it and picking the
brightest cells is not analysis; it is sampling from the tail of a noise distribution.

Corrections: Bonferroni (family-wise error rate, conservative), Holm-Bonferroni (same guarantee,
uniformly more powerful — there is no reason to prefer plain Bonferroni), Benjamini-Hochberg (false
discovery rate, far more powerful when you have thousands of tests and can tolerate some false
discoveries).

**The practical discipline: exploratory findings are hypotheses, and they must be confirmed on held-out
data or by an experiment.** Split your data before exploring, or you will confirm your own noise.

### Ecological fallacy and its inverse

**Ecological fallacy:** inferring individual-level relationships from group-level data. Robinson (1950)
showed the definitive example: across US states, the correlation between the proportion of foreign-born
residents and literacy was **+0.53**; at the *individual* level it was **−0.11**. Opposite signs.

The mechanism is the same as Simpson's paradox: immigrants settled in states that already had high
literacy. Aggregating destroyed the within-state structure.

This matters directly whenever you analyse pre-aggregated data — daily rollups, per-cohort averages,
per-region summaries. **Correlations computed on aggregates are not correlations between individuals**,
and the difference can flip the sign.

**Atomistic fallacy** is the reverse: inferring group-level effects from individual data. Both are
failures to keep the level of analysis matched to the level of the question.

### Berkson's paradox, quantified

Selection into a dataset induces correlations that do not exist in the population.

```python
import numpy as np
rng = np.random.default_rng(0)
n = 100_000
talent    = rng.normal(0, 1, n)
interview = rng.normal(0, 1, n)            # independent by construction
print(f"population correlation:      {np.corrcoef(talent, interview)[0,1]:+.4f}")
hired = (talent + interview) > 1.5          # selection on the SUM
print(f"among the hired ({hired.mean():.1%}): "
      f"{np.corrcoef(talent[hired], interview[hired])[0,1]:+.4f}")
```

Measured:

```
population correlation:      +0.0011
among the hired (14.5%): -0.6771
```

**From +0.001 to −0.68 by doing nothing but filtering.** Two independent variables become strongly
negatively correlated among the selected, because selection on their
sum means a high value of one compensates for a low value of the other.

Where this appears in practice:

- **Hospital data.** Two diseases uncorrelated in the population appear negatively correlated among
  inpatients, because having either raises your chance of admission.
- **Customer data.** "Among our customers, price sensitivity and feature usage are negatively
  correlated" — because customers are selected on being willing to pay *or* needing the features.
- **Model training data.** Any dataset filtered on a downstream outcome introduces collider bias into
  every relationship in it. Filtering training data on "was reviewed by a human" or "had a resolution"
  is exactly this.

**The check: how did a row get into this dataset?** If the selection depends on two variables you are
about to correlate, the correlation is at least partly an artefact.

### Causal inference: what is actually available

You cannot always randomise. The observational toolkit, with its assumptions stated:

| Method | Idea | Key assumption | Fails when |
|---|---|---|---|
| **Stratification / regression adjustment** | Compare like with like | All confounders measured | An unmeasured confounder exists |
| **Propensity score matching** | Match treated to control on P(treated \| covariates) | All confounders measured ("no unmeasured confounding") | Same. It does *not* solve unmeasured confounding, despite frequent claims |
| **Difference-in-differences** | Compare the change over time in treated versus untreated groups | **Parallel trends** — both groups would have moved the same way absent treatment | The groups were already diverging; check the pre-period |
| **Instrumental variables** | Find Z affecting X but not Y except through X | The exclusion restriction, which is untestable | Weak instruments give badly biased estimates |
| **Regression discontinuity** | Compare just above and below a cut-off | No manipulation of the running variable around the cut-off | People can game the threshold |
| **Synthetic control** | Build a weighted combination of untreated units matching the treated one's pre-period | Good pre-period fit and no interference | Short pre-periods; a treated unit outside the donor pool's convex hull |

**The point almost always missed: propensity score matching does not solve confounding.** It is a
convenient way to condition on *measured* covariates. If an unmeasured confounder exists — and in the
notifications example, "intent to keep using the product" is unmeasured almost by definition — matching
does nothing about it. Only randomisation handles unmeasured confounders, and that is the entire reason
experiments are worth their cost.

**Difference-in-differences** is the one most worth learning, because it is cheap and often available:
you need a treated group, an untreated group, and observations before and after. The assumption to
check is parallel trends, and you check it by plotting the pre-period.

### Production failure modes

| Failure | Signature | Detection |
|---|---|---|
| **Simpson's paradox** | Aggregate contradicts every segment | Run the segmentation check across every categorical variable before concluding |
| **Ecological fallacy** | Correlation computed on daily/regional rollups | Analyse at the level of the question; Robinson measured +0.53 aggregate against −0.11 individual |
| **Collider bias from data filtering** | A relationship that only exists in your dataset | Ask how rows entered the dataset; if selection depends on both variables, be suspicious |
| **Pearson destroyed by one outlier** | r near zero on a visibly linear scatter | Measured 0.895 → 0.087 from one point in 501. Report Spearman too; plot |
| **Correlation heatmap mined for findings** | Several exciting correlations, none replicate | 4,950 pairs over 100 features gives ~250 spurious hits at α = 0.05 |
| **Feature importance read as a causal ranking** | An intervention on the top feature does nothing | SHAP tells you what the model used, not what the world does |
| **Adoption metric read as causal** | A campaign to increase adoption moves nothing | Voluntary actions are selected-into; measured 31 points observational versus 2.1 experimental |
| **Controlling for a mediator** | A real effect disappears when you "control for confounders" | Draw the DAG; a mediator is on the causal path and must not be controlled for |
| **Zero correlation read as independence** | A strong non-monotone relationship missed | `y = x²` has r ≈ 0. Use mutual information or distance correlation, and always plot |

### Frontier and further pointers

- **P. J. Bickel, E. A. Hammel and J. W. O'Connell, "Sex Bias in Graduate Admissions: Data from
  Berkeley," *Science* 187(4175), 1975.** Takeaway: an aggregate 14-point admission gap disappeared —
  and mildly reversed — on stratifying by department, because applicants of different genders applied to
  departments with very different admission rates. The canonical, real, and still best example.
- **W. S. Robinson, "Ecological Correlations and the Behavior of Individuals," *American Sociological
  Review* 15(3), 1950.** Takeaway: the state-level correlation between foreign birth and literacy was
  +0.53 while the individual-level correlation was −0.11 — aggregate correlations can have the opposite
  sign to individual ones.
- **J. Pearl, *Causality* (2nd ed., 2009), and Pearl & Mackenzie, *The Book of Why* (2018).**
  Takeaway: causal questions require a causal model; the do-calculus and the back-door/front-door
  criteria tell you exactly which variables to condition on, and colliders are why "control for
  everything" is wrong.
- **J. Berkson, "Limitations of the application of fourfold table analysis to hospital data,"
  *Biometrics Bulletin* 2(3), 1946.** Takeaway: selection into a sample on a function of two variables
  induces correlation between them among the selected, even when they are independent in the
  population.
- **G. W. Imbens and D. B. Rubin, *Causal Inference for Statistics, Social, and Biomedical Sciences*
  (2015).** Takeaway: the potential-outcomes framework makes explicit that every causal claim is a
  comparison against a counterfactual you did not observe, which is what makes the assumptions
  unavoidable rather than optional.

### Stretch challenge

Build an EDA tool that actively warns you about your own conclusions.

1. Given a dataframe, a group column and an outcome, **automatically search every categorical variable
   for Simpson's-paradox reversals** and report them ranked by the share of data that reverses. Test it
   on the Berkeley data and confirm it flags department.
2. Add **collider detection by construction**: given a proposed DAG, use `dowhy` or an implementation
   of the back-door criterion to report which variables must be controlled for and which must not.
   Demonstrate on a case where controlling for the wrong variable inverts the estimate.
3. Add **multiple-comparison awareness** to the correlation report: for `k` features, state the number
   of pairs, the expected number of spurious hits at α = 0.05, and apply Benjamini-Hochberg. On 100
   noise features it should report roughly 250 expected hits and zero survivors.
4. Add **robustness diagnostics**: Pearson and Spearman side by side, plus a leave-one-out sensitivity
   showing the largest change in `r` from removing any single point. Flag anything where one point moves
   `r` by more than 0.1.
5. Finally, run it on a real dataset and write the memo: three findings, and for each one, which of the
   four explanations for a correlation you have ruled out and how.

There is no single right answer — step 5 is the deliverable, and the honest version usually concludes
that most findings are not yet causal claims.

## Common mistakes

| Symptom | Cause | Fix |
|---|---|---|
| Aggregate contradicts every segment | Simpson's paradox from an uneven confounder | Segment across every categorical variable before concluding; automate it |
| A "strong driver" whose intervention does nothing | Reverse causation or selection into a voluntary action | Check temporality; segment by prior engagement; then randomise |
| Correlation near zero on a visibly related scatter | Non-monotone relationship, or one outlier | Plot; report Spearman; use mutual information for non-monotone |
| Several exciting findings from a correlation heatmap | Multiple comparisons over `k(k−1)/2` pairs | Measured: 257 spurious hits among 4,950 noise pairs. Correct, and confirm on held-out data |
| A relationship that only exists in your data | Collider bias from how rows were selected | Ask how rows entered the dataset; if selection depends on both variables, suspect it |
| A real effect vanishes after "controlling for confounders" | You controlled for a mediator | Draw the DAG; mediators are on the causal path and must be left alone |
| Correlations from daily or regional rollups | Ecological fallacy | Analyse at the level of the question; Robinson measured opposite signs |
| Feature importance used as an intervention list | Association read as causation | SHAP describes the model, not the world; propose an experiment |
