## Why this exists at all

You already know Python lists. A list can hold anything, which is exactly the problem:

```python
prices = [3.5, 2.0, 9.25]
total = sum(p * 2 for p in prices)      # a Python loop, one item at a time
```

Every element is a separate object, so Python checks the type of each one, every time. For three
prices that is invisible. For the million-element arrays in this phase it is the difference between
a second and a minute.

NumPy stores numbers the way C does — **one block of memory, all the same type** — and does the
loop in compiled code:

```python
import numpy as np

prices = np.array([3.5, 2.0, 9.25])
total = (prices * 2).sum()             # no Python loop at all
```

`prices * 2` does not mean "repeat the list twice", the way it would for a Python list. It means
"multiply every element by 2". That one difference is most of NumPy.

<Warning>
**The trap that catches everyone once.** For a Python list, `[1, 2] * 2` gives `[1, 2, 1, 2]`.
For a NumPy array, `np.array([1, 2]) * 2` gives `[2, 4]`. Same operator, completely different
meaning. If a result looks absurd, check which one you have with `type(x)`.
</Warning>

## The five things you need

### 1. Making an array, and its shape

```python
import numpy as np

v = np.array([1.0, 2.0, 3.0])            # 1-D: a vector
M = np.array([[2.0, 1.0],
              [1.0, 2.0]])               # 2-D: a matrix

print(v.shape)      # (3,)     three elements
print(M.shape)      # (2, 2)   two rows, two columns
print(M.dtype)      # float64  every element is a 64-bit float
```

**`shape` is the single most useful thing in NumPy.** Nearly every error you will hit this phase is
a shape you did not expect. When something breaks, print the shape first — before reading the error
message, before changing any code.

`shape` reads **outermost first**: `(2, 3)` is 2 rows of 3, not 3 columns of 2. A trailing comma in
`(3,)` just means it is one-dimensional — `(3,)` and `(3, 1)` are different things, and mixing them
up is the most common shape bug there is.

### 2. Getting elements out

For 2-D arrays the index is `[row, column]`:

```python
M = np.array([[10, 20, 30],
              [40, 50, 60]])

M[0, 2]      # 30      row 0, column 2
M[1]         # [40 50 60]     the whole of row 1
M[:, 1]      # [20 50]        the whole of column 1
```

That `M[:, 1]` is the one to slow down on, because it appears constantly from here on.

The colon means **"every index in this position"**. So `[:, 1]` reads as *every row, column 1* —
which is exactly "give me column 1". By the same logic `M[0, :]` is *row 0, every column*, and
`M[0]` is shorthand for the same thing.

You will most often meet it as `vecs[:, 0]`, meaning **the first column of a matrix**, because this
course stores eigenvectors as columns.

### 3. Arithmetic happens element by element

```python
a = np.array([1.0, 2.0, 3.0])
b = np.array([10.0, 20.0, 30.0])

a + b        # [11. 22. 33.]
a * b        # [10. 40. 90.]   <- element-wise, NOT a dot product
a * 2        # [2. 4. 6.]
np.sqrt(a)   # square root of each element
```

`a * b` multiplies matching positions. It is **not** the dot product, and this is worth saying twice
because the maths notation for both is a dot.

### 4. `@` is matrix multiplication

The dot product and matrix multiplication both use `@`:

```python
a @ b                # 140.0   the dot product: 1*10 + 2*20 + 3*30
M @ v                # matrix times vector
A @ B                # matrix times matrix
M.T                  # the transpose: rows become columns
```

**The rule for `@`:** the inner dimensions must match, and they vanish from the result.
`(2, 3) @ (3, 4)` works and gives `(2, 4)` — the 3s meet in the middle and cancel.
`(2, 3) @ (2, 3)` fails, and the error will say so:

```
ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0
```

When you see that, print both shapes. One of them is not what you think.

### 5. `axis` — which direction to collapse

```python
M = np.array([[1, 2, 3],
              [4, 5, 6]])

M.sum()             # 21   everything
M.sum(axis=0)       # [5 7 9]     down the columns
M.sum(axis=1)       # [ 6 15]     across the rows
```

`axis=0` is the confusing one. It does **not** mean "give me rows". It means *"collapse axis 0"* —
axis 0 is the row axis, so the rows disappear and you are left with one value per column.

A reliable trick: whichever axis you name is the one that **vanishes from the shape**. `(2, 3)` with
`axis=0` gives `(3,)`. With `axis=1` it gives `(2,)`.

## The functions these two weeks use

You do not need to memorise these. Skim once, then refer back.

| Call | What it does |
| --- | --- |
| `np.array([...])` | build an array from a list |
| `np.zeros(n)`, `np.ones(n)`, `np.empty(n)` | pre-sized arrays |
| `np.linspace(0, 1, 50)` | 50 evenly spaced values from 0 to 1 |
| `np.sqrt`, `np.exp`, `np.log`, `np.abs`, `np.sign` | element-wise maths |
| `np.sum`, `np.mean`, `np.median`, `np.percentile` | summaries, with optional `axis=` |
| `np.linalg.norm(v)` | length of a vector |
| `np.linalg.svd(M)` | the decomposition Module 3 is built on |
| `np.linalg.det`, `np.linalg.matrix_rank` | determinant, rank |
| `np.allclose(a, b)` | equal within floating-point tolerance |
| `np.round(x, 3)` | round for readable printing |
| `np.corrcoef(a, b)` | correlation matrix |

<Tip>
**Never compare floats with `==`.** Week 1 showed you why: `0.1 + 0.2` is not `0.3`. Use
`np.allclose(a, b)`, which asks "are these equal to within a tiny tolerance?" — the honest question.
</Tip>

## Random numbers, the modern way

You will see this line constantly:

```python
rng = np.random.default_rng(0)     # a generator, seeded with 0
x = rng.normal(size=1000)          # 1000 draws from a bell curve
y = rng.integers(0, 10, size=5)    # 5 whole numbers in [0, 10)
```

The `0` is a **seed**. Same seed, same numbers, every run, on every machine. That is what makes a
result reproducible — and reproducibility is graded in this course.

Older code uses `np.random.seed(0)` and `np.random.randn(...)`. It still works; `default_rng` is
the current recommendation and what these weeks use.

## The three errors you will actually hit

| The error says | What it means | What to do |
| --- | --- | --- |
| `operands could not be broadcast together with shapes (3,) (4,)` | you tried to combine arrays of incompatible sizes | print both `.shape` values; one is wrong |
| `matmul: Input operand 1 has a mismatch in its core dimension` | inner dimensions of `@` do not meet | check the middle numbers match; you may need `.T` |
| `IndexError: too many indices for array` | you used `[i, j]` on a 1-D array | it only has one axis — use `[i]`, or check the shape |

**In all three cases the first move is the same: print the shapes.** Not read the traceback, not
edit the line. Print `.shape` for every array involved. The bug is nearly always visible there.

## Prove it works

Type this out — do not paste it. It uses everything above, and it is the exact shape of the code
in Module 1.

```python
import numpy as np

rng = np.random.default_rng(0)
docs = rng.normal(size=(4, 3))          # 4 documents, 3 features each
query = np.array([1.0, 0.0, 0.0])

print(docs.shape, query.shape)          # (4, 3) (3,)

sims = docs @ query                     # (4,3) @ (3,) -> (4,)
sims = sims / (np.linalg.norm(docs, axis=1) * np.linalg.norm(query))

print(np.round(sims, 3))                # cosine similarity of each doc
print("closest document:", int(np.argmax(sims)))
```

If that runs and the shapes make sense to you, you are ready for Module 1. If any line is still
opaque, re-read the section it came from — the modules from here on assume all five ideas.
