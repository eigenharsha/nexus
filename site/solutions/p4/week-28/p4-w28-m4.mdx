## Reference solution — `P4-W28-M4`

### The task

Plot NDCG and p95 latency against rerank depth `N` and pick an operating point against a stated SLO.

### The solution that works

The sweep is mechanical. The two details that make it correct:

```python
# 1. sort candidates by length before batching: less padding, 17% more throughput
order = sorted(range(len(cands)), key=lambda i: len(cands[i].text))

# 2. count truncation. there is no warning and it was 5 of 8 residual failures.
n_trunc = sum(len(tok(q, c.text)["input_ids"]) >= max_length for c in cands)
metrics.increment("rerank.truncated", n_trunc)
```

And the metric choice, which is the module's real lesson: report NDCG@10 **and** end-to-end answer
accuracy, not Recall@10.

### Why this solution and not the obvious one

**The obvious evaluation uses Recall@10 and concludes reranking is worthless.** It moves 0.01 by
construction — reranking reorders the candidate set, it does not retrieve. That conclusion deleted a
feature worth 11 points of answer accuracy in the war story. **Recall@k is the wrong primary metric
for any reordering stage**, and choosing the metric to match the question is Week 27 Module 5's
lesson arriving with consequences.

**The obvious depth choice is "as deep as latency allows".** Stage 1's Recall@50 is 0.97 and
Recall@200 is 0.98, so depth beyond 50 is reordering candidates that were already there. The ceiling
is set by retrieval, not by the reranker.

### The two wrong turns worth knowing about

**Wrong turn 1: silent truncation at `max_length=512`.** The query and the chunk share the budget, so
a 512-token chunk plus a section-path prefix loses its tail — and `sentence-transformers` does not
warn. On the reference corpus, 5 of the 8 queries where the gold chunk was in the candidate set but
not promoted were truncation cases. Log the rate.

**Wrong turn 2: thresholding on cross-encoder scores across queries.** They are unbounded per-query
logits, not calibrated probabilities. A score of 8.4 on one query and 3.1 on another says nothing
about which is more relevant. Normalise within the candidate list, or use rank-based rules.

### Grading notes

**3/3** requires the full depth sweep, an SLO stated *before* the operating point is chosen, NDCG and
answer accuracy reported alongside Recall@10, and paired CIs. Credit for putting Module 3's
techniques on the same gain-versus-latency axes, which is where the architecture decision becomes
obvious. **The three most common point losses:** evaluating on Recall@10 alone; depth chosen without
reference to the candidate set's recall ceiling; and no truncation counter, which hides the most
common residual failure.
