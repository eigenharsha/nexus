## Reference solution — `P4-W27-M3`

### The task

Evaluate four embedding models on your own labelled query set, segmented by query type; report
Recall@10 and cost; choose one with justification.

### The solution that works

The harness is Module 3 Layer 2's `Embedder` plus the evaluation loop. The two lines that decide
whether your numbers mean anything:

```python
QUERY_PREFIXES = {
    "BAAI/bge-base-en-v1.5":  ("Represent this sentence for searching relevant passages: ", ""),
    "intfloat/e5-large-v2":   ("query: ", "passage: "),
    "Alibaba-NLP/gte-large-en-v1.5": ("", ""),
    "sentence-transformers/all-MiniLM-L6-v2": ("", ""),
}
q_prefix, d_prefix = QUERY_PREFIXES[model_name]
```

Get this wrong and you are measuring a handicapped model.

Choice: **`bge-base`**, because it is indistinguishable in quality at 3× the throughput and 25% less

### Why this solution and not the obvious one

**The obvious solution reports one aggregate number per model and ranks them.** The aggregate hides
two findings that change decisions. First, a reversal: `bge-small` beats `e5-large` on policy and
contract language, opposite to both the aggregate and the leaderboard. Second, and far more
important, **every model scores 0.37–0.41 on exact-identifier queries.** That is not a model
selection problem; it is a query class dense retrieval cannot serve, and no amount of model shopping
fixes it. Discovering it here is what motivates Week 28's hybrid search — and you only see it if you
segment.

### The two wrong turns worth knowing about

**Wrong turn 1: omitting the query instruction prefix.** `e5` without `query: ` and `passage: `
measured 0.79 instead of 0.87 on the reference corpus — eight points from two string literals. Every
family has a different convention and some have none; read the model card, and measure both ways so
the number is in your report rather than in your assumptions.

**Wrong turn 2: an embedding cache keyed only on text.** Switch models, get the old model's vectors
back, spend a day debugging a "regression" that is a cache hit. The key must include the model name
and revision, and you should assert the loaded vector's dimension against the model's.

### Grading notes

**3/3** requires at least four models, per-segment breakdown, paired CIs, cost and storage columns,
the correct prefixes demonstrated, and a justification naming the segment where the chosen model
loses. **The three most common point losses:** aggregate-only reporting, which hides both the
reversal and the broken query class; missing or misapplied prefixes, which quietly handicaps one or
more candidates; and choosing the highest score without noting that the difference is inside the CI
while the throughput difference is 3×.
