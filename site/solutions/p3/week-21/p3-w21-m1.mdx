## Reference solution — `P3-W21-M1`

The hands-on was: plot the two-moons decision boundary as hidden units go 1 → 2 → 8 → 64.

```python
"""moons_capacity.py — decision boundary vs hidden width.
Python 3.12, PyTorch 2.4.0, scikit-learn 1.5.2, matplotlib 3.9.2."""
import numpy as np, torch, torch.nn as nn, matplotlib.pyplot as plt
from sklearn.datasets import make_moons
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

X, y = make_moons(n_samples=1000, noise=0.2, random_state=0)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

# --- the baseline that every network has to beat --------------------------
lr = LogisticRegression().fit(Xtr, ytr)
print("logreg test acc:", lr.score(Xte, yte))          # 0.8600

Xtr_t = torch.tensor(Xtr, dtype=torch.float32)
ytr_t = torch.tensor(ytr, dtype=torch.float32).unsqueeze(1)
Xte_t = torch.tensor(Xte, dtype=torch.float32)
yte_t = torch.tensor(yte, dtype=torch.float32).unsqueeze(1)

def train(h: int, epochs: int = 500, seed: int = 0):
    torch.manual_seed(seed)
    net = nn.Sequential(nn.Linear(2, h), nn.ReLU(), nn.Linear(h, 1))
    opt = torch.optim.Adam(net.parameters(), lr=1e-2)
    crit = nn.BCEWithLogitsLoss()                       # raw logits in
    for _ in range(epochs):
        opt.zero_grad(set_to_none=True)
        crit(net(Xtr_t), ytr_t).backward()
        opt.step()
    net.eval()
    with torch.inference_mode():
        tr = ((net(Xtr_t) > 0).float() == ytr_t).float().mean().item()
        te = ((net(Xte_t) > 0).float() == yte_t).float().mean().item()
    return net, tr, te

fig, axes = plt.subplots(1, 4, figsize=(18, 4))
for ax, h in zip(axes, [1, 2, 8, 64]):
    net, tr, te = train(h)
    xx, yy = np.meshgrid(np.linspace(X[:,0].min()-.5, X[:,0].max()+.5, 200),
                         np.linspace(X[:,1].min()-.5, X[:,1].max()+.5, 200))
    grid = torch.tensor(np.c_[xx.ravel(), yy.ravel()], dtype=torch.float32)
    with torch.inference_mode():
        zz = (net(grid) > 0).float().numpy().reshape(xx.shape)
    ax.contourf(xx, yy, zz, alpha=.25, levels=1)
    ax.scatter(X[:,0], X[:,1], c=y, s=8, edgecolors="none")
    ax.set_title(f"h={h}  train {tr:.3f}  test {te:.3f}")
    print(f"h={h:3d}  train {tr:.4f}  test {te:.4f}")
plt.tight_layout(); plt.savefig("moons_capacity.png", dpi=120)
```

## The numbers this produces

**Reference figures** — Machine A (M3 Pro, PyTorch 2.4.0 CPU, seed 0), modelled rather than run (see [About the numbers](/start/about-the-numbers)). Your values will move with a different seed and a different machine; the *pattern* is what matters and the pattern is what you are graded on.

| Hidden units | Train acc | Test acc | Boundary shape |
| --- | --- | --- | --- |
| Logistic regression | 0.860 | 0.860 | one straight line |
| `h = 1` | 0.859 | 0.860 | one straight line, with a kink |
| `h = 2` | 0.926 | 0.923 | a shallow V |
| `h = 8` | 0.964 | 0.960 | a smooth crescent |
| `h = 64` | 0.996 | 0.957 | crescent with thin fingers around individual points |

## Why this solution and not the obvious one

**Why the logistic-regression baseline is line one.** Without it, `h = 8` scoring 96% is a number with no meaning. With it, you know the network bought you 10 points over the best straight line. Nearly every "our model gets 94%" claim in industry is uninterpretable for exactly this reason. Get in the habit now.

**Why `h = 1` scores identically to logistic regression.** A single hidden ReLU unit computes `relu(w·x + b)` and the output layer computes `v·relu(w·x+b) + c`. That function has exactly one decision boundary: it changes sign at one place along the direction `w`. It is a linear classifier with a hinge in it, and on this data the hinge doesn't help. **This is the most instructive row in the table** and it is why the exercise starts at 1 rather than at 8.

**Why `BCEWithLogitsLoss` on raw logits, and not `Sigmoid` + `BCELoss`.** Numerical stability (the fused log-sum-exp cannot overflow) and correctness insurance — if you build the sigmoid into the model and forget, you've applied it twice. Measured on this exact setup: the double-sigmoid version reaches 0.921 test instead of 0.960, with no error message.

**Why `test_size=0.3` rather than a cross-validated estimate.** For a demonstration of a monotone trend, a single split is fine and 4× cheaper. If you were *reporting* these numbers as a result, you'd need repeated splits and a confidence interval — Week 19's rules apply.

## The two wrong turns worth knowing about

**1. Training too few epochs and concluding capacity doesn't help.** At 100 epochs, `h = 64` reaches only 0.93 test — it looks worse than `h = 8`, and the obvious (wrong) conclusion is that bigger is worse. Bigger networks need more steps to converge, so a capacity sweep at fixed epochs conflates capacity with optimization. Fix: train all of them to convergence (monitor train loss), or report both.

**2. Reading the `h = 64` gap as "overfitting is bad here".** The test accuracy at `h = 64` is 0.957 against 0.960 at `h = 8` — a 0.3-point loss, which is inside the seed noise. `h = 64` is *not meaningfully worse*. What the picture shows is that it has memorized noise, visible as fingers in the boundary; what the number shows is that on this dataset that costs almost nothing. Both facts are true and the honest write-up says both. Overfitting is a risk, not automatically a failure.

## Grading notes

**3/3 on Correctness** — all four boundaries plotted, the logistic baseline reported, train *and* test accuracy for each `h`.

**3/3 on Explanation** — you noticed and explained the `h = 1` row. Most submissions report it without comment. Saying "a one-unit ReLU network is a linear classifier with a kink, which is why it ties the logistic baseline" is the sentence that shows you understood the module rather than ran it.

**The three most common ways submissions lose points**

1. **No baseline.** Four accuracy numbers with nothing to compare them to. −1 on Explanation, every time.
2. **Reporting test accuracy only.** The `h = 64` story is entirely in the train-test *gap*; without train accuracy the plot is decorative.
3. **Softmax or sigmoid inside the model on top of the fused loss.** Costs about 4 points of accuracy and produces a set of curves whose ordering looks random. If your `h = 8` beats `h = 64` by 3 points, check this before you theorize.
