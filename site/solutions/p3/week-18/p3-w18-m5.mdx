## Reference solution — `P3-W18-M5`

The task: produce a t-SNE plot, then write the three claims a reader would wrongly make from it, with the correct check for each.

## The three wrong claims, and their checks

| The claim, as a colleague says it | Why it is unsupported | The check, **in the original space** |
| --- | --- | --- |
| "Cluster C is broad and diffuse; A is a tight, homogeneous group." | t-SNE tunes a per-point Gaussian bandwidth so every point has the same effective number of neighbours, which normalises away exactly this difference | mean distance from each point to its cluster centroid, per cluster |
| "A and B are closely related; C is off on its own — or is it?" | the KL objective heavily penalises near-in-data-far-in-map and barely penalises the reverse, so far distances are not constrained at all | Euclidean or cosine distance between cluster centroids |
| "There are clearly three groups here." | the optimisation manufactures visible separation from chance neighbourhoods in any point cloud | cluster in the original space with the stability tests from Module 4; the plot only *displays* labels you computed elsewhere |

## The counterexample that proves it

Construct data whose global properties are known exactly: three clusters in 20 dimensions, where **C is 4x wider than A and 6.6x further away than B is.**

```python
rng = np.random.default_rng(0)
A = rng.normal(0, 1.0, size=(400, 20))
B = rng.normal(0, 1.0, size=(400, 20)); B[:, 0] += 6.0     # same size, close
C = rng.normal(0, 4.0, size=(400, 20)); C[:, 0] += 40.0    # 4x wider, far
```

| Method | cluster-size ratio C/A | distance ratio d(A,C)/d(A,B) |
| --- | --- | --- |
| **TRUTH (20-D)** | **3.95** | **6.63** |
| PCA, 2 components | 4.23 ✓ | 6.64 ✓ |
| t-SNE, perplexity 5 | 1.01 ✗ | 1.22 ✗ |
| t-SNE, perplexity 30 (default) | **0.97** ✗ | **1.09** ✗ |
| t-SNE, perplexity 100 | 0.95 ✗ | 1.86 ✗ |
| UMAP, n_neighbors 5 | 0.97 ✗ | 1.49 ✗ |
| UMAP, n_neighbors 15 (default) | 0.90 ✗ | **0.90** ✗✗ |
| UMAP, n_neighbors 50 | 0.91 ✗ | 2.33 ✗ |

The row to point at is UMAP at its default. The true distance ratio is 6.63; UMAP renders it as **0.90**, which means it draws the far cluster *nearer* than the near one. **The ordering reverses.** No amount of parameter tuning fixes any of this, because global metric structure is not in either objective.

How much rank-order distance information survives at all:

```
Spearman correlation of all pairwise distances with the 20-D truth:
  PCA          0.9585
  t-SNE p=30   0.6214
  UMAP nn=15   0.4372
```

## The harder failure: structure from nothing

```python
N = rng.normal(size=(900, 50))         # pure isotropic Gaussian noise
E = TSNE(2, perplexity=30, random_state=0, init="pca").fit_transform(N)
```

```
silhouette of KMeans(k=3) on the t-SNE map : 0.3461
silhouette of KMeans(k=3) on the raw 50-D  : 0.0168
```

**20.6x more apparent cluster structure than the data contains.** This is why "you can see the clusters" is never a conclusion, and why the third claim in the table above is the most dangerous of the three — it is the one that looks least like an inference.

## Why this solution and not the obvious one

**The obvious solution takes a real labelled dataset, makes a t-SNE plot, observes that the classes separate, and writes a paragraph about how t-SNE "revealed the structure".** That demonstrates nothing, because on a labelled dataset you cannot tell whether the picture is faithful or merely lucky — you have no ground truth for the *global* properties, only for the labels.

The constructed dataset is the whole method: by generating the data you know the size ratio is 3.95 and the distance ratio 6.63 by construction, so any discrepancy is measured, not argued.

Two more wrong turns:

1. **Concluding "so use UMAP instead".** UMAP is faster, has a `transform`, and is often described as preserving more global structure. On this construction it preserves **less** (Spearman 0.4372 against t-SNE's 0.6214) and reverses the distance ordering at its default parameters. It is a good tool; it is not the global-structure-preserving alternative.
2. **Using a single seed.** Both methods are stochastic. The whole finding weakens if a reader can say "you got unlucky". Two seeds and two neighbourhood-size values, always — and the reference table above varies perplexity across a 20x range precisely so nobody can claim a bad parameter choice.

## Grading notes

**3/3 looks like:** the constructed counterexample with a size ratio above 3.5 rendering below 1.2 and a distance ratio above 6 rendering below 1.5; PCA included as the control that gets both right; at least three perplexity or `n_neighbors` values so the failure cannot be blamed on parameters; the pure-noise silhouette comparison; and three wrong claims written the way a colleague would actually say them, each paired with a check that runs in the original space.

**The three most common ways submissions lose points:**

1. **No PCA control.** Without it, "the projection distorted things" could be a property of any 20-to-2 reduction. PCA getting 4.23 and 6.64 is what makes it specifically a t-SNE and UMAP property.
2. **One parameter setting.** Invites the objection that the parameter was wrong, which the multi-value table forecloses.
3. **Writing the wrong claims as strawmen.** "A reader might think the clusters are the same size" is weak. "Cluster C is our most homogeneous segment, so it is the easiest to target" is what somebody actually says in a meeting, and refuting *that* is the exercise.
