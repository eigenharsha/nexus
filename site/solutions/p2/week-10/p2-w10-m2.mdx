## Reference solution — `P2-W10-M2`

### The boundaries demonstration

```python
import socket, threading, time, collections
HOST, PORT = "127.0.0.1", 9982
recvs = []

def server(ready):
    s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind((HOST, PORT)); s.listen(1); ready.set()
    c, _ = s.accept(); total = 0
    while total < 3000:
        b = c.recv(65536)
        if not b: break
        recvs.append(len(b)); total += len(b)
    c.close()

ready = threading.Event()
threading.Thread(target=server, args=(ready,), daemon=True).start(); ready.wait()
c = socket.create_connection((HOST, PORT))
c.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)
for _ in range(1000):
    c.sendall(b"MSG")
time.sleep(0.5); c.close(); time.sleep(0.2)
print(len(recvs), "recv calls;", sum(recvs), "bytes;", max(recvs) // 3, "msgs in the largest read")
```

| Configuration | recv() calls | Largest read |
|---|---|---|
| `TCP_NODELAY` on | **413** | 40 messages |
| Nagle on (default) | **67** | 58 messages |

Both delivered all 3,000 bytes in order.

### The Mathis table

```python
import math
MSS = 1460
def mathis(rtt_ms, loss):
    return 1.22 * MSS * 8 / ((rtt_ms / 1000) * math.sqrt(loss)) / 1e6   # Mbit/s
```

| RTT | 0.01% | 0.1% | 1% | 2% |
|---|---|---|---|---|
| 1 ms | 1425 | 451 | 142 | 101 |
| 20 ms | 71.2 | 22.5 | 7.1 | 5.0 |
| 100 ms | 14.2 | 4.5 | 1.4 | 1.0 |
| 200 ms | 7.1 | 2.3 | 0.7 | 0.5 |

## Why this solution and not the obvious one

**Counting `recv()` calls rather than inspecting one read.** A single `recv` that happens to return
6 bytes proves the point weakly; the histogram over 1,000 sends proves it and shows the distribution.
The 413-versus-67 comparison additionally isolates Nagle as a separate variable, which is what turns
a demonstration into an experiment.

**Computing the Mathis bound before touching anything.** The instinct on a slow transfer is to change
something. The correct first move is arithmetic: measure RTT and loss, compute the ceiling, and see
whether you are already at it. If you are, no amount of tuning below the congestion-control layer
will help.

**Wrong turns worth knowing about.**

1. *Concluding that data was lost.* All 3,000 bytes arrived. The framing was lost, and framing was
   never TCP's responsibility. Students who write "TCP lost my messages" have inverted the lesson.
2. *Benchmarking throughput on loopback and generalising.* Loopback MSS measured **16,332 bytes**
   (16 KB MTU) versus 1460 on Ethernet, and RTT is effectively zero — loopback numbers
   (40.8 Gbit/s measured) tell you about your CPU, not about TCP.
3. *`sendall` with 1 MiB buffers on macOS.* Fails with `OSError: [Errno 55] No buffer space
   available` when the write exceeds the socket buffer. Chunk to 256 KiB.
4. *Setting `SO_REUSEADDR` and expecting `TIME_WAIT` to disappear.* It permits `bind()`; it does not
   remove the state or free the ephemeral port.

## Measured numbers this solution produces

- 1,000 sends of 3 bytes → **413** `recv()` calls with `TCP_NODELAY`, **67** with Nagle; largest
  single read 40 and 58 messages respectively.
- Loopback TCP throughput **40.81 Gbit/s**; `SO_SNDBUF` 4,194,304 bytes; loopback MSS **16,332 bytes**.
- TCP handshake on a real path: **22.6 ms** (one RTT).
- BDP: 62.5 KB (1 Gbit/s × 0.5 ms), 1.19 MB (10 Gbit/s × 1 ms), 2.38 MB (100 Mbit/s × 200 ms).
- Mathis ceiling at 100 ms and 1% loss: **1.4 Mbit/s per flow**.

## Grading notes

**What 3/3 looks like**

- *Correctness* — the student's own histogram, with and without `TCP_NODELAY`, and the assertion that
  all bytes arrived.
- *Code quality* — the demo is deterministic and self-contained; the server counts reads rather than
  printing them.
- *Performance* — measured throughput under emulated loss compared against the Mathis prediction,
  with the error reported.
- *Explanation* — identifies where the formula stops holding (very low loss, where the window binds;
  very high loss, where timeouts rather than fast retransmit dominate).

**The three most common ways submissions lose points**

1. **"TCP lost my messages."** The single most important misconception in the module, and it must be
   corrected explicitly in the write-up.
2. **Loopback numbers presented as network numbers.** The MSS of 16,332 is the tell.
3. **Measured-versus-predicted omitted.** The table of predictions is the course's; the comparison is
   the student's contribution.
