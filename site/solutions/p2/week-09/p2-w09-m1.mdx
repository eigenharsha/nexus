## Reference solution — `P2-W09-M1`

### The gate set, minimal, with measured cost

```python
# nandsim.py — the reference. Every gate below is NAND-only.
NAND_COUNT = 0

class Wire:
    __slots__ = ("v", "depth")
    def __init__(self, v, depth=0):
        self.v = int(v) & 1
        self.depth = depth

def nand(a, b):
    global NAND_COUNT
    NAND_COUNT += 1
    return Wire(1 - (a.v & b.v), max(a.depth, b.depth) + 1)

def NOT(a):      return nand(a, a)                       # 1 NAND,  depth 1
def AND(a, b):   return NOT(nand(a, b))                  # 2 NANDs, depth 2
def OR(a, b):    return nand(NOT(a), NOT(b))             # 3 NANDs, depth 2
def NOR(a, b):   return NOT(OR(a, b))                    # 4 NANDs, depth 3
def XOR(a, b):
    c = nand(a, b)
    return nand(nand(a, c), nand(c, b))                  # 4 NANDs, depth 3
def MUX(a, b, s):
    ns = NOT(s)
    return nand(nand(a, ns), nand(b, s))                 # 4 NANDs, depth 3
def DMUX(x, s):
    ns = NOT(s)
    return AND(x, ns), AND(x, s)                         # 5 NANDs, depth 3

def reset():
    global NAND_COUNT
    NAND_COUNT = 0
```

### The multi-way variants

```python
def MUX16(A, B, s):            # 16 x 4 = 64 NANDs, depth 3
    return [MUX(A[i], B[i], s) for i in range(16)]

def MUX4WAY16(A, B, C, D, s0, s1):
    ab = MUX16(A, B, s0)
    cd = MUX16(C, D, s0)
    return MUX16(ab, cd, s1)   # 3 x 64 = 192 NANDs, depth 6

def OR8WAY(X):                 # balanced tree, NOT a chain
    l1 = [OR(X[0], X[1]), OR(X[2], X[3]), OR(X[4], X[5]), OR(X[6], X[7])]
    l2 = [OR(l1[0], l1[1]), OR(l1[2], l1[3])]
    return OR(l2[0], l2[1])    # 7 x 3 = 21 NANDs, depth 6 (chain would be depth 14)
```

## Why this solution and not the obvious one

**MUX in 4 NANDs, not 8.** The construction everyone writes first is
`OR(AND(a, NOT s), AND(b, s))`, which is 1 + 2 + 2 + 3 = 8 NANDs at depth 5. The 4-NAND version
exploits the fact that `AND` is `NAND` followed by `NOT`, and `OR` of two values is `NAND` of their
negations. Written out: `OR(AND(a,ns), AND(b,s)) = nand(NOT(AND(a,ns)), NOT(AND(b,s)))
= nand(nand(a,ns), nand(b,s))`. Four inversions cancel. Halving the gate count *and* cutting two
levels of depth for free is the whole lesson of the module, and it is exactly what a synthesis tool
does when it maps to AOI/OAI cells.

**`Or8Way` as a balanced tree.** The chain version (`OR(OR(OR(...)))`) is the same 21 NANDs but
depth 14 instead of 6. It costs nothing to build it balanced, and in the ALU (Module 3) this block
sits on the `zr` path, so its depth is directly on the critical path.

**Two wrong turns worth knowing about.**

1. *Building `XOR` from the canonical sum-of-products.* `(NOT a AND b) OR (a AND NOT b)` is correct
   and costs 9 NANDs at depth 4. It is the natural thing to write from the truth table, and it is
   2.25× the area of the right answer. If your XOR costs 9, this is why.
2. *Tracking depth as "number of gates called".* Depth is `max(input depths) + 1`, not a counter.
   Get this wrong and every parallel structure looks serial, which makes the entire Week 9
   performance argument disappear.

## Grading notes

**What 3/3 looks like on each row**

- *Correctness* — all chips pass, and the student tested every gate over all `2^n` rows rather than a
  sample. For ≤ 3 inputs there is no excuse for sampling.
- *Code quality* — `Mux16` is a comprehension over `Mux`, not sixteen lines. `Mux4Way16` is three
  `Mux16`s. If any 16-bit chip contains the word `nand`, it was not composed.
- *Performance* — both gate count and depth reported, and at least two chips beat the naive
  construction with the saving explained (usually `Mux` 8 → 4 and `Or8Way` depth 14 → 6).
- *Explanation* — states why NAND rather than AND is the primitive, in transistors (4 vs 6), and
  connects depth to `f_max`.

**The three most common ways submissions lose points**

1. **Depth is missing or computed as a gate count.** This is by far the most common. The report says
   "XOR: 4 gates" and stops. Half the module's content is in the second number.
2. **The 8-NAND MUX, unnoticed.** Not wrong, but the student did not compare against a target, which
   means they did not treat gate count as a cost function — the stated learning objective.
3. **`Or8Way` built as a chain.** It passes every functional test and quietly adds 8 levels to the
   ALU's critical path in Module 3, where the student then cannot explain why their `f_max` is bad.
