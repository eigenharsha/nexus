## Reference solution — `P2-W14-M3`

Detect a cycle in a real dependency graph and **print the cycle path**. The full implementation is
in Layer 2 of the module page; this covers the three things that decide the mark.

### 1. Three colours, not two

```
WHITE  never visited
GREY   on the CURRENT depth-first path
BLACK  fully explored; everything below it led nowhere back
```

A two-colour implementation reports a cycle on this perfectly acyclic graph:

```
a → b → d
a → c → d
```

DFS reaches `d` via `b`, marks it visited, backtracks, reaches `d` again via `c`, sees "visited",
and reports a cycle. **Reaching a BLACK node is fine.** Only a GREY node — one on the path you are
currently standing on — is a back edge.

```python
def test_diamond_is_not_a_cycle():
    assert find_cycle({"a": ["b", "c"], "b": ["d"], "c": ["d"], "d": []}) == []
```

**Write this test first.** It fails on the two-colour version, and diamonds are the normal shape of
a real dependency graph.

### 2. Iterative, not recursive

```python
def test_deep_chain_does_not_blow_the_stack():
    g = {f"n{i}": [f"n{i+1}"] for i in range(10_000)}
    g["n10000"] = []
    assert find_cycle(g) == []
```

CPython's default recursion limit is 1,000. A transitive dependency chain 10,000 deep is not
unusual, and the recursive version raises `RecursionError` on real data while passing every test you
wrote. **Raising `sys.setrecursionlimit` is not the fix** — the real constraint is the C stack, and a
high limit converts a clean exception into a segfault.

The iterative form keeps an explicit stack of `(node, iterator-over-children)`:

```python
stack = [(start, iter(graph.get(start, ())))]
colour[start] = GREY
while stack:
    node, children = stack[-1]
    advanced = False
    for nb in children:                       # the iterator RESUMES where it left off
        if colour.get(nb, WHITE) == GREY:
            ...  # back edge — reconstruct the cycle from `parent`
        if colour.get(nb, WHITE) == WHITE:
            parent[nb] = node
            colour[nb] = GREY
            stack.append((nb, iter(graph.get(nb, ()))))
            advanced = True
            break                             # descend
    if not advanced:
        colour[node] = BLACK                  # finished: all children explored
        stack.pop()
```

**Storing the iterator, not the child list, is what makes this correct.** Resuming the same iterator
after descending is what "continue where I left off" means; re-creating the list would restart the
loop and revisit children forever.

### 3. Print the path, not a boolean

```python
if colour.get(nb) == GREY:
    cycle = [nb]
    cur = node
    while cur != nb:
        cycle.append(cur)
        cur = parent[cur]
    cycle.reverse()
    return cycle + [nb]        # closes on itself: auth -> db -> cache -> auth
```

`dependency cycle detected` on a 340-node graph cost the module's war story most of a day.
`auth -> db -> cache -> auth` costs thirty seconds. **The `parent` map is the only extra state
required and it is one dictionary.**

### Measured, so you can size your own

| Operation | Scale | Time | Per edge |
| --- | --- | --- | --- |
| BFS, full traversal | 100,000 nodes, 2,000,000 directed edges | 159.4 ms | **80 ns** |
| Kahn's topological sort, acyclic | 200,000 nodes, 599,998 edges | 135.1 ms | 225 ns |
| Kahn's with a cycle injected | same + 1 back edge | 179.5 ms | 299 ns |

| Nodes | Edges | Adjacency list | Bitset matrix | Advantage |
| --- | --- | --- | --- | --- |
| 10,000 | 100,000 | 4.9 MB | 12.5 MB | 2.53× |
| 100,000 | 1,000,000 | **52.3 MB** | **1,250.0 MB** | **23.89×** |

**Cycle detection costs 33% more than a clean topological sort, not 2×.** Kahn's does the same
in-degree pass either way. **Cycle detection is essentially free**, which removes the last excuse for
"log it and continue".

## Why this solution and not the obvious one

**Why both algorithms.** Kahn's gives you the topological order *and* tells you a cycle exists;
three-colour DFS gives you the cycle *path*. Production wants both: the order to execute in, and a
usable error message when there is not one. They share no code and both are fifteen lines.

**Why fail closed.** The war story's pipeline logged the cycle and fell back to declaration order,
producing plausible wrong numbers found eleven days later by finance. **A cycle is a configuration
error.** Refusing to run is correct; running in an arbitrary order is not.

**Why 80 ns per edge is the number to carry.** It tells you a million-edge traversal is ~160 ms in
Python — fine for a request-scoped operation, hopeless for 100 million edges (13 seconds). Above
roughly 10 million edges you want `scipy.sparse.csgraph` or `rustworkx`, and knowing the threshold
before you need it is the point of measuring.

## Grading notes

**3/3 on Correctness** — three colours; iterative; the diamond test; the 10,000-deep chain test; and
all components searched, not just the one containing the first node.

**3/3 on Code quality** — the cycle *path* returned, and the tool exits non-zero so it works as a CI
check.

**3/3 on Explanation** — why two colours produce false positives on a diamond, and why raising the
recursion limit is not a fix.

**The three most common ways submissions lose points:**

1. **Two colours.** False cycles on every diamond-shaped dependency graph, which is most of them.
2. **Recursive DFS.** Works on the test fixture, crashes on a real `package-lock.json`.
3. **Only the first connected component searched.** Starting a DFS from one node instead of looping
   over every WHITE node. Dependency graphs are routinely disconnected, and the cycle is often in the
   component you did not visit.

**A fourth, easy to miss:** returning a boolean. It satisfies the letter of "detect a cycle" and
misses the point of the exercise, which is that an error message naming specific entities is worth
an order of magnitude more than one naming a category.

**On the stretch challenge.** If someone submits the ecosystem survey, the interesting question is
whether they separated cycles by **edge type** — runtime, dev, peer, optional. npm's peer-dependency
graph is notoriously cyclic while its runtime graph is largely not, and a survey that conflates them
reports a number that is true and useless.
