## Reference solution — `LAB-P2-W11`

The module solution pages carry the implementations. This page covers the three things the lab adds:
the layout, the broadcasting backward pass that the `hard` track turns on, and how the tests are
constructed so they actually catch things.

### Layout

```
nanomath/
  vectors.py    dot, norm(p), cosine, normalise, project, euclidean
  matrices.py   matvec, matmul, matmul_tiled, transpose, identity, det2, rank, inverse
  decomp.py     power_iteration, deflate, top_k_eigen, pca_svd, low_rank, lora_params
  autodiff.py   Value, backward, numeric_grad, gradcheck
  optim.py      gd, momentum, nesterov, rmsprop, adam, adamw, clip_global_norm, schedules
tests/
  test_*.py     one file per module, each comparing against NumPy
tools/
  report.py     regenerates every table in REPORT.md
  bench_matmul.py
```

Nothing in `vectors.py` or `matrices.py` imports NumPy. NumPy appears only in the *tests*, as the
oracle. That separation is the point of the exercise: you are building the thing you will later trust,
so it must not be built out of the thing it is checked against.

### The `hard` track's actual difficulty: broadcasting backwards

A broadcast in the forward pass is a **sum over the broadcast axes** in the backward pass. This is the
one piece of tensor autodiff that is genuinely subtle.

```python
def unbroadcast(grad, shape):
    """Reduce `grad` back to `shape`, undoing any broadcasting done in the forward pass."""
    # 1. sum away leading axes that did not exist in the original
    while grad.ndim > len(shape):
        grad = grad.sum(axis=0)
    # 2. sum (keeping the axis) any axis that was size 1 in the original
    for i, s in enumerate(shape):
        if s == 1 and grad.shape[i] != 1:
            grad = grad.sum(axis=i, keepdims=True)
    return grad

def _add_backward(self, other, out):
    def _b():
        self.grad  += unbroadcast(out.grad, self.data.shape)
        other.grad += unbroadcast(out.grad, other.data.shape)
    return _b
```

Get this wrong and shapes still line up in the common case (adding a bias of shape `(d,)` to a
`(B, d)` activation) while the bias gradient is `B` times too large or the wrong shape entirely.
**Gradcheck a bias-add against a numerical gradient with `B > 1`** — that single test catches it, and
nothing else does.

### Tests that actually catch things

```python
def test_gradient_accumulates_on_reuse():
    """A diamond graph: x used twice. Assignment instead of += halves the gradient."""
    x = Value(3.0)
    y = (x * x) + x          # dy/dx = 2x + 1 = 7
    y.backward()
    assert abs(x.grad - 7.0) < 1e-12, x.grad

def test_backward_twice_doubles():
    """Proves accumulation rather than assignment."""
    x = Value(2.0); y = x * x
    y.backward(); first = x.grad
    y.backward()
    assert abs(x.grad - 2 * first) < 1e-12

def test_eckart_young():
    """The rank-k error must equal the root of the discarded energy."""
    A = np.random.default_rng(0).standard_normal((80, 50))
    sv = np.linalg.svd(A, compute_uv=False)
    for k in (1, 5, 10, 25):
        err = np.linalg.norm(A - low_rank(A, k))
        assert abs(err - np.sqrt((sv[k:] ** 2).sum())) < 1e-8

def test_pca_is_centred():
    X = np.random.default_rng(0).standard_normal((200, 12)) + 100.0
    out = pca_svd(X, 3)
    assert np.abs((X - out["mean"]).mean(axis=0)).max() < 1e-12

def test_stability_threshold():
    """lr < 2/L converges; lr > 2/L diverges. Sharp, not approximate."""
    for L in (1.0, 10.0):
        for lr, should_converge in [(1.99 / L, True), (2.01 / L, False)]:
            x = 1.0
            for _ in range(200):
                x = x - lr * (L * x)
            assert (abs(x) < 1.0) == should_converge, (L, lr, x)
```

The first two are the tests that separate a correct autodiff engine from one that happens to work on
straight chains. If your suite does not contain them, it is not testing the thing that breaks.

## Why this solution and not the obvious one

**NumPy is the oracle, never the implementation.** Every function is written from the definition and
checked against NumPy in a test. Importing NumPy inside `vectors.py` and calling it "from scratch"
defeats the entire exercise, and it is surprisingly common.

**The report is generated, not typed.** `tools/report.py` re-derives every table, and `make verify`
diffs it against the committed `REPORT.md`. Performance numbers typed by hand go stale within a week,
and a stale benchmark is worse than none.

**The cheat sheet is written from memory before being checked.** The gaps you find are exactly what you
have not learned, and finding them on Saturday costs an hour while finding them in Week 21 costs a
weekend.

## Grading notes

**What 3/3 looks like on each rubric row**

- *Correctness* — NumPy agreement to 1e-6 across all modules; gradcheck below 1e-7 on seven-plus
  functions; the diamond and double-backward tests present; Eckart–Young verified; singular inputs
  raise clearly.
- *Code quality* — no NumPy in the library, only in the tests; one implementation per concept, reused;
  every docstring states input shapes.
- *Performance* — tiled matmul at least 10× naive at n = 256, with the optimal tile size reported and
  predicted from cache sizes; the gap to BLAS decomposed into four named factors with a number each.
- *Explanation* — the cheat sheet is complete, in the student's own words, and each entry names the
  later week that uses it (cosine → 27, SVD → 26, chain rule → 21, Adam memory → 26).

**The three most common ways submissions lose points**

1. **The autodiff engine tested only on chains.** Passes everything, fails on any real graph. The
   diamond test is two lines and its absence is the clearest signal that the student did not understand
   why accumulation matters.
2. **Gradcheck run in float32.** Produces failures that are the harness's fault, after which the
   student "fixes" gradients that were already correct.
3. **A cheat sheet that is a summary of the modules rather than the student's own.** Instantly
   recognisable, and it forfeits the highest-retention exercise in Phase 2.
