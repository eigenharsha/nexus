## Reference solution — `P2-W11-M4`

### The three lines that make autodiff work

```python
def __mul__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    out = Value(self.data * other.data, (self, other), "*")
    def _b():
        self.grad  += other.data * out.grad     # (1) ACCUMULATE, never assign
        other.grad += self.data  * out.grad
    out._backward = _b                          # (2) a closure capturing the local derivative
    return out

def backward(self):
    topo, seen = [], set()
    def build(v):
        if v in seen: return
        seen.add(v)
        for c in v._prev: build(c)
        topo.append(v)
    build(self)
    self.grad = 1.0
    for v in reversed(topo):                    # (3) reverse topological order
        v._backward()
```

Those three numbered points *are* the algorithm. Everything else is operator coverage.

### `gradcheck`

```python
def numeric_grad(f, xs, i, h=1e-6):
    orig = xs[i].data
    xs[i].data = orig + h; fp = f(xs).data
    xs[i].data = orig - h; fm = f(xs).data
    xs[i].data = orig
    return (fp - fm) / (2 * h)

def gradcheck(f, n, trials=200, h=1e-6, seed=0):
    rng = random.Random(seed); worst = 0.0
    for _ in range(trials):
        xs = [Value(rng.uniform(-2, 2)) for _ in range(n)]
        for x in xs: x.grad = 0.0
        f(xs).backward()
        for i in range(n):
            a, b = xs[i].grad, numeric_grad(f, xs, i, h)
            worst = max(worst, abs(a - b) / max(1e-12, abs(a) + abs(b)))
    return worst
```

## Why this solution and not the obvious one

**`+=` rather than `=` in every `_backward`.** If a `Value` is used twice in an expression — which is
the normal case, not an edge case — both uses contribute to its gradient. Assignment keeps only the
last one. The bug passes every test built from a linear chain and fails on any diamond, which is
exactly what a real computation graph is. (It is also why PyTorch requires `zero_grad()`: accumulation
is the correct default, so it must be explicitly cleared.)

**Reverse topological order, not insertion order.** A node's gradient is complete only after every node
that consumes it has run. Insertion order happens to work for straight chains and silently produces
partial gradients for anything branched.

**The topological sort is iterative-safe and memoised with a `seen` set.** Without it, a diamond graph
is traversed exponentially.

**`gradcheck` uses relative error, not absolute.** An absolute error of 0.01 on a gradient of 10,000 is
irrelevant; on a gradient of 1e-8 it is total. Relative error is the only threshold that transfers
across scales.

**Wrong turns worth knowing about.**

1. *Gradchecking in float32.* The numerical gradient's noise floor is around `ε^(2/3) ≈ 2.4e-5` there,
   so the check cannot distinguish a correct gradient from one that is 0.01% wrong. Always float64.
2. *Choosing `h` too small.* Measured: `h = 1e-12` gives a worst relative error of **1.143e-01** —
   eight orders of magnitude worse than the optimum at `h = 1e-4` (1.325e-08). Roundoff, not
   truncation, dominates below about 1e-6.
3. *Gradchecking through a kink.* Perturbing a ReLU input across zero makes analytic and numerical
   gradients legitimately disagree. Use `tanh` for the check, or sample away from zero.
4. *Concluding that "backprop propagates errors".* It computes the chain rule in reverse topological
   order. The cost argument — 1 backward pass versus `n` forward passes — is the actual content.

## Measured numbers this solution produces

`gradcheck` worst relative error over 200 random inputs, float64, `h = 1e-6`:

| Function | Worst relative error |
|---|---|
| MSE `(y − t)²` | 1.831e-10 |
| sigmoid | 3.731e-10 |
| `tanh(w·x + b)` | 1.940e-07 |
| `relu(w·x + b)²` | 4.815e-10 |
| binary cross-entropy | 3.608e-10 |
| 5-deep `tanh` chain | 2.938e-09 |
| softmax + cross-entropy over 3 | 3.970e-09 |

Step-size sweep on `tanh(w·x + b)`:

| h | worst relative error |
|---|---|
| 1e-1 | 1.284e-02 |
| 1e-2 | 1.291e-04 |
| **1e-4** | **1.325e-08** |
| 1e-6 | 1.940e-07 |
| 1e-8 | 1.219e-05 |
| 1e-10 | 9.314e-04 |
| 1e-12 | 1.143e-01 |

A clean U-curve with the minimum near `h = 1e-4`, matching the theoretical optimum `ε^(1/3) ≈ 6e-6` to
within the resolution of the sweep.

Saturation demonstration: for `z = tanh(x·y + e^x)` at `x=2, y=3`, `z.data = 0.9999999999953071` and
`x.grad = 9.75e-11` — `tanh` has saturated and its local derivative `1 − tanh² ≈ 9.4e-12` annihilates
everything upstream.

  softmax + cross-entropy; the diamond-graph accumulation test passes; calling `backward()` twice
  without zeroing gives exactly double.
- *Code quality* — under 100 lines; every operator's `_backward` is a two-line closure; no operator
  duplicates another's logic.
- *Performance* — the step-size sweep, showing both sides of the U-curve.
- *Explanation* — the forward-versus-reverse cost model stated with the `n = 7e9` number, and the
  memory cost of the tape named as what checkpointing trades away.

**The three most common ways submissions lose points**

1. **`=` instead of `+=`.** Passes chains, fails diamonds. A diamond test must be in the suite.
2. **Gradcheck in float32 or at `h = 1e-10`.** Reports failures that are the check's fault, and the
   student then "fixes" a correct gradient.
3. **No cost argument.** The engine is built and works, and the write-up says backprop "propagates
   errors backwards" rather than giving the `1` versus `n` passes comparison that is the entire reason
   reverse mode exists.
