## Reference solution — `P2-W11-M1`

### The five functions

```python
import math

def dot(u, v):
    if len(u) != len(v):
        raise ValueError(f"length mismatch: {len(u)} vs {len(v)}")
    return sum(a * b for a, b in zip(u, v))

def norm(v, p=2):
    if p == 1:            return sum(abs(x) for x in v)
    if p == 2:            return math.sqrt(dot(v, v))
    if p == float("inf"): return max(abs(x) for x in v)
    return sum(abs(x) ** p for x in v) ** (1.0 / p)

def normalise(v):
    n = norm(v)
    if n == 0:
        raise ValueError("cannot normalise the zero vector")
    return [x / n for x in v]

def cosine(u, v):
    nu, nv = norm(u), norm(v)
    if nu == 0 or nv == 0:
        raise ValueError("cosine is undefined for a zero vector")
    return dot(u, v) / (nu * nv)

def project(u, v):
    d = dot(v, v)
    if d == 0:
        raise ValueError("cannot project onto the zero vector")
    s = dot(u, v) / d
    return [s * x for x in v]
```

### The concentration experiment

```python
import numpy as np
rng = np.random.default_rng(0)
for d in (2, 3, 5, 10, 50, 100, 500, 1000, 4096):
    n = 2000
    X = rng.standard_normal((n, d))
    Xn = X / np.linalg.norm(X, axis=1, keepdims=True)
    idx = rng.integers(0, n, size=(20000, 2)); idx = idx[idx[:, 0] != idx[:, 1]]
    cos = np.einsum('ij,ij->i', Xn[idx[:, 0]], Xn[idx[:, 1]])
    dist = np.linalg.norm(Xn[1:] - Xn[0], axis=1)
    print(d, np.abs(cos).mean(), dist.std() / dist.mean(),
          (dist.max() - dist.min()) / dist.min())
```

## Why this solution and not the obvious one

**Every function raises on a zero vector rather than returning `nan`.** A `nan` propagates silently
through a retrieval pipeline and produces a document that matches nothing, with no error anywhere. An
exception at write time is a five-second fix; a `nan` in an index is a day of investigation. This is
the single most valuable design decision in the module's code.

**`norm` uses `sqrt(dot(v, v))` rather than a separate sum of squares.** One definition, one place to
get it wrong, and it makes the identity `‖v‖² = v·v` visible in the code.

**`einsum('ij,ij->i', A, B)` for row-wise dot products.** The obvious `(A * B).sum(axis=1)` allocates
a full `(n, d)` temporary; `einsum` does not. At 20,000 pairs in 4096 dimensions that is 640 MB of
avoided allocation.

**Wrong turns worth knowing about.**

1. *Using `np.linalg.norm(A, axis=1)` without `keepdims=True`.* It returns `(n,)`, and dividing an
   `(n, d)` matrix by it either errors or broadcasts along the wrong axis. With `keepdims=True` you
   get `(n, 1)`, which broadcasts across columns correctly. This is the most common bug in the module.
2. *Concluding that Euclidean distance is "wrong".* It is not — it answers a different question. The
   cats/tax-law example shows it ranking the two cat documents as further apart than a cat document is
   from tax law, and both facts are true of the *points*. The error is asking a length-sensitive
   question when you wanted a direction-sensitive one.
3. *Measuring concentration with unnormalised Gaussian vectors.* The norm of a `d`-dimensional
   Gaussian concentrates around `sqrt(d)`, which mixes a norm effect into the distance measurement.
   Normalise first, so you are measuring angular structure only.

## Grading notes

**What 3/3 looks like**

- *Correctness* — zero-vector guards on every function; NumPy agreement to 1e-6 on 1,000 inputs; the
  unit-vector identity `‖u−v‖² = 2 − 2(u·v)` verified.
- *Code quality* — `norm` supports p = 1, 2, ∞ through one implementation; docstrings state shapes.
- *Performance* — the concentration table across the full range of `d`, plus the `1/sqrt(d)` rate
  checked rather than asserted.
- *Explanation* — two sentences on what concentration means for vector search **and** why embeddings
  work anyway (low intrinsic dimension). Stopping at the first half is the common failure.

**The three most common ways submissions lose points**

1. **`keepdims` omitted**, producing a silently wrong normalisation that still has the right shape.
2. **The concentration result stated without the caveat.** "Nearest neighbour is meaningless in high
   dimensions" is false for real embeddings, and a submission that says it has learned the wrong
   lesson.
3. **Zero vectors unhandled.** Easy to miss because random test data never produces one, and certain
   to appear in production the first time a document is empty.
