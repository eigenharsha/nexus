## Reference solution — `LAB-P2-W13`

The individual structures are in the module pages. This page is about the two things the lab is
actually assessing: **the benchmark harness** and **`RESULTS.md`**.

### The harness

```python
# pycollections/bench.py
from __future__ import annotations
import gc, math, resource, subprocess, sys, time
from dataclasses import dataclass


@dataclass(frozen=True, slots=True)
class Measurement:
    name: str
    n: int
    seconds: float
    peak_rss_mb: float


def best_of(fn, reps: int = 5) -> float:
    """Minimum, not mean. The mean folds in every unrelated thing the machine
    did during the run; the minimum is the closest estimate of the work itself."""
    best = math.inf
    for _ in range(reps):
        gc.collect()
        t = time.perf_counter()
        fn()
        best = min(best, time.perf_counter() - t)
    return best


def fit_exponent(sizes, times) -> float:
    """Slope of log(time) vs log(n) IS the exponent, if time = a*n^k."""
    xs = [math.log(n) for n in sizes]
    ys = [math.log(t) for t in times]
    mx, my = sum(xs) / len(xs), sum(ys) / len(ys)
    return (sum((x - mx) * (y - my) for x, y in zip(xs, ys))
            / sum((x - mx) ** 2 for x in xs))


def measure_in_subprocess(module: str, case: str) -> Measurement:
    """Peak RSS is a process high-water mark and never decreases. Measuring
    several structures in one process makes them all report the first one's peak."""
    out = subprocess.run([sys.executable, "-m", module, case],
                         capture_output=True, text=True, check=True).stdout
    name, secs, mb = out.strip().split(",")
    return Measurement(name, 0, float(secs), float(mb))
```

Three decisions, each of which a naive harness gets wrong:

- **Best-of, not mean.** State it in `RESULTS.md`. A mean is a measurement of your laptop's mood.
- **One structure alive at a time.** Build, measure, `del`, `gc.collect()`, then build the next.
  Three large structures coexisting evict each other from cache and the last one measured looks
  slowest, for reasons that have nothing to do with it.
- **`ru_maxrss` in a subprocess** for memory. `tracemalloc` costs ~30× on an allocation-heavy loop
  (see the module-5 solution) and misses native allocations entirely.

### `RESULTS.md`: the structure that gets full marks

```markdown
# Constants vs Big-O — measured

## Environment
Apple M3 Pro, 18 GB, macOS 15.2 · CPython 3.12.9 (Homebrew)
Timing: time.perf_counter, best of 5, gc.collect() between reps
Memory: resource.getrusage(RUSAGE_SELF).ru_maxrss, one subprocess per case

## Results
| structure | operation | n | ns/op | fitted exponent | theory |
| ...

## Where measurement disagreed with theory
### 1. `list.sort()` measures an exponent of 1.09, not the ~1.15 expected for n log n
...
### 2. My open-addressed table is 2.08x SLOWER than chaining at load factor 0.95
...
### 3. `dict` is 5-12x faster than both of my implementations at every load factor
...

## What I would actually ship
For each structure: would I use mine in production? Almost always no, and here is
what writing it taught me that importing it would not have.
```

**The "Where measurement disagreed" section is the deliverable.** Everyone's `HashMap` looks the
same. The paragraph explaining why yours behaved unexpectedly is the thing an interviewer reads.

### The disagreements you should find

If your `RESULTS.md` has none, your sweep is too narrow. These four are reliably there:

| Observation | Explanation |
| --- | --- |
| A genuinely linear operation fits an exponent above 1.1 | cache behaviour: at n=10³ the data is in L1, at n=10⁶ it is not. The algorithm is O(n); the machine is not |
| `list.sort()` cannot be distinguished from O(n) by the fit | over a 64× range of n, `log₂ n` moves only 1.6× — invisible in a log-log fit |
| Open addressing beats chaining below α ≈ 0.75 and loses above | contiguous probing versus a dereferenced Python list object, then primary clustering takes over |
| `dict` beats both hand-rolled tables by 5–12× | CPython's compact dict: a dense entries array plus a sparse `int8`/`int16` index table, probing with high hash bits |

## Why this solution and not the obvious one

**Why the report is a graded artifact and the code is not.** The structures are textbook and everyone
arrives at roughly the same code. The measurement discipline — best-of, isolation, subprocess memory,
stated environment — and the willingness to write down a result that contradicts expectation are the
transferable skills. That is what `bench-smoke` failing on a missing `RESULTS.md` is enforcing.

**Why `hypothesis` property tests against `dict` and `sorted()`.** Five hand-written cases will not
contain: a key that hashes negative, a resize triggered mid-sequence, a delete of a key that
collided with a still-present one, or `NaN` in the heap. Random operation sequences find all four in
under a second.

## Grading notes

**3/3 on Correctness** — structural invariants asserted (not just behaviour), property tests against
`dict` and `sorted()`, and the delete-heavy churn test for the open-addressed table.

**3/3 on Performance** — swept across four sizes, exponents fitted, per-structure memory measured in
subprocesses, and a stated baseline beaten *or* an honest loss with a profile.

**3/3 on Explanation** — at least two measurement-versus-theory disagreements, correctly attributed.
"Measurement noise" is not an attribution unless accompanied by a variance figure showing the spread
exceeds the effect.

**The three most common ways submissions lose points:**

1. **`RESULTS.md` with no environment block.** CPU, RAM, OS, Python version, timing method. Without
   them the numbers are anecdotes and nobody can reproduce or dispute them.
2. **Every row agreeing with theory.** Almost certainly means the sweep stopped at 10⁴, before cache
   effects appear. Sweep to 10⁶.
3. **Reporting the mean, or using `time.time()`.** `time.time()` has ~15 ms resolution on some
   platforms — larger than several of the measurements in this lab.

**On the `hard` track.** Beating `dict` in pure Python is very unlikely, and **an honest loss with a
profile earns full marks.** What loses marks is a claimed win with no committed benchmark script, or
a win that does not state what generality was given up. If someone genuinely wins — usually with
`array.array` storage plus a minimal perfect hash over a frozen key set — check for a test
demonstrating the failure mode they accepted, such as "inserting after freeze raises".
