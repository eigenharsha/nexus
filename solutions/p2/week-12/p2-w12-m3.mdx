## Reference solution — `P2-W12-M3`

### The paired bootstrap — the ten lines that decide model comparisons

```python
B = 10_000
idx = rng.integers(0, len(yt), size=(B, len(yt)))   # ONE index set, reused for BOTH models
bA = np.array([f1_of(yt[i], predA[i]) for i in idx])
bB = np.array([f1_of(yt[i], predB[i]) for i in idx])
diff = bB - bA
print(f"paired difference 95% CI [{np.percentile(diff,2.5):+.4f}, {np.percentile(diff,97.5):+.4f}]")
print(f"P(B > A) = {(diff > 0).mean():.4f}")
```

**The single most important line is `idx`.** One index array, used for both models. If you generate a
separate resample for each model, you have destroyed the pairing and thrown away the correlation that
makes the comparison powerful.

### Wilson, because Wald is broken

```python
def wilson(k, n, conf=0.95):
    z = stats.norm.ppf(1 - (1 - conf) / 2)
    p = k / n; denom = 1 + z**2 / n
    centre = (p + z**2 / (2*n)) / denom
    half = z * np.sqrt(p*(1-p)/n + z**2/(4*n**2)) / denom
    return centre - half, centre + half
```

`wilson(0, 100)` gives `(3.47e-18, 0.03699)`. The Wald interval gives `(0.0, 0.0)` — a zero-width
interval asserting the rate is exactly zero, from 100 observations.

## Why this solution and not the obvious one

**The paired difference, not two intervals.** Measured on real models: A's CI is `[0.8898, 0.9527]`,
B's is `[0.9251, 0.9742]`, and they **overlap**. The paired difference CI is `[+0.0074, +0.0538]`,
entirely above zero, with `P(B > A) = 0.9966`.

Both computations are correct. Only the second answers the question. When both models are evaluated on
the same items, a resample containing hard items hurts *both*, so the shared noise cancels in the
difference and the interval on the difference is far tighter than either individual interval suggests.

**Welch, not Student.** SciPy's `ttest_ind` defaults to `equal_var=True`. Equal variance is an
assumption you almost never have grounds for and dropping it costs nothing.

**Relative error for gradcheck-style comparisons, percentile bootstrap by default, BCa when skewed.**

**Wrong turns worth knowing about.**

1. *Concluding "no significant difference" from overlapping intervals.* This is the module's core error
   and it cost a real team six months of a shelved improvement.
2. *Separate resamples per model.* Silently destroys the pairing; the difference interval becomes as
   wide as the unpaired one and the conclusion flips back.
3. *Bootstrapping autocorrelated data.* Latency measurements taken in sequence are correlated (a GC
   pause slows several consecutive requests), so the ordinary bootstrap under-covers badly. Use a block
   bootstrap.
4. *Gradcheck-style comparisons in float32, or bootstrapping with `B = 200`.* Both produce noise
   masquerading as a result.
5. *Post-hoc power analysis.* Computing power after a null result just restates the p-value.

## Measured numbers this solution produces

Two naive Bayes classifiers (`alpha=1.0` and `alpha=0.1`) on the same 1,115-message test set, 10,000
bootstrap resamples:

| | Value |
|---|---|
| Model A F1 | 0.9231 |
| Model B F1 | 0.9518 |
| Observed difference | +0.0287 |
| A 95% CI | [0.8898, 0.9527] |
| B 95% CI | [0.9251, 0.9742] |
| **Paired difference 95% CI** | **[+0.0074, +0.0538]** |
| P(B > A) | **0.9966** |
| Individual CIs overlap? | **Yes** |

Interval half-width against `n` on a normal population (true mean 100):

| n | sample mean | 95% CI half-width |
|---|---|---|
| 10 | 98.313 | 12.005 |
| 30 | 98.764 | 4.246 |
| 100 | 99.432 | 2.977 |
| 1000 | 99.459 | 0.996 |
| 10000 | 99.867 | 0.297 |

100× the data gives 10× the precision. Sample size for two means at 80% power: d=0.2 needs 393 per
group, d=0.5 needs 63, d=0.1 needs 1,570.

## Grading notes

**What 3/3 looks like**

- *Correctness* — coverage of the percentile interval verified by simulation at 95% ± 2pp; the paired
  bootstrap uses one shared index array; Wilson handles `k = 0`.
- *Code quality* — `bootstrap_ci(data, statistic)` takes the statistic as a function, so it works for
  mean, median, p99, F1 and AUC without modification.
- *Performance* — the bootstrap vectorised enough that 10,000 resamples of a 1,000-row test set is
  seconds, not minutes.
- *Explanation* — the write-up states clearly that the individual CIs overlap **and** that B is better,
  and explains why both are true.

**The three most common ways submissions lose points**

1. **Unpaired resampling.** The single most common bug, and it silently reproduces the error the module
   exists to correct.
2. **The overlapping-CI result reported without explanation.** The numbers alone look like a
   contradiction; the explanation is the deliverable.
3. **No coverage check.** A bootstrap implementation that has not been validated by simulation is
   untested, and coverage is the only meaningful test.
