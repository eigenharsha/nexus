## Reference solution — `LAB-P2-W14`

Solutions to fifteen medium problems are widely available and are not the point. **The journal is
the deliverable**, and this page covers the four problems where the interesting mistake lives, plus
what a full-marks journal entry looks like.

### Problem 11 — cheapest flights within K stops

**This is the one that carries the marks**, because Dijkstra is wrong here and the reason is subtle.

```python
# WRONG: Dijkstra with a stop counter.
heapq.heappush(pq, (cost, stops, city))
# Dijkstra finalises a node the FIRST time it pops it. But a MORE EXPENSIVE route
# reaching a city in FEWER stops can be the only viable one under the limit —
# so finalising on cost alone discards the answer.
```

The counterexample to put in the journal:

```
src=0, dst=3, K=1 (at most one intermediate stop)
0 → 1 cost 100
1 → 2 cost 100
2 → 3 cost 100     (total 300, but 2 stops — exceeds K)
0 → 3 cost 500     (total 500, 0 stops — the only legal route)
```

Dijkstra pops city 3 at cost 300 and finalises it. The answer is 500.

```python
# RIGHT: Bellman-Ford bounded to K+1 rounds.
dist = [inf] * n; dist[src] = 0
for _ in range(K + 1):
    snapshot = dist[:]                    # <-- relax from a SNAPSHOT
    for u, v, w in edges:
        if snapshot[u] + w < dist[v]:
            dist[v] = snapshot[u] + w
return dist[dst] if dist[dst] < inf else -1
```

**The snapshot is the whole trick.** Each round must extend every path by *exactly one* edge. Relax
in place and a path improved earlier in the same round gets extended again, so round `r` produces
paths of more than `r` edges and the stop limit is not enforced. **This bug passes most tests**,
because it only matters when a longer-but-cheaper path exists.

### Problem 12 — coin change

The journal must contain a coin set where greedy fails:

```
coins = [1, 3, 4], target = 6
greedy: 4 + 1 + 1 = 3 coins
optimal: 3 + 3     = 2 coins
```

Greedy is optimal for canonical systems (including all real currencies, which is why the intuition
is so strong) and not in general. **Stating the counterexample is what demonstrates you know why DP
is required rather than that DP is the answer.**

### Problem 9 — Pacific-Atlantic water flow

The insight: **search backwards from the oceans, not forwards from each cell.** Forwards is a
separate BFS per cell — `O((rows·cols)²)`. Backwards is two multi-source BFS runs from the border
cells, flowing *uphill*, and the answer is the intersection: `O(rows·cols)`.

Journal entry: *"First idea: BFS from every cell to see if it reaches both oceans. O((rc)²) — too
slow at 200×200. Working: two multi-source BFS from the ocean borders, moving to strictly-higher
neighbours; the answer is the intersection of the two reachable sets. O(rc)."*

### Problem 8 — word ladder

The graph is **not given**; you generate neighbours on demand. The naive neighbour generation is
`O(n)` per word (compare against every other word); the right version is `O(len · 26)` via wildcard
buckets:

```python
from collections import defaultdict
buckets = defaultdict(list)
for w in wordlist:
    for i in range(len(w)):
        buckets[w[:i] + "*" + w[i+1:]].append(w)
```

**BFS, not DFS**, because the question asks for the *shortest* transformation.

### The journal entry that gets 3/3

> **11. Cheapest flights within K stops.**
> *First idea:* Dijkstra carrying the stop count in the priority queue. O((V+E) log V).
> *Why it failed:* Dijkstra finalises a node the first time it pops it, but a more expensive route
> reaching a city in fewer stops can be the only one under the limit. Broke on a 4-city graph where
> the cheap route used 2 stops and the limit was 1 — it returned 300, the answer was 500.
> *Working approach:* Bellman-Ford bounded to K+1 relaxation rounds. Each round extends every path
> by exactly one edge, so the round index *is* the hop count. Relax from a snapshot of the previous
> round, or one round leaks into the next.
> *Complexity:* O(K·E) time, O(V) space.

Ninety seconds to write, and it is exactly what you would say aloud in an interview.

## Why this solution and not the obvious one

**Why the journal rather than the solutions.** Fifteen solved problems are worth nothing to an
interviewer — the internet is full of them and they are discounted on sight. **A record of fifteen
wrong first ideas and why each was wrong is evidence of how you think**, which is the only thing a
technical screen assesses. Hence `make journal` failing on a missing "failed first idea" field.

**Why the route planner reports expansions.** Expansions are deterministic and comparable across
machines; wall time is not. And the `--compare` mode asserting both algorithms return the same cost
is what turns "I implemented A*" into "I implemented A* and verified it".

**Why the ≥3× requirement is set above what plain Manhattan achieves.** Measured, plain Manhattan
gives 1.49×. The gap is deliberate: reaching 3× requires either better tie-breaking, a stronger
admissible heuristic (ALT), or accepting bounded suboptimality — and **choosing between those three
is the actual engineering content of the track.**

## Grading notes

**3/3 on Explanation** — all four journal fields for all fifteen, the Dijkstra counterexample for
problem 11, and the failing greedy coin set for problem 12.

**3/3 on Correctness** — edge cases per problem: empty input, a single node, a disconnected graph,
and an unreachable target.

**3/3 on Performance** — the route planner's expansion ratio averaged over ≥100 random pairs with the
distribution reported, plus the empirical admissibility check on ≥1,000 sampled nodes.

**The three most common ways submissions lose points:**

1. **Journal entries with no failed first idea.** The field that makes the artifact valuable is the
   one omitted. Write the wrong idea down *while you are having it*.
2. **Problem 11 solved with Dijkstra plus a stop counter, "and it passed".** It passes tests that do
   not contain a longer-but-cheaper path. The counterexample is four edges.
3. **Recursive tree and graph traversals.** Crash on deep real input; pass every fixture.

**A fourth:** problem 11 with Bellman-Ford relaxing in place rather than from a snapshot. It produces
*better* answers than the correct algorithm on some inputs, which looks like success. It is
computing the unbounded shortest path and ignoring the stop limit.
