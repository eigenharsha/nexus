## Reference solution — `P2-W11-M3`

### Power iteration with deflation

```python
def power_iteration(M, iters=1000, tol=1e-12, seed=0):
    rng = np.random.default_rng(seed)
    v = rng.standard_normal(M.shape[0]); v /= np.linalg.norm(v)
    lam_prev = 0.0
    for _ in range(iters):
        w = M @ v
        nw = np.linalg.norm(w)
        if nw == 0:
            return 0.0, v
        v = w / nw
        lam = float(v @ M @ v)                       # Rayleigh quotient
        if abs(lam - lam_prev) < tol * max(1.0, abs(lam)):
            break
        lam_prev = lam
    return lam, v

def deflate(M, lam, v):
    return M - lam * np.outer(v, v)                  # remove the found eigenpair
```

### PCA and low-rank

```python
def pca_svd(X, k):
    X = np.asarray(X, dtype=np.float64)
    mean = X.mean(axis=0, keepdims=True)
    U, S, Vt = np.linalg.svd(X - mean, full_matrices=False)
    return dict(scores=(U[:, :k] * S[:k]), components=Vt[:k],
                explained_ratio=S**2 / (S**2).sum(), mean=mean, singular_values=S)

def low_rank(A, k):
    U, S, Vt = np.linalg.svd(A, full_matrices=False)
    return (U[:, :k] * S[:k]) @ Vt[:k]

def lora_params(d_out, d_in, r):
    full, lora = d_out * d_in, r * (d_out + d_in)
    return dict(full=full, lora=lora, fraction=lora/full, reduction=full/lora)
```

## Why this solution and not the obvious one

**The Rayleigh quotient `v @ M @ v` rather than the norm of `M @ v`.** Both converge to the dominant
eigenvalue's magnitude, but the Rayleigh quotient gets the **sign** right and converges quadratically
for symmetric matrices rather than linearly. On a matrix whose dominant eigenvalue is negative, the
norm-based version returns the wrong sign and everything downstream is wrong.

**Convergence is tested on the eigenvalue, not the eigenvector.** The eigenvector's sign can flip
between iterations (both `v` and `−v` are valid), so a vector-based convergence test can loop forever.

**PCA is computed by SVD of the centred data, never by eigendecomposition of the covariance.** Forming
`XᵀX` squares the condition number, which halves your accurate digits for no benefit. `sklearn` does
this for the same reason and says so in its documentation.

**Wrong turns worth knowing about.**

1. *Forgetting to centre before PCA.* The first component becomes the direction of the mean, which is
   almost never informative. Assert that the centred columns have means below 1e-12.
2. *Forgetting to standardise features with different units.* This is the war story: a fraud model's
   AUC fell from 0.91 to 0.83 because transaction amount (variance ~10⁶) dominated every component.
3. *Claiming a compression ratio without checking it.* At `k = 400` on a 427×640 image, storage is
   427,200 values against the original 273,280 — the "compression ratio" is **0.64×**, i.e. it is
   bigger. Low-rank only pays below `k ≈ mn/(m+n)`.
4. *Using PCA as supervised feature selection.* It maximises variance, which has no relationship to
   predictive signal; rare high-signal features have tiny variance and are discarded first.

## Grading notes

**What 3/3 looks like**

- *Correctness* — power iteration matches `eigvalsh` including sign; the Eckart–Young bound verified to
  1e-8; explained-variance ratios sum to 1.
- *Code quality* — one `low_rank`, used for both the image and the synthetic test; PCA returns the mean
  so the transform is reproducible on new data.
- *Performance* — the full compression table including the row where compression drops below 1×.
- *Explanation* — the LoRA connection stated as the *same arithmetic*, with both sets of numbers, plus
  a statement of when the low-rank assumption fails.

**The three most common ways submissions lose points**

1. **Only the compression ratio reported, not the error.** Energy, relative error and PSNR tell
   different stories — 98.08% energy sounds excellent and looks mediocre.
2. **The LoRA connection asserted, not computed.** "LoRA is low-rank approximation" without the
   parameter counts is a slogan.
3. **PCA fitted on unscaled features.** Instantly visible: one feature's loading dominates the first
   component.
