## Reference solution — `LAB-P4-W31`

### Shape of the repository

```
week-31-evals/
├── EVALS.md              # what it measures, the taxonomy, the judge's kappa, WHAT IT CANNOT SEE
├── RED-TEAM.md           # 15 attacks, outcomes, mitigations labelled probability/consequence
├── evals/
│   ├── cases.yaml        # 120+ cases, tagged: category, origin, added date
│   ├── assertions.py     # tier 1 — free, exact, runs on every commit
│   ├── judge.py          # tier 3 — binary criteria, reasoning first

└── tests/                # 44 tests, no API calls, under 15 s
```

Two files a reviewer opens first: `EVALS.md` and `RED-TEAM.md`. Make them the best two files in the
repository, and put the honest sections near the top.

### The CI comment that makes this useful

```
## Eval results — PR #214 (prompts/system_v7.txt)

| Category            | main | this PR |     |
|---------------------|------|---------|-----|
| missing entity      | 0.94 |    0.96 |  +2 |
| ungrounded claim    | 0.91 |    0.88 |  -3 |
| wrong format        | 1.00 |    1.00 |     |
| should have refused | 0.83 |    0.85 |  +2 |
| overall             | 0.91 |    0.92 |  +1 |

Newly failing: ord-multi-item, refund-partial
Mean output length: 212 words -> 288 words   <-- check verbosity before celebrating
Judge: kappa 0.71 (threshold 0.60) OK · suite runtime 4m12s · cost $0.83
```

Three things that make this comment worth reading: **per-category**, so a reviewer sees *what* moved;
**newly-failing ids**, because a flat overall can hide two regressions offset by two improvements;
and **mean output length**, which is the one-line check that would have caught this week's
verbosity war story on day one.

### The five things that separate a 3/3 from a 2/3

1. **`EVALS.md` has a "what this cannot see" section.** Ours names three: tone, anything requiring the context to be *true* rather than merely used, and traffic shapes we have no cases for.
2. **The judge is validated on labels it was never tuned against.** Tune on 25, validate on a held-out 25, report both. Tuning and validating on the same 50 is testing on the training set.
3. **`RED-TEAM.md` labels every mitigation** probability or consequence, and contains at least one attack that still works with an accepted-risk justification.
4. **The guardrail sweep has a lookalike column** and a blocked-users-per-10,000 column.
5. **The suite runs inside the budget** — under 6 minutes and $1.20 — and the write-up says which levers got it there.

## Why this solution and not the obvious one

**Obvious:** run the judge on every case for maximum coverage. It blows both budgets. Assertions
first with short-circuiting, exact-containment pre-filter before any judge call (41% fewer calls at
identical scores), cheap model for mechanical criteria, and concurrency. That is how 4m12s and $0.83
happen.

**Obvious:** gate the build on the overall score. Gate on **newly-failing cases** instead. An overall
threshold lets four improvements pay for one safety-category regression, and that is exactly the
trade you must not make automatically.

**Obvious:** put the guardrails in and call the security work done. Module 4's numbers: guardrails
alone left 4 of 15 attacks effective; scoping write tools out of the untrusted context left 0. The
security section of your write-up should lead with the architecture and mention the guardrails second.

## Grading notes

**Automatic caps.** No `EVALS.md` → maximum 60. No `RED-TEAM.md` → maximum 60. A judge below its
stated threshold wired into the gate → the Measurement row is 0 and the lab does not pass. Any
claimed improvement smaller than the suite's detectable difference → maximum 75.

**A 3/3 submission** reads like a measurement report written by someone who was actively trying not
to fool themselves: the taxonomy from real reading, the judge's kappa progression with its ceiling,
the attribution experiment including the fault nothing caught, the red-team table with two columns,
and the guardrail sweep with the segment where it fails. The honest sections are what make it
credible; a submission with no negative results has not finished.

**The three most common losses:** a judge validated on the cases it was tuned on; a guardrail
measured without lookalikes; and a red-team report with a single compliance column.
