## Reference solution — `P4-W27-M5`

### The task

Build the 100-query eval set and run the ablation. Every Week 28 change must be justified against it.

### The solution that works

Generation, then review, then the funnel recorded. The prompt matters more than the code:

```
Write a question a real user would type into a search box. Use at most 12 words.
Do NOT mention the section number, the document title, or any phrase copied from
the passage. Prefer the words a non-expert would use.
```

And the guard that keeps the eval set honest over time:

```python
def load_eval(path, corpus_hash):
    data = json.load(open(path))
    if data["corpus_hash"] != corpus_hash:
        raise RuntimeError(
            f"eval set labelled against corpus {data['corpus_hash'][:8]}, "
            f"current corpus is {corpus_hash[:8]}. Re-resolve gold spans or re-label.")
    return data["items"]
```

### Why this solution and not the obvious one

**The obvious eval set is generated and not reviewed.** Reference figure: an unreviewed
generated set scores 0.91 where hand-labelled real user queries score 0.61 — thirty points, and
the production number was the low one. The mean query length tells you immediately: 21 tokens for
generated, 4.3 for real users.

**The obvious ablation reports point estimates.** Rows 4, 5 and 6 are not significant on Recall@10
and the table must say so. Keeping row 5 anyway is correct — its NDCG gain is real and reranking
will build on it — but that reason has to be written down, because "we kept a change that did not
move the primary metric" is otherwise indistinguishable from carelessness.

### The two wrong turns worth knowing about

**Wrong turn 1: storing gold as chunk IDs.** Re-chunk at a different size and the eval set is
silently invalid. Store `(doc_id, char_start, char_end)` and resolve at eval time, with the corpus
hash guard above so the failure is loud rather than silent.

**Wrong turn 2: tuning against the eval set and then reporting from it.** After a dozen changes
guided by these 100 queries, the number is optimistic by an unmeasurable amount. Hold back the other
80 candidates as a test set, open it once at the end of Week 28, and report both.

### Grading notes

**3/3** requires the funnel with discard reasons, gold stored as character spans with a corpus-hash
guard, paired bootstrap CIs on every row, non-significant rows explicitly labelled, and the failure
attribution split. **The three most common point losses:** an unreviewed generated eval set, which
inflates every number in Week 28 as well; deltas without CIs; and no held-out set, which means the
final Week 28 number cannot be trusted no matter how carefully the intermediate ones were measured.
