## Reference solution — `P4-W27-M1`

### The task

Parse 50 messy PDFs, produce a parse-quality scorecard, fix the worst 5, and show the delta.

### The solution that works

The pipeline is Module 1 Layer 2's `ingest.py`. The part worth reproducing is the routing rule,
because "run the expensive parser on everything" is the wrong answer and "run the fast one on
everything" loses 11 points of recall:

```python
def route(rep: DocReport) -> str:
    if rep.needs_ocr:
        return "ocr_then_fast"
    if rep.chars_per_page < 400:
        return "hi_res"
    if sum(p.tables for p in rep.pages) > len(rep.pages) * 0.3:
        return "hi_res"
    if sum(p.two_column for p in rep.pages) > len(rep.pages) * 0.5:
        return "fast_column_aware"
    return "fast"
```

### Why this solution and not the obvious one

**The obvious solution routes everything through `unstructured` with `hi_res`.** It gets marginally
better quality (+0.03 on the full corpus) at 80× the wall clock — 5.6 minutes becomes 7.5 hours on
1,000 documents. That turns a nightly ingest into a weekly one, which turns a freshness problem into
a product complaint. Route by scorecard features; measured, routing the hard 14% gets +0.025 at 12×
rather than 80×.

**The second obvious solution drops documents that fail to parse.** They must be *counted* and
*listed*, not dropped. A dropped document is indistinguishable from a document that has no answer
in it, and that ambiguity is exactly what made the war-story team spend three weeks on embeddings.

### The two wrong turns worth knowing about

**Wrong turn 1: batch-level error handling.** One `try/except` around the whole loop means one
encrypted PDF aborts a 9-minute run at document 700. Per-document isolation with a recorded failure
list is four extra lines and it is the difference between a pipeline and a script.

**Wrong turn 2: the header detector eating real content.** Detecting "lines that appear on more than
60% of pages" works on a 40-page manual and destroys a 3-page memo, where a section title trivially
exceeds 60%. Require a minimum page count — 5 works — before header detection runs at all. The
symptom is that your shortest documents lose their titles, which is invisible in an aggregate
scorecard and very visible in retrieval.

### Grading notes

**3/3** requires the full scorecard, per-document error isolation, the before/after Recall@10 on the
same eval questions, and a routing rule rather than a blanket strategy. **The three most common
point losses:** dropping unparseable documents silently instead of counting them; reporting a parse
scorecard with no retrieval delta attached, which measures characters rather than quality; and
running `hi_res` on everything, which is defensible only if you also report the wall clock.
