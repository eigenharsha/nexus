## Reference solution — `P4-W30-M3`

### The 50-turn benchmark, and how to score it without a human

Plant facts that are *machine-checkable*. Identifiers, dates, amounts — never opinions.

```python
FACTS = [
    ("order",  "ORD-100281", "My order is ORD-100281.",         2),
    ("email",  "asha@example.com", "Send it to asha@example.com.", 5),
    ("date",   "2026-07-14", "It was delivered on 2026-07-14.",  9),
    # ... 12 total, planted at turns 2..30
]
QUESTIONS = [("order", "What was my order number?", 36), ...]   # asked at turns 35..50

def score(transcript) -> int:
    return sum(1 for kind, value, _, _ in FACTS
               if value in answer_for(transcript, kind))       # exact substring match
```

Exact substring match on the identifier, not semantic similarity. If the model says "your order was
ORD-100821" that is a *failure*, and a similarity-based scorer will call it a pass. The entire point
of the benchmark is to catch confident near-misses.

| Input tokens | 613,750 | 244,750 | 342,500 |
| Facts recalled | 11/12 | 6/12 | 11/12 |
| Cost | $3.34 | $1.50 | $2.03 |
| Cost per recalled fact | $0.304 | $0.250 | **$0.185** |

With prompt caching on the 6,400-token prefix, the prefix portion falls from $1.60 to $0.197 —
87.7%. Verify with `usage.cache_read_input_tokens`, not by looking at the bill three days later.

## Why this solution and not the obvious one

**Obvious:** the window is 1M tokens, so send everything. Two objections and the second is the one
people miss. It costs $3.34 for a single 50-turn conversation. And it *still lost a fact*: at turn
50 the transcript is ~55,000 tokens, and our own needle measurements show 5-needle recall already
falling by 32,000. More context is not monotonically better even when money is free.

**Obvious:** summarize everything, drop the window. We tried it: 8/12 recall at $1.71. Summaries
lose identifiers no matter how hard the prompt insists, because compression is lossy and an order
reference is high-entropy. Identifiers must be *stored*, not summarized. This is why the hybrid has
three tiers and not two.

**Obvious:** retrieve only when the model asks. Tool-only recall found 7/12. The model does not know
what it has forgotten — absence is not perceptible. Unconditional injection of the top 3 took it to
11/12 for about 600 tokens a turn.

## The two wrong turns worth knowing about

1. **`k=10` instead of `k=3` on injected memories.** Recall of the *targeted* facts stayed flat, and recall of other facts fell 6 points. Irrelevant injected context is not merely wasted — it actively competes. Tune k; do not assume more is safer.
2. **A timestamp in the system prompt.** `"Current time: 2026-08-20T14:03:11Z"` took `cache_read_input_tokens` to zero for the entire benchmark and we spent an afternoon believing caching did not work. Put volatile content *after* the last cache breakpoint, and assert on the cache-read counter in a test.

## Grading notes

**3/3 on Correctness:** the tail-repair logic is tested (a window that would begin with an orphaned
`tool_result` is corrected), the first user message is never dropped, and compaction fires on a
schedule you can assert on.

**3/3 on Explanation:** a written keep/summarize/retrieve policy for your own domain, committed next
to the code, with a justification per row.

**Common losses:**
- Scoring with semantic similarity, which hides the near-miss failure this module exists to expose.
- Reporting tokens but not dollars, or dollars but not recall. The metric is cost *per recalled fact*.
- No `superseded_by`. A store that updates in place cannot answer "what did the agent know last Tuesday", which is the first question asked in every incident review.
