## Reference solution — `P3-W18-M2`

The task: demonstrate the feature-importance trap by injecting a random high-cardinality ID column and showing it ranking first under impurity importance.

## The construction that makes the trap unmissable

The design decision that most submissions get wrong is the choice of *honest* features. Use continuous informative features and the trap is muted, because the real features also have many split points and can compete. Use **binary** informative features and the contrast is stark, because a binary feature offers exactly one candidate split and the ID offers `n - 1`.

```python
# scikit-learn 1.9.0, numpy 2.5.2, pandas 3.0.5
import numpy as np, pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split
from sklearn.inspection import permutation_importance

rng = np.random.default_rng(0); n = 4000
B = rng.integers(0, 2, size=(n, 5)).astype(float)          # 5 BINARY informative features
logit = 1.2*B[:,0] + 0.9*B[:,1] + 0.7*B[:,2] + 0.5*B[:,3] + 0.3*B[:,4] - 1.8
y = (rng.uniform(size=n) < 1/(1 + np.exp(-logit))).astype(int)
cust = rng.permutation(n).astype(float)                     # unique per row, ZERO information
X = np.c_[B, cust]
names = [f"bin_{i}" for i in range(5)] + ["customer_id"]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
rf = RandomForestClassifier(n_estimators=500, random_state=0, n_jobs=-1).fit(Xtr, ytr)
```

## The three numbers

**1. The trap.**

```
customer_id   0.8182       <-- a random permutation of 0..n-1
bin_0         0.0803
bin_1         0.0404
bin_2         0.0300
bin_3         0.0158
bin_4         0.0152
```

**81.8% of all impurity importance** goes to a column with no information. It ranks first by a factor of ten.

**2. The damage.**

```
train accuracy                    1.0000
test accuracy WITH customer_id    0.5858
test accuracy WITHOUT             0.6650
```

Deleting the most "important" feature raises held-out accuracy by **7.9 points**. Train accuracy of exactly 1.0000 is the tell: with a unique value per row the forest can memorise the entire training set through that one column.

**3. The fix, and its honest limit.**

```
permutation importance, held out, n_repeats=30:
  bin_0         +0.03181
  bin_1         +0.03006
  bin_2         +0.01878
  bin_4         +0.01236
  customer_id   +0.01189      <- 5th of 6, not zero
  bin_3         +0.00808
```

The three strongest real features are now on top, in the right order. `customer_id` is demoted from 1st to 5th — but it is **not zero**, and a report that claims permutation importance "correctly identifies it as useless" is overstating. The forest genuinely built rules on that column; shuffling it degrades those rules. Permutation importance answers "how much does this model rely on this column", which is the right question for a model audit but is not the same as "how much signal does this column carry".

## Why it happens, in one sentence you can defend

Impurity importance is the total training-set impurity decrease attributable to each feature. A feature with `n` distinct values offers `n - 1` candidate cut points at every node; a binary feature offers one. With that many attempts, the ID column will always find *some* cut that separates the rows in the current node a little — a separation that is pure chance and does not generalise. This is Quinlan's (1986) multi-valued bias, formalised for forests by Strobl et al. (2007).

Two independent defects, and it is worth naming both: **cardinality bias**, and **computed on training data**.

## Why this solution and not the obvious one

**The obvious solution adds the ID to a dataset like `load_breast_cancer` and expects it to rank first.** Measured, it does not — it lands **28th of 31**, because breast cancer's features are extremely informative continuous measurements that outcompete a random column at every node. A submission built that way concludes the trap is a myth.

Two more wrong turns:

1. **Running permutation importance on the training set.** On this exact model that gives `customer_id` a *large positive* score, because on training rows its memorised rules genuinely work. It is the correct computation applied to the wrong data and it inverts the conclusion. scikit-learn's documentation warns about it explicitly.
2. **Reporting only the mean permutation importance.** `permutation_importance` returns `importances_std` and `importances` (all repeats). With `n_repeats=30` the standard deviations here are of the same order as the smaller effects. A ranking whose neighbouring entries overlap within one standard deviation is not a ranking.

## Grading notes

**3/3 looks like:** the honest features are binary (or the submission explains why its choice still produces a clean contrast); the ID takes more than 50% of impurity importance; the drop-and-refit measurement shows held-out accuracy *increasing*; permutation importance is on held-out data with `n_repeats>=30` and reported with its standard deviation; and the write-up states that permutation importance for the ID is small-but-nonzero and explains why.

**The three most common ways submissions lose points:**

1. **Continuous informative features**, so the trap does not fire and the write-up concludes it is not real.
2. **Permutation importance on training data**, which reverses the finding.
3. **Claiming the ID's permutation importance is zero.** It is +0.0119 here. Rounding an inconvenient number to the story you wanted is the exact habit this module exists to break.
