## Reference solution — `P3-W20-M1`

The task: implement out-of-fold target encoding from scratch, and show the accuracy inflation of the naive version.

## Four arms, not two

Most submissions compare "leaky" against "correct" and miss the two most informative rows. The full picture, on 12,000 rows with a 1,200-level category (10 rows per category) and a deliberately weak category effect:

| Arm | Accuracy | ROC-AUC | Verdict |
| --- | --- | --- | --- |
| **no category feature at all** | 0.5965 | **0.6318** | **the floor — omit this and the rest is uninterpretable** |
| encode on the FULL dataset | 0.6798 | 0.7471 | +11.53 AUC points of fiction |
| encode on the training fold, apply to itself | 0.5927 | **0.6234** | **worse than not having the feature** |
| out-of-fold encoding | 0.5995 | **0.6423** | +1.05 AUC points of real signal |

**The two failure modes point in opposite directions**, and that is the finding worth writing up.

The full-dataset version inflates. With 10 rows per category, the encoding contains `1/10` of the row's own label and the model reads it off.

The in-fold version **degrades**. The cross-validation estimate is honest — nothing crossed the fold boundary — but the training rows saw an encoding computed partly from their own labels while the test rows saw one that was not. The model learned to trust a feature that behaves differently at prediction time, and it ended up below the no-feature floor.

Without the floor row you cannot see the second effect at all, which is why the acceptance criterion demands four arms.

## The implementation

The rule is one sentence: **a row's encoding must never be computed from that row's label.** That forces `transform` to behave differently on the fitting rows than on new rows, which is unusual and is where the bugs are.

```python
def fit(self, X, y):
    self.prior_ = float(y.mean())
    self.maps_ = {c: self._fit_map(X[c], y, self.prior_) for c in self.cols_}   # for NEW rows
    kf = KFold(self.n_splits, shuffle=True, random_state=self.random_state)
    self.oof_ = {c: np.empty(len(X)) for c in self.cols_}                       # for THESE rows
    for tr, va in kf.split(X):
        prior_in = float(y[tr].mean())
        for c in self.cols_:
            m = self._fit_map(X[c].iloc[tr], y[tr], prior_in)
            self.oof_[c][va] = X[c].iloc[va].map(m).fillna(prior_in).to_numpy()
    self._fit_index = np.asarray(X.index)
    return self
```

Verified: the published implementation reaches 5-fold AUC **0.6426**, matching the 0.6423 measured in the module body.

Two details that are easy to get wrong.

**The inner prior must be the inner fold's mean**, not the outer training fold's. Using the outer prior leaks a small amount of the validation rows' labels through the fallback for unseen categories — small, and it is exactly the kind of thing that turns a clean result into a slightly-inflated one.

**Unseen categories fall back to the prior, not to zero and not to `NaN`.** A `NaN` gets imputed by something downstream and you will not know by what.

## Smoothing is not the fix

The acceptance criterion asks you to show this, because it is the most common misconception in the area.

Out-of-fold, sweeping `m`:

```
m=0    AUC 0.6423        m=20   AUC 0.6426
m=1    AUC 0.6416        m=50   AUC 0.6418
m=5    AUC 0.6389        m=200  AUC 0.6423
```

Essentially flat. And the same sweep applied to the **leaky** version:

```
full-dataset encoding, m=0    AUC 0.7471
full-dataset encoding, m=20   AUC 0.7436
full-dataset encoding, m=200  AUC 0.7438
```

**The inflation is untouched.** Smoothing changes the leaked fraction from `1/n_c` to `1/(n_c + m)` — at `n_c = 10` and `m = 20` the row still supplies 3.3% of its own encoding — and the model can still invert it. **Smoothing is a variance control. Out-of-fold is the leakage control.** They are different problems and doing one while believing you have done the other is the expensive mistake.

## Why this solution and not the obvious one

**The obvious solution uses a strong category effect**, so the leak is masked by real signal and the demonstration fails. Design the dataset so the category is genuinely weak and the ratio `n/cardinality` is around 10 — then the leak has room to be visible and the honest gain is small enough to be believable.

Two more wrong turns:

1. **Applying the full-training map to the training rows inside `fit_transform`.** This is the in-fold version, and because it does not inflate the score, nothing alerts you. The model is just quietly worse. The test that catches it is comparing against the no-feature floor.
2. **Using `sklearn.preprocessing.TargetEncoder` and stopping.** It is the right production choice and it does the out-of-fold work correctly. But the failure mode is invisible from the API, and having written the inner-fold loop once is what lets you recognise the broken version in somebody else's code.

## Grading notes

**3/3 looks like:** four arms including the no-feature floor; the in-fold version scoring *below* that floor with the mechanism explained; smoothing swept for both the correct and the leaky version, showing the leak persists; the inner prior computed per inner fold; and a written statement of the `1/n_c` leakage arithmetic with the dataset's `n/cardinality` ratio quoted.

**The three most common ways submissions lose points:**

1. **Only two arms.** The in-fold result — worse than omitting the feature — is the most interesting finding and it is invisible without the floor.
2. **A strong category effect**, so the leak does not show and the write-up concludes it is overstated.
3. **Claiming smoothing fixes it.** Measured, it moves the inflated AUC from 0.7471 to 0.7438 across four orders of magnitude of `m`.
