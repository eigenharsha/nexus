## Reference solution — `P3-W17-M3`

The task: derive the gradient on paper, implement it, and verify against a numerical gradient to better than 1e-7.

## The derivation

For one sample, `z = x . theta`, `p = sigma(z)`, label `y` in `{0, 1}`:

```
L      = -[ y log p + (1-y) log(1-p) ]

dL/dp  = -[ y/p - (1-y)/(1-p) ]
       = -[ y(1-p) - (1-y)p ] / [ p(1-p) ]
       = -[ y - yp - p + yp ] / [ p(1-p) ]
       = ( p - y ) / [ p(1-p) ]

dp/dz  = p(1-p)                                   sigma'(z) = sigma(z)(1 - sigma(z))

dL/dz  = dL/dp * dp/dz = p - y                    <-- the p(1-p) cancels

dL/dtheta = ( p - y ) x

Over n samples, with an L2 penalty that excludes the intercept:

  objective  = (1/n) sum_i [ logaddexp(0, z_i) - y_i z_i ] + (1/(2 n C)) ||theta_{1:}||^2
  gradient   = (1/n) X^T (p - y) + (1/(n C)) [0, theta_1, ..., theta_p]
```

The `logaddexp` form of the objective comes from `log(1 - sigma(z)) = -logaddexp(0, z)` and `log(sigma(z)) = z - logaddexp(0, z)`. Substituting both into the cross-entropy gives `logaddexp(0, z) - y*z`, which never overflows and never needs clipping.

## The verification

Central difference, relative error criterion, on a 200 x 5 problem with `lam = 0.1`:

```
analytic: [ 0.061536 -0.106687  0.328385  0.114954  0.418849]
numeric : [ 0.061536 -0.106687  0.328385  0.114954  0.418849]
relative error: 2.115e-10
```

And the `eps` sweep that most submissions do not run:

| `eps` | relative error |
| --- | --- |
| 1e-2 | 2.976e-06 |
| 1e-4 | 2.981e-10 |
| **1e-6** | **2.115e-10** |
| 1e-8 | 1.598e-08 |
| 1e-10 | 1.620e-06 |

It is a U. Truncation error falls as `eps^2`; round-off error grows as `machine_eps/eps`. The optimum sits near `machine_eps^(1/3) ≈ 6e-6` in float64. **A submission that checked only at `eps=1e-10` will report a passing gradient as failing.**

## The full-scale check

Against `LogisticRegression(C=1.0, max_iter=10000, tol=1e-10)` on `load_breast_cancer` (569 x 30, standardised):

```
grad-check relative error: 1.471e-10
max |coef diff| vs sklearn: 2.58e-03
identical predictions: True
objective ours 0.0663602356  sklearn 0.0663601862  gap 4.94e-08
iters used: 4680   ||grad|| at our theta 1.0e-05 ; at sklearn's 2.6e-08
```

The coefficient gap of `2.6e-3` is **not a bug**. Three features in this dataset (`mean radius`, `mean perimeter`, `mean area`) correlate above 0.99, so the objective is nearly flat along the directions that trade them. Our gradient descent stopped at `||grad|| = 1e-05`; lbfgs got to `2.6e-08`. Every prediction is identical and the objective agrees to `4.9e-08`.

**The correct acceptance test compares objectives and predictions, not coefficients.** This is the identifiability point from Module 2 and it is the single most common source of "my implementation doesn't match sklearn" reports that are not actually bugs.

## Why this solution and not the obvious one

The obvious solution clips probabilities to `[1e-15, 1-1e-15]` and computes `-mean(y*log(p) + (1-y)*log(1-p))`. It works, mostly, and it is what almost every tutorial does. Three reasons not to:

1. **Clipping puts a discontinuity in the gradient.** Any sample whose `z` is saturated past the clip gets an exactly-zero contribution instead of a small one. On separable data that is a meaningful fraction of your dataset.
2. **It is less accurate where it matters.** `log(1e-15)` is representable but the subtraction `1 - p` for `p` near 1 has already lost all significance. `logaddexp` never forms `p` at all.
3. **`np.exp(-z)` overflows for `z < -745`.** In float64 this raises a `RuntimeWarning` and produces `inf`, then `nan`. It happens on real data with large unscaled features far more often than people expect.

The other wrong turn: **using a forward difference for the gradient check.** `(L(t+e) - L(t)) / e` has error `O(eps)` rather than `O(eps^2)`. At `eps=1e-6` the central difference gives `2.1e-10` and the forward difference gives roughly `1e-7` — borderline against the `1e-7` acceptance threshold, so it will pass sometimes and fail sometimes, which is worse than failing.

## Grading notes

**3/3 looks like:** the derivation is written out with the `p(1-p)` cancellation explicit; the objective uses `logaddexp` with no clipping anywhere; the gradient check is central-difference with a relative-error criterion and the `eps` sweep is plotted; the comparison against scikit-learn is on objective and predictions, with the `C` versus `lambda` conversion stated in a comment; and the coefficient discrepancy on `breast_cancer` is *explained* rather than chased.

**The three most common ways submissions lose points:**

1. **Asserting on coefficients.** Loses points twice: the test is wrong, and the write-up usually contains an hour of misdirected debugging that would have been avoided by checking the objective first.
2. **Forgetting that scikit-learn's `C` is `1/lambda` and that the intercept is unpenalised.** These two produce a small, systematic, confusing offset that grows with regularization strength. Write `alpha = 1 / (n * C)` at the top of the file before writing anything else.
3. **Reporting "gradient check passed" with a single `eps`.** The check is only informative if you know you are on the flat bottom of the U. One number could be anywhere on the curve.
