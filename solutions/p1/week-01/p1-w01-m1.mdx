## Reference solution — `P1-W01-M1`

The deliverable is `binviz.c`: given `int N`, `float X` or `str "..."`, print the bit pattern and the memory-order bytes, verified against `hexdump -C`.

```c
/* binviz.c — build: cc -std=c17 -Wall -Wextra -Werror -O2 binviz.c -o binviz */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <inttypes.h>

static void print_bits(const void *obj, size_t nbytes) {
    const unsigned char *p = obj;
    for (size_t i = nbytes; i-- > 0; ) {            /* MSB-first for humans */
        for (int b = 7; b >= 0; b--) putchar((p[i] >> b) & 1 ? '1' : '0');
        putchar(' ');
    }
    putchar('\n');
}

static void print_memory_order(const void *obj, size_t nbytes) {
    const unsigned char *p = obj;
    for (size_t i = 0; i < nbytes; i++) printf("%02x ", p[i]);
    puts("  <- memory order, low address first");
}

static int do_float(const char *arg) {
    float v = strtof(arg, NULL);
    uint32_t bits;
    memcpy(&bits, &v, sizeof bits);                  /* NOT a pointer cast: see below */
    unsigned expo = (bits >> 23) & 0xFFu;
    printf("float32 %.9g\n", (double)v);
    printf("  sign=%u  exponent=%u (biased) => 2^%d  mantissa=0x%06x\n",
           bits >> 31, expo, (int)expo - 127, bits & 0x7FFFFFu);
    print_bits(&v, sizeof v);
    print_memory_order(&v, sizeof v);
    return 0;
}

int main(int argc, char **argv) {
    if (argc != 3) { fprintf(stderr, "usage: %s (int|float|str) VALUE\n", argv[0]); return 2; }
    if (!strcmp(argv[1], "int")) {
        int32_t v = (int32_t)strtol(argv[2], NULL, 0);
        printf("int32  %" PRId32 "  (unsigned view: %" PRIu32 ")\n", v, (uint32_t)v);
        print_bits(&v, sizeof v);
        print_memory_order(&v, sizeof v);
    } else if (!strcmp(argv[1], "float")) {
        return do_float(argv[2]);
    } else if (!strcmp(argv[1], "str")) {
        size_t n = strlen(argv[2]);
        printf("string of %zu bytes\n", n);
        print_memory_order(argv[2], n);
        for (size_t i = 0; i < n; i++) {
            printf("  byte %2zu = 0x%02x  ", i, (unsigned char)argv[2][i]);
            print_bits(&argv[2][i], 1);
        }
    } else { fprintf(stderr, "unknown mode %s\n", argv[1]); return 2; }
    return 0;
}
```

Verification, which is the part that actually gets graded:

```bash
./binviz str "café" | grep '^63'      # 63 61 66 c3 a9
printf 'café' | hexdump -C            # must match, byte for byte
./binviz float 12.1414223             # sign=0 exponent=130 => 2^3 mantissa=0x424344
```

## Why this solution and not the obvious one

**Wrong turn 1: `*(uint32_t *)&v` instead of `memcpy`.**

Almost everyone writes the pointer cast, because it is shorter and it works. It is a **strict-aliasing violation**: C says an object may only be accessed through a compatible type, and `float` and `uint32_t` are not compatible. gcc with `-O2 -fstrict-aliasing` (which is on by default at `-O2`) is entitled to reorder the store to `v` past the load through the `uint32_t *`, and it sometimes does. The symptom is that the program prints the bit pattern of an *older* value of `v`, only at `-O2`, only in some compilers.

`memcpy` is the standards-blessed way to reinterpret bytes, and every modern compiler recognises the idiom and emits zero instructions for it — the assembly is identical to the cast. You lose nothing. (C23 and C++20 also give you `memcpy`'s typed cousin, `std::bit_cast`.) This is the same class of bug as the UB demo in Module 5: the wrong version works until the optimiser notices.

**Wrong turn 2: printing bits in memory order.**

The natural loop is `for (i = 0; i < nbytes; i++)`, which on a little-endian machine prints `01000001 00000000 00000000 00000000` for the value 65 — technically correct and completely unreadable. Humans write numbers most-significant-first, so `print_bits` walks bytes downward (`for (size_t i = nbytes; i-- > 0; )`) and prints `00000000 00000000 00000000 01000001`.

The right answer is to print **both**, labelled — which is what the reference does, and which is exactly what makes the tool useful for teaching endianness. If you only print one, print the human order and say so.

Note the loop idiom `for (size_t i = nbytes; i-- > 0; )`. Writing `for (size_t i = nbytes - 1; i >= 0; i--)` with an unsigned `i` is an infinite loop, because an unsigned value is never negative — the Module 1 signed/unsigned trap in three characters.

## Grading notes

**3/3 on correctness** means the `str` output matches `hexdump -C` for at least one 1-, 2-, 3- and 4-byte UTF-8 character, and the `float` mode's exponent and mantissa can be hand-verified against the printed bit string.

**3/3 on explanation** means the README derives the BF16 range from the bit layout rather than quoting it, and states why bf16 beat fp16 for training in one sentence about exponent bits.

The three most common ways submissions lose points:

1. **The strict-aliasing cast.** Works on the author's machine, so it is never noticed. Graders check for `memcpy` or a union specifically.
2. **No verification against `hexdump`.** The tool prints *something* and nobody checked it. The whole point of the exercise is the cross-check against an independent implementation.
3. **BF16 range quoted, not derived.** "BF16 max is 3.39e38" copied from a table earns 1. Showing that the exponent field is 8 bits with bias 127 so the max biased exponent 254 gives 2¹²⁷ × (2 − 2⁻⁷) = 3.3895 × 10³⁸ earns 3.
