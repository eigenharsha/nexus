## Reference solution — `P1-W05-M3`

The exercise: one layout, pixel-correct at 360 px, 768 px and 1440 px, no horizontal scroll
anywhere in between, plus one long frame found and fixed.

### The complete stylesheet

```css
/* 1. tokens ------------------------------------------------------------- */
:root {
  color-scheme: light dark;
  --space-1: .25rem; --space-2: .5rem; --space-3: 1rem; --space-4: 2rem;
  --radius: .5rem;
  --bg: #fffdf7; --surface: #fff; --ink: #1e1e1e; --ink-muted: #5b5b5b;
  --accent: #1971c2; --border: #e5e3dd;
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --bg: #1a1a19; --surface: #232322; --ink: #e8e6e3; --ink-muted: #a9a6a1;
    --accent: #74c0fc; --border: #34342f;
  }
}
:root[data-theme="dark"] {
  --bg: #1a1a19; --surface: #232322; --ink: #e8e6e3; --ink-muted: #a9a6a1;
  --accent: #74c0fc; --border: #34342f;
}

/* 2. reset -------------------------------------------------------------- */
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; font: 100%/1.5 system-ui, sans-serif; background: var(--bg); color: var(--ink); }
img, svg, video { display: block; max-width: 100%; height: auto; }

/* 3. shell -------------------------------------------------------------- */
.shell {
  display: grid; min-height: 100dvh;
  grid-template-columns: 1fr;
  grid-template-areas: "head" "main" "foot";
}
@media (min-width: 60rem) {
  .shell { grid-template-columns: 16rem 1fr;
           grid-template-areas: "head head" "side main" "foot foot"; }
}
.shell > header { grid-area: head; }
.shell > nav    { grid-area: side; }
.shell > main   { grid-area: main; min-width: 0; }   /* the line that prevents overflow */
.shell > footer { grid-area: foot; }

/* 4. content ------------------------------------------------------------ */
.cards { display: grid; gap: var(--space-3);
         grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr)); }
.card  { background: var(--surface); border: 1px solid var(--border);
         border-radius: var(--radius); padding: var(--space-3); }
h1 { font-size: clamp(1.75rem, 1.2rem + 2.5vw, 3rem); line-height: 1.15; }
.prose { max-width: 68ch; }
.table-wrap { overflow-x: auto; }                     /* the table scrolls, not the page */

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```

Three declarations do most of the work: `min-width: 0` on the grid item, `overflow-x: auto` on the
table wrapper, and `repeat(auto-fit, minmax(16rem, 1fr))` replacing what would otherwise be three
media queries.

### The resize sweep that proves it

```js
// paste in DevTools console after setting a wide window; or run under Playwright
const bad = [];
for (let w = 320; w <= 2560; w += 20) {
  await page.setViewportSize({ width: w, height: 900 });
  const overflow = await page.evaluate(() =>
    document.documentElement.scrollWidth - document.documentElement.clientWidth);
  if (overflow > 0) bad.push({ w, overflow });
}
console.log(bad.length ? bad : 'no horizontal overflow at any width');
```

## Why this solution and not the obvious one

**Wrong turn 1: `overflow-x: hidden` on `body`.** It makes the sweep pass visually while the
overflow is still there — and it silently breaks `position: sticky` on every ancestor chain,
because `overflow` other than `visible` creates a scroll container. The sweep above measures
`scrollWidth`, so it still fails, which is deliberate. The real fix is finding *what* overflows,
usually with `* { outline: 1px solid red }` and a bisect.

**Wrong turn 2: three media queries for the card grid.** They work at the viewport widths you
tested and break the moment the grid is placed inside a sidebar, because a viewport query cannot
see its container. `auto-fit` + `minmax` is one line, has no breakpoints to maintain, and is
correct in containers you have not thought of yet.

**Wrong turn 3: a second stylesheet for dark mode.** Duplicating component rules means every
future component must be written twice, and the two copies drift within a month. Re-declaring
tokens is the only version that scales. The `:root:not([data-theme="light"])` guard is not
decoration: without it, a user who explicitly chooses light mode on a dark-preference OS gets dark
anyway, because the media query has equal specificity and appears later.

## Measured numbers this solution produces

| Claim | Number | How to reproduce |
| --- | --- | --- |
| Flex-wrap is more expensive than Grid at scale | 5,000 items: flex 80.2 ms vs grid 20.5 ms vs float 18.2 ms | the layout harness in Layer 3 |
| Containment reduces re-layout cost | 2.8 ms → 2.3 ms after one child resize | same harness with `contain: strict` |
| Bulk style writes are most of a frame | 5,000 inline style writes + forced layout = 12.3 ms of a 16.7 ms budget | same |
| Interleaved reads and writes are catastrophic | 50,000 rows batched 230.7 ms; 5,000 rows interleaved 2,406.3 ms | the DOM harness from `P1-W05-M5` |

## Grading notes

**A 3/3 on correctness**: the sweep reports zero overflow from 320 px to 2560 px, the layout is
correct at all three named widths, dark mode works in both override directions, and
`prefers-reduced-motion` is respected.

**A 3/3 on performance**: a Performance-panel trace with one long frame identified, the causing
property named, and a second trace after the fix.

**The three most common ways submissions lose points**

1. `overflow-x: hidden` used as the fix. Automatic 1 on correctness.
2. Dark mode implemented so that an explicit user choice cannot override the OS preference in both directions.
3. A "long frame" identified as "JavaScript" with no property named — the point of the exercise is the specific attribution.
